# Ver 3.0 위치등록 신규 확인 구현

근거: `Ver_3.0_계획.md` 3장(재업로드 초기화), 5장(옛 양식), 11장.

## 행 분류

| 구분 | 조건 | 처리 |
|---|---|---|
| `new` | DB에 없는 통합시설코드 | 확인 목록 → [확인] 시 마커·공정 정보 저장 |
| `missingCoords` | DB에 있고 좌표 없음 | 확인 목록 → [확인] 시 국소명·좌표·공정 정보 저장 |
| `existing` | DB에 있고 좌표 있음 | [기존 N건 갱신] 시 국소명·공정 정보 저장 |
| 코드 없음 | 통합시설코드 빔 | 저장하지 않고 안내 |
| 주소 없음 | 주소가 비었거나 `불필요`·`미확정` | 저장하지 않고 안내. 이미 등록된 코드여도 갱신하지 않음 |

## 사업연도 (A열)

공정_일정관리.xlsb의 A열에는 사업연도가 있고 헤더 칸이 비어 있다. **첫 열의 헤더가 비어 있으면 `사업연도`로 읽는다**(`erp-parse.ts`). 시설연도는 이 값을 가장 먼저 쓰고, 비면 시설연도 열 → 프로젝트 코드 → 국소명 `26Y_` → ACTA 구축완료일 순으로 구한다.

**같은 통합시설코드라도 사업연도가 올해 이상(올해·미래)이면 시설을 진행하는 별개 건이다.** 기존 마커의 시설연도(`information.facility_year`)와 비교해 분류한다(`erp-classify.ts`).

| 행의 사업연도 | DB에 같은 코드의 마커 | 처리 |
|---|---|---|
| 올해 이상 | 같은 연도(또는 연도를 모르는) 마커 있음 | 그 마커에 연결 — 기존 건. 같은 파일을 다시 올려도 중복이 생기지 않는다 |
| 올해 이상 | 다른 연도 마커만 있음 | **새 마커.** ID는 `erp_코드_연도`(예: `erp_202621972_2027`) |
| 올해 이상 | 없음 | 새 마커 `erp_코드` |
| 지난 연도·빈 값 | 진행 중(올해 이상)이 아닌 마커 있음 | 예전처럼 코드로 연결 |
| 지난 연도 | 진행 중인 마커만 있음 | 저장하지 않음(`지난 사업연도`). 진행 중인 건의 공정 정보를 덮지 않기 위해서다 |
| 빈 값 | 진행 중인 마커만 있음 | 예전처럼 코드로 연결(연도를 몰라 판단하지 않는다) |

"올해"는 업로드하는 날의 연도다. 연도가 바뀌면 지난해 마커는 지난 연도로 취급된다.

같은 코드가 파일에 여러 번 나오면 DB의 같은 코드 마커에 순서대로 연결하고, 남는 행은 `erp_코드_n` ID의 신규로 본다. 통합시설코드가 `끝`인 행은 양식의 데이터 끝 표시이므로 그 행에서 읽기를 멈춘다(`erp-columns.ts`).

분류는 `erp-classify.ts`, 저장은 `erp-review-save.ts`, 주소 대조는 `address-compare.ts`에 있고 모두 업로드·확인할 때 지연 로딩한다. 임시 저장(`erp-review.ts`)만 항상 로드한다.

## 저장 규칙

- 신규는 전체 열을 저장하되 같은 ID가 이미 있으면 덮어쓰지 않는다.
- 기존 건 마커에는 `id`·`name`·`facility_code`(좌표 없는 건은 `lat`·`lng`까지)만 보낸다. 나머지 열은 유지된다.
- 공정 정보(`information`·`erp_details`)는 삭제 후 다시 넣고, 삭제 오류도 확인한다. 저장 원자성은 이번 범위가 아니다.
- 기존 마커 조회는 `fetchAllRows`로 1000건 제한을 피한다.
- 대표/SUB 재정리는 건별로 하지 않는다. 목록을 끝낼 때, [나중에 이어서], 취소, 기존 건 갱신, 임시 저장 복원 때 필요한 경우에만 실행한다.

## 마커주소

`road_address`(신주소)·`jibun_address`(지번)는 엑셀에서 올린 주소이고, **`markers.marker_address`(마커주소)는 마커가 놓인 좌표의 주소**(도로명 우선)다. 엑셀 주소와 같든 다르든 저장한다.

- 저장 시점: 확인 목록의 [확인](주소가 달라 `그래도 저장`한 경우 포함)과, 저장된 장비 마커를 지도에서 끌어 옮길 때. 옮긴 뒤 주소를 못 구하면 옛 값이 남지 않게 비운다.
- 위치 저장과 따로 쓴다(`marker-address.ts`). 컬럼이 없는 DB(`20261117000000_marker_address.sql` 적용 전)에서도 위치 저장은 성공하고, 확인 저장은 마커주소를 못 남겼다는 안내를 띄운다.
- 표시: 상세 모달 `지번` / `신주소` / `마커주소`, 지도 말풍선 `지번` → `(신주소)` → `(마커주소)`. 이미 등록된 마커는 위치를 다시 저장하거나 옮기기 전까지 비어 있다.
- 전체 백업·복원의 `markers` 열 목록에 포함한다(마이그레이션 적용 전 DB에 복원하면 이 열 때문에 실패하므로 먼저 적용한다).

## 주소 대조

`isSameAddress(엑셀 주소, 좌표의 도로명·지번 주소)`

- 엑셀 주소가 지번이면 동·리·가 이름과 번지(산 포함)를, 도로명이면 도로명과 건물번호를 비교한다.
- 시도 표기(`광주광역시`/`광주`)는 비교하지 않는다. 시·군·구는 엑셀 주소에 있을 때만 비교한다.
- 비교할 수 없으면(좌표의 주소 없음, 엑셀 주소를 해석할 수 없음) 다른 주소로 취급해 사용자에게 보여 준다.

## 임시 저장

- 키: `map-marker-erp-draft:<사용자 ID>` (`localStorage`). 확인 목록과 재정리 필요 여부만 저장하고, 기존 건은 저장하지 않는다. 기존 건은 파일을 다시 올려 갱신한다.
- 스토어 구독은 항상 마운트된 `map-marker-page`에서 한다. 패널을 닫은 채 마커를 옮겨도 저장된다.
- 파일을 다시 올리면 같은 ID의 옮긴 위치를 유지한다.

## 화면

- 확인 목록(`erp-review-panel.tsx`): [확인], 위치 보기, 제외, 주소 못 찾은 건의 [지도에서 찍기].
- 드래그는 위치만 바꾼다. 저장은 [확인]으로만 한다.
- 확인 목록 마커의 수정 화면은 막는다. 공정 정보 없이 저장되어 확인 절차를 건너뛰기 때문이다.
