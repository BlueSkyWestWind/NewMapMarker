## 1. 배경과 결정 사항

1단계(안전망)로 저장 실패 때 입력 보존, 되돌리기(`Ctrl+Z`·토스트), 보기 상태 유지, 검색 결과 강조가 들어갔다. 사용자는 시설일정을 매일 쓰며 **"뭔가 모를 반복성 노가다"** 가 남아 있다고 했다. 2단계는 같은 내용을 되풀이해 입력하거나 여러 번 클릭하는 장면을 줄인다.

### 1.1 사용자가 정한 것

| # | 결정 | 출처 |
|---|---|---|
| 1 | 반복 장면: 복사, 미배정→재입력, 기간 일정 일괄 수정 불가, 일일일정 칸마다 클릭 | 1단계 인터뷰 Q4 |
| 2 | 엑셀처럼 바로 입력하고 싶다. 일정은 주 30~60건, 한 번에 여러 건을 다루는 일이 많다 | 1단계 인터뷰 Q7 |
| 3 | 이미 등록한 기간 일정도 일괄 수정되길 원한다(추정 묶음을 보여 주고 확인 후 수정, 앞으로는 묶음 정보 저장) | 1단계 인터뷰 Q9 |

## 2. 확인한 사실

| 사실 | 근거 |
|---|---|
| 미배정 창은 한 번에 **한 날짜·한 팀**에만 넣고, 국소명(`mainText`)만 저장한다. 칸마다 `createScheduleCell`을 순서대로 보내 중간 실패 시 일부만 저장되고 되돌릴 수 없다 | `schedule-unscheduled-dialog.tsx` `handleAdd` (`subText: ""`, `for … await`) |
| 미배정 창은 추가한 뒤에도 **열려 있고** 선택만 비운다(연속 작업 가능) | 같은 파일 `finally` 블록 |
| 시설일정에는 **일정 복제 기능이 없다**(일일일정 텍스트 복사 `day-copy.ts`와 시행 결과의 "다시 잡을 날짜" 복사 `copyCellToDate`만 있다) | `lib/day-copy.ts`, `api.ts` `copyCellToDate` |
| 검색은 `main_text`만, 최대 `SEARCH_RESULT_LIMIT`(200)건, 팀·기간 필터와 "더 있음" 안내가 없다 | `api.ts` `searchScheduleCells`, `schedule-search.tsx` |
| 완료 여부(완료·일부완료·미시설)는 **칸 편집 창을 열고 → 줄의 점을 눌러 → 결과 창**에서만 기록한다. 주간 표에는 기록된 결과의 점과 툴팁만 있다 | `schedule-cell-dialog.tsx` 834줄 부근, `schedule-grid.tsx` 결과 점 |
| 시행 결과 기록 API는 칸 하나씩 `updateScheduleCellResult`(UPDATE)이다 | `api.ts` |
| 1B의 `apply_schedule_groups`는 **기존 칸의 시행 결과를 갱신하지 않는다**(복원 삽입·새 칸 삽입 때만 결과를 넣는다). 그래서 **결과 변경의 되돌리기는 별도 방식**이 필요하다 | `20261121000000_schedule_apply_groups.sql` 갱신 분기 |
| 일일일정 인라인 칸은 Enter·Escape만 처리하고 Tab 이동이 없으며 저장 중 다른 칸 편집이 막힌다 | `schedule-day-inline-cell.tsx`, `schedule-day-view.tsx` `busyRef` |

## 3. 조각과 순서

| 조각 | 내용 | DB | 이 문서의 상세도 |
|---|---|---|---|
| **S1 미배정 배정 개선** | 메모 입력, 여러 날짜로 이어 배정(하루 N건), 원자 저장·되돌리기 | 없음 | 상세 |
| **S2 일정 복제** | 날짜 또는 주 단위로 다른 날짜에 복제(팀 선택, 미리보기, 되돌리기) | 없음 | 상세 |
| **S3 검색 필터** | 팀·기간 필터, 메모 포함 검색, "일부만 표시" 안내 | 없음 | 상세 |
| **S4 완료 빠른 등록** | 주간 표 칸에서 바로 완료 표시·해제, 오늘 완료 현황, 결과 되돌리기 | 없음 | 상세 |
| **S5 일일일정 Tab 입력** | 인라인 칸 Tab·Shift+Tab·Enter 이동, 저장 중에도 다음 칸 편집(저장 대기열) | 없음 | 상세(§3.5, 2026-11-16 추가) |
| S6 기간 묶음 일괄 수정 | 묶음 정보 저장·추정 묶음 확인 후 일괄 수정 | **있음** | 방향만(마지막, 별도 설계) |

순서 이유: 효과 대비 작업량이 작은 것부터, 1B 저장 구조를 먼저 재사용해 검증하고, DB를 건드리는 S6은 마지막에 둔다.

### 3.1 S1 — 미배정 배정 개선

**지금**: 국소를 체크 → 날짜·팀 하나 고르기 → 국소명만 칸 단위로 순서대로 저장.

**바꾸는 것**
- **메모 입력**: 창에 `모국·장비·메모` 입력칸 하나를 두고, 추가하는 모든 줄의 `subText`에 같은 값을 쓴다(칸 편집 창의 "합친 메모 칸"과 같은 방식). 비우면 지금처럼 빈 값.
- **이어 배정**: `하루 최대 N건` 입력(비우면 지금처럼 고른 날짜에 전부). 값이 있으면 선택한 국소를 **이름 목록 순서대로** N건씩 끊어 **고른 날짜부터 다음 날짜로** 이어 배정한다. 날짜는 **월~금만, 공휴일(`lib/holidays.ts`) 제외**를 기본으로 하고 "주말·공휴일도 포함" 체크로 바꿀 수 있다. 각 날짜의 같은 팀 빈 행(`nextFreeRows`)에 넣는다. 행이 가득 차면 그 날짜는 가능한 만큼만 넣고 남은 건은 다음 날짜로 넘긴다. 최대 31일(기존 `MAX_WORK_DATES`)을 넘으면 남은 건은 "넣지 못함"으로 알린다.
- **원자 저장·되돌리기**: 계산한 결과를 `applyOpsToGroups`의 `create` ops로 만들어 `useScheduleWrite().write("미배정 배정", …)`로 한 번에 저장한다. 성공 토스트에 [되돌리기]가 붙는다. 실패하면 선택·입력을 그대로 둔다(창을 닫지 않는다).
- **저장 전 미리보기**: 버튼 위에 "7/21 5건 · 7/22 5건 · 7/23 2건 (넣지 못함 0건)" 한 줄을 보여 준다(순수 함수 결과).
- 국소 선택·검색·정렬은 기존 그대로.

**순수 함수**: `lib/unscheduled-assign.ts` — `planUnscheduledAssign({ stations, startDate, perDay, includeOffDays, memo, existingByDate, maxRows, holidays })` → `{ days: { date, creates: {rowNo, text}[] }[], skipped: { label, reason: "full" | "range" }[] }`.

### 3.2 S2 — 일정 복제

**목적**: 지난주·다른 날 일정을 다시 입력하지 않고 복제한다.

**UI**: 일정표 도구 줄에 **[복제]** 버튼 → 창.
1. **원본**: `날짜 하나`(기본: 지금 선택한 날짜) 또는 `주 전체`(월~일). 
2. **대상**: 날짜 하나 복제는 대상 날짜를 여러 개 고른다(+1일·+7일 단축 버튼, 최대 31일). 주 복제는 `다음 N주`(최대 8)에 같은 요일로.
3. **팀**: 원본 날짜의 팀 중 복제할 팀 체크(기본 전체, 비고 열 제외).
4. **대상 팀에 이미 일정이 있으면**: `건너뛰기`(기본) / `뒤에 이어 붙이기` 중 선택.
5. **미리보기**: "7/28 12건 복제 · 7/29 8건 복제 · 건너뜀 2팀 · 넣지 못함(행 가득) 1건"을 보여 주고 [복제] 확정.
6. 저장은 `write("복제", …)` 한 번(원자, 되돌리기 가능).

**복제 내용**: `mainText`·`subText`·`textColor`·`companionTarget`. **시행 결과(완료 여부)·날짜 메모·칸 색 표시는 복제하지 않는다**(기존 `planReschedule`·`copyCellToDate`의 규칙과 같다). 행 번호는 원본 그대로이고, 이어 붙이기 모드에서는 빈 행을 이어 쓴다.

**순수 함수**: `lib/day-copy-plan.ts`(기존 `day-copy.ts`와 이름이 겹치지 않게) — `planCopy({ pairs: {from, to}[], columnIds, mode, cellsByDate, maxRows })` → `{ groups, summary: { copied, skippedTeams, skippedFull }[] }`.

### 3.3 S3 — 검색 필터

- 필터: **팀**(다중), **기간**(시작~끝, 비우면 전체), **메모 포함**(체크하면 `sub_text`도 검색).
- 결과가 상한(200건)에 닿으면 "최근 200건만 표시합니다. 필터로 좁혀 보세요"를 보여 준다(`limit+1`건을 요청해 판단).
- `searchScheduleCells(supabase, query, options)`에 `{ columnIds?, from?, to?, includeSub? }`를 추가한다. 메모 포함 검색은 `or(main_text.ilike…, sub_text.ilike…)`에서 **`%`·`_`·`,`·`(`·`)` 이스케이프**를 순수 함수로 만들어 테스트한다. 결과 칸 클릭 동작(날짜 이동·강조)은 1A 그대로.
- `queryKey`에 옵션을 포함한다.

### 3.4 S4 — 완료 빠른 등록

**지금**: 칸 편집 창 → 줄의 점 → 결과 창(완료·일부완료·미시설+사유+재일정). 완료 하나 기록하는 데 클릭이 많다.

**바꾸는 것** (관리자만)
- 주간 표 칸에 마우스를 올리면 칸 왼쪽에 작은 **✓ 버튼**이 보인다(기능 기호, 이모지 아님). 누르면 그 칸을 **완료**로 기록하고(칸 편집 창은 열리지 않는다), 이미 완료면 **기록 취소**(미기록)로 되돌린다. 일부완료·미시설은 이미 있는 결과 창(칸 편집 창의 점)을 그대로 쓴다.
- **되돌리기**: 완료 표시·해제는 이전 결과값을 기억해 토스트 [되돌리기]와 `Ctrl+Z`로 되돌린다. 결과는 `apply_schedule_groups`가 갱신하지 않으므로 **결과 전용 되돌리기 항목**(이전 `CellResult | null` 복원, `updateScheduleCellResult`)을 같은 스택에 쌓는다.
- **오늘 완료 현황**: 헤더에 `오늘 완료 n/m`(시행 결과가 있는 칸 중 완료 수/전체 칸 수) 작은 칩을 보인다. 눌러서 필터링하는 기능은 넣지 않는다.
- 일괄: 날짜·팀 단위로 "이 팀(또는 이 날) 전부 완료"는 기존 일괄 결과 창이 처리하므로 이번에 새로 만들지 않는다.

**순수 함수**: `lib/quick-result.ts` — `toggleDone(current: CellResult | null)` → 다음 결과값(완료 ↔ null, 일부완료·미시설이면 "완료로 덮어쓰기"를 쓰지 않고 `null` 반환해 호출부가 결과 창을 열게 함), `completionSummary(cells, date)` → `{ done, total }`.

### 3.5 S5 — 일일일정 Tab 입력

**지금**(`schedule-day-inline-cell.tsx`, `schedule-day-view.tsx`): 작업유형·중장비투입·작업내용·작업내용 상세 네 열은 표에서 바로 고친다. 하지만 ① 칸을 하나 고치고 Enter/다른 곳 클릭으로 저장하면 **다음 칸은 마우스로 다시 눌러야 한다**(Tab 이동 없음) ② 저장은 `runExclusive`로 하나씩만 돌고 그동안 `editable={… && !busy}`라서 **저장이 끝날 때까지(저장 직전 DB 조회 + upsert + 재조회) 다른 칸을 편집할 수 없다.** 한 날 20~60행을 채울 때 클릭과 대기가 반복된다.

**바꾸는 것**
- **칸 이동 키**: 편집 중 `Tab` → 저장하고 **오른쪽 칸**(같은 행의 다음 편집 열, 행 끝이면 다음 행의 첫 편집 열)을 연다. `Shift+Tab` → 반대 방향. `Enter` → 저장하고 **아래 칸**(같은 열의 다음 행)을 연다(엑셀과 같다), `Shift+Enter` → 위 칸. 맨 끝·맨 처음이면 저장만 하고 닫는다. `Esc`는 지금처럼 취소(저장 안 함). 다른 곳 클릭도 지금처럼 저장하고 닫는다.
- **저장 대기열**: 인라인 저장을 **순서대로 하나씩 처리하는 대기열**에 넣어, 저장 중에도 바로 다음 칸을 편집할 수 있게 한다. 대기열의 저장은 앞 저장이 끝난 뒤 시작하므로 각 저장이 "저장 시점의 DB 행에 합치는" 기존 `saveDetails`의 안전성을 그대로 쓴다. 앞 저장이 실패해도 뒤 저장은 계속한다(실패한 칸만 오류 토스트).
- **저장 중 표시**: 저장을 기다리는 칸은 **방금 입력한 값을 바로 보여 주고**(낙관적 표시, `italic text-slate-400`으로 구분) 저장이 끝나 표가 갱신되면 일반 표시로 돌아온다. 실패하면 원래 값으로 돌아가고 토스트로 알린다.
- **배타 동작과의 관계**: 복사·내려받기·누적 저장·상세 창 저장·행 삭제(기존 `runExclusive`)는 **인라인 저장 대기열이 비어 있을 때만** 시작한다(대기 중이면 버튼을 비활성하고 눌러도 무시). 반대로 그 동작이 도는 동안에는 인라인 편집을 막는다(지금과 같다).

**테스트 대상(seam)** — 로직은 순수 모듈 두 개로 빼서 `.ts` 테스트로 지킨다(`.tsx`는 테스트가 실행되지 않는다).
1. `lib/inline-nav.ts` — `nextInlineTarget({ rowKeys, columnKeys, current, key })`: 이동 키(`Tab`·`Shift+Tab`·`Enter`·`Shift+Enter`)와 현재 칸으로 다음 칸을 돌려준다(끝이면 `null`). *잡는 것*: 행 끝에서 다음 행으로 넘어가는 경계, 맨 처음·끝, 열이 하나뿐일 때, 현재 칸이 목록에 없을 때. *놓치는 것*: 실제 포커스·화면 갱신(화면 확인으로 본다).
2. `lib/serial-queue.ts` — `createSerialQueue()`: 작업을 넣은 순서대로 하나씩 실행하고, 앞 작업이 실패해도 다음을 실행하며, 대기·실행 중 개수(`pending`)와 변화 알림을 준다. *잡는 것*: 순서, 실패 뒤 계속, 개수 증감, 동시에 두 작업이 돌지 않음. *놓치는 것*: Supabase 호출 자체와 낙관적 표시.

## 4. 목표·비목표

**목표**: 같은 입력을 되풀이하는 장면(미배정 재입력, 주간 복제, 검색 좁히기, 완료 표시)에서 클릭·입력을 눈에 띄게 줄인다. 실패해도 입력이 남고 되돌릴 수 있다.

**비목표**: 칸 편집 창 재설계·인라인 편집(3단계), 주간·월간 드래그 규칙 통일(3단계), 입회·신호수 자동 입력(§6 #2), 기간 묶음 일괄 수정(S6), 엑셀 형식 변경. (일일일정 Tab 입력은 S5에서 한다.)

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 복제가 한 날짜에 수십 건을 만들어 행이 가득 차 일부가 빠진다 | 미리보기에서 "넣지 못함" 건수를 먼저 보여 주고, 계획 함수가 `MAX_ROWS`를 지킨다. 저장은 계산된 만큼만 한다 |
| 복제 결과를 되돌리면 새로 만든 칸이 사라진다 | 1B 되돌리기가 그룹 스냅샷 복원이므로 그대로 지원한다(`before`는 빈 그룹 포함) |
| 완료 ✓ 버튼이 드래그(`draggable`)·클릭(칸 편집 창)과 충돌한다 | 버튼 `onClick`에서 `stopPropagation`, 버튼 `draggable={false}`. 화면 확인 항목에 포함 |
| 메모 포함 검색의 `or()` 구문 오류·주입 | 입력 이스케이프를 순수 함수로 두고 테스트. 오류 시 기존 `main_text` 단독 검색으로 대체 |
| 완료 결과 되돌리기가 1B 스택과 형식이 다르다 | `UndoEntry`를 `{ kind: "groups" | "result" }` 합집합으로 넓히되 기존 항목 동작은 그대로(`kind` 없으면 groups). 스택·`undo()` 테스트 보강 |

## 6. 사용자 확인 대상 (Claude 제안, 승인된 순서 외 세부)

1. **S1 이어 배정의 기본값**: 월~금만, 공휴일 제외. (대안: 달력 날짜 그대로)
2. **S1에 입회·신호수는 넣지 않는다.** 입회·신호수는 "대상 표시"와 정리 순서 규칙(`planCompanionArrangement`)과 얽혀 있어 칸 편집 창에서 입력하도록 둔다. 필요하면 S1 뒤에 별도로 붙인다.
3. **S2 복제 때 시행 결과·칸 색은 복제하지 않는다.** (색 표시 복제가 필요하면 알려 주세요)
4. **S4 ✓ 버튼의 위치·모양**: 칸에 마우스를 올릴 때 왼쪽에 작게. 화면을 보고 조정한다.
5. **일부완료·미시설 빠른 등록은 하지 않는다**(사유가 필수라 창이 필요).
6. **S5에서 `Enter`의 동작이 바뀐다**: 지금은 저장하고 닫기만 하지만, 엑셀처럼 **저장하고 아래 칸을 연다**. (예전처럼 닫기만 원하시면 알려 주세요.)
7. **S5의 낙관적 표시**: 저장이 끝나기 전에도 입력한 값을 표에 보여 준다(실패하면 되돌림).
