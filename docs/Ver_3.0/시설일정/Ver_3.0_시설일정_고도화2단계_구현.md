설계의 **S1(미배정 배정 개선) · S2(일정 복제) · S3(검색 필터) · S4(완료 빠른 등록) · S5(일일일정 Tab 입력)** 를 구현했다(S1~S4는 2026-11-16, S5는 같은 날 이어서). DB 변경은 없다(1B의 `apply_schedule_groups`를 재사용). **S6(기간 묶음 일괄 수정, DB 필요)은 아직이다.** 구현은 agy가 하고 Claude가 diff를 검토했다.

## 직접 하실 일

관리자 계정으로 시설일정(`일정관리 > 시설일정`)에서 확인한다. 새 SQL 적용은 **없다**(1B 마이그레이션 `20261121000000_schedule_apply_groups.sql`은 이미 적용하셨다). 복제·미배정 배정은 그 함수가 있어야 동작한다.

1. **미배정 국소 배정(S1)**
   - `미배정 국소` 창에서 국소 여러 건을 체크하고 **모국·장비·메모**에 글을 적어 추가한다. 추가된 모든 줄의 메모 칸에 같은 글이 들어가는지.
   - `하루 최대`에 `2`를 넣고 5건을 추가한다. **하루 2건씩 평일(월~금)에 이어서** 들어가는지, 버튼 위 한 줄 미리보기(`7/21 2건 · 7/22 2건 · 7/23 1건`)와 같은지. `주말·공휴일도 포함`을 켜면 토·일에도 들어가는지.
   - 추가 직후 토스트의 **[되돌리기]** 또는 `Ctrl+Z`로 한 번에 사라지는지.
   - 같은 팀 날짜에 이미 일정이 많을 때 빈 행에만 들어가는지(미리보기는 빈 행 수를 모르므로 건수가 실제와 다를 수 있다 — 아래 한계).
2. **일정 복제(S2)**
   - 도구 줄의 **복제**: `날짜 복제`로 원본 날짜를 다른 날짜 두 곳에 복제한다. 미리보기 한 줄(`7/28 12건 · 7/29 8건 (건너뜀 …)`)과 결과가 같은지.
   - 대상에 이미 일정이 있는 팀은 `건너뛰기`일 때 그대로 두고, `뒤에 이어 붙이기`일 때 그 뒤 행에 붙는지.
   - **시행 결과(완료 표시)와 칸 색이 복제본에 없는지**(원본에 완료 점이 있던 칸을 복제해 본다).
   - `주 복제`로 이번 주를 다음 1주에 복제한다. 같은 요일에 들어가는지. 복제 뒤 **되돌리기**로 모두 사라지는지.
3. **검색 필터(S3)**
   - 검색창에 두 글자 이상 입력하면 결과 위에 필터 줄(팀 칩·시작/종료일·메모 포함)이 보이는지. 팀 하나를 고르면 그 팀 결과만, 기간을 주면 그 범위만 나오는지. 끝 날짜를 시작보다 앞으로 하면 오류 안내가 나오는지.
   - `메모 포함`을 켜고 메모(모국·장비 칸)에만 있는 단어로 찾으면 나오는지(끄면 안 나오는지).
   - 결과가 200건을 넘는 흔한 단어(예: 한 글자짜리가 아닌 자주 쓰는 글)로 찾으면 "최근 200건만 표시합니다…" 안내가 보이는지.
   - 날짜 선택 달력을 눌러도 검색 패널이 닫히지 않는지.
4. **완료 빠른 등록(S4)**
   - 주간 표에서 칸에 마우스를 올리면 칸 왼쪽에 작은 **✓**가 보이는지(입회·신호수 줄과 빈 칸에는 없어야 한다).
   - ✓를 누르면 칸 편집 창이 **열리지 않고** 완료 점이 생기며 토스트 `… 완료 기록`이 뜨는지. 다시 누르면 `… 완료 취소`로 점이 사라지는지.
   - 토스트의 [되돌리기] 또는 `Ctrl+Z`로 이전 상태로 돌아오는지.
   - 일부완료·미시설이 기록된 칸에서 ✓를 누르면 덮어쓰지 않고 **칸 편집 창이 열리는지**.
   - ✓ 버튼을 누르며 칸을 끌어 보아 드래그(칸 이동)와 충돌하지 않는지.
   - 헤더에 `오늘 완료 n/m`이 보이는지(오늘 칸 중 결과를 기록한 것 기준, 오늘이 화면 주에 없으면 숨김).
5. **일일일정 Tab 입력(S5)** (`일정관리 > 일일일정`, 관리자)
   - 작업유형·중장비투입·작업내용·작업내용 상세 칸을 눌러 입력하고 **Tab**을 누르면 저장되고 **오른쪽 칸**이 바로 열리는지. 행 끝에서는 다음 행의 첫 편집 칸으로 넘어가는지, `Shift+Tab`은 반대로 가는지.
   - **Enter**를 누르면 저장되고 **아래 칸(같은 열의 다음 행)** 이 열리는지, `Shift+Enter`는 위 칸인지. 맨 아래 행에서 Enter는 저장만 하고 닫는지. (예전에는 Enter가 저장하고 닫기만 했다. 예전 방식이 낫다면 알려 주세요.)
   - `Esc`는 저장하지 않고 취소하는지. 다른 곳을 눌러도 저장되고 닫히는지. 목록에서 항목을 고르면 이동 없이 저장되는지.
   - Tab으로 칸을 연달아 15~20칸 입력해 본다. **저장이 끝나기를 기다리지 않고** 계속 입력되는지, 저장 중인 칸이 **기울어진 회색 글씨**로 보이다가 저장이 끝나면 일반 글씨로 돌아오는지. 끝난 뒤 새로고침해도 모두 남아 있는지.
   - 같은 칸을 연달아 두 번 고쳤을 때 마지막 값이 남는지. 저장을 일부러 실패시켜(네트워크 오프라인) 입력하면 오류 토스트가 뜨고 칸이 원래 값으로 돌아오는지.
   - 저장 중에는 상단 `표 복사`·`엑셀 내려받기`·`누적 저장` 버튼이 잠깐 비활성이 되었다가 풀리는지. 상세 창에서 저장을 눌렀을 때 인라인 저장이 남아 있어도 **기다렸다가 저장되는지**(눌렀는데 반응이 없으면 안 된다).
6. 이상이 없으면 "커밋"이라고 말씀해 주세요. S6 진행도 알려 주세요. 처음 질문 두 가지(**입력 중 가장 자주 반복되는 장면**, **완료 여부에서 빠진 점**)에 답해 주시면 S6과 3단계의 우선순위를 정하는 데 씁니다.

## 검토에서 확인한 것

- **이어 배정 규칙**: 설계 §3.1과 같다(월~금·공휴일 제외 기본, 쉬는 날에 시작하면 첫 근무일부터, 하루에 넣을 빈 행이 0이면 그 날짜 건너뜀, 31일 초과분은 `range`로 알림). 달력 날짜를 손으로 계산한 기대값으로 시험했고(예: 금 `11-13` 시작 → 금·월 `11-16`·화 `11-17`), **공휴일 건너뜀 조건을 지우면 ⑤, 기간 한도를 어긋나게 하면 ⑧이 실패**하는 것을 확인하고 원복했다.
- **복제 규칙**: `skip`은 대상 팀에 칸이 하나라도 있으면 그 팀 전체를 건너뛰고, `append`는 빈 행에 원본 순서대로 붙으며 빈 행이 모자라면 들어가는 만큼만 넣고 나머지는 `넣지 못함`으로 센다. **시행 결과는 `creates`에 필드 자체가 없다.** `skip` 판정을 끄면 ③, `companionTarget` 보존을 지우면 ⑨가 실패하는 것을 확인하고 원복했다.
- **검색 이스케이프**: `likePattern`이 LIKE 와일드카드(`%`·`_`·`\`)를, `escapeOrValue`가 PostgREST `or()` 값의 `"`·`\`를 이스케이프한다(이중 적용이 아님을 손으로 확인). 이스케이프 규칙을 고치면 두 이스케이프 시험이, `slice(0, 200)`을 지우면 상한 시험이 실패하는 것을 확인했다.
- **결과 되돌리기**: `apply_schedule_groups`는 기존 칸의 시행 결과를 갱신하지 않으므로, 완료 표시의 되돌리기는 `updateScheduleCellResult`로 이전 값을 다시 쓰는 별도 항목이다. `partial`/`undone`을 덮어쓰는 변이를 넣으면 시험이 실패하는 것을 확인했다. (입회·신호수 제외 조건을 지우는 변이는 시험이 잡지 못했는데, 입회·신호수 칸은 국소 글이 비어 있어 앞의 "글 없음" 조건이 이미 걸러내는 **동치 변이**라 결함이 아니다.)
- **S5**: 이동 규칙을 순수 함수로 시험했다(행 끝에서 다음 행으로 넘어가는 경계를 일부러 틀리게 바꾸면 ②·⑪이, 저장 대기열을 동시 실행으로 바꾸면 ①·③이 실패하는 것을 확인하고 원복). `tail.then(run)`으로 거부 처리를 지우는 변이는 시험이 통과했는데, 대기열의 `tail`이 절대 거부되지 않는 구조라 결과가 같은 **동치 변이**다. **Claude가 고친 것**: agy 구현은 인라인 저장이 남아 있을 때 상세 창의 [저장]·행 추가를 **조용히 무시**했다(눌러도 반응 없음) → `runExclusive`·`handleAddRow`가 대기열이 빌 때까지 **기다린 뒤** 진행하도록 바꿨다.
- 계획과 다르게 한 점 없음(S5의 `inlineQueue` 초기화를 `useRef` 대신 `useState(() => createSerialQueue())`로 한 것은 React 19 ESLint 규칙 때문). agy가 추가한 것(S3): S3 바깥 클릭 처리에서 `DatePicker` 달력(포털 `role="dialog"`)을 눌러도 검색 패널이 닫히지 않게 예외를 둠.

## 한계

- **UI 연결은 자동 테스트가 없다**(`.tsx` 테스트 미지원). 위 화면 확인에 의존한다.
- **S1 미리보기는 빈 행 수를 모른다.** 미리보기(`7/21 2건 …`)는 그 팀·날짜가 비어 있다고 가정해 건수만 나눈다. 이미 일정이 많은 날은 저장 때 일부가 다음 날짜로 밀리거나 `넣지 못함`이 될 수 있다(저장 직전 조회로 정확히 다시 계산한다).
- **복제는 DB 함수(1B)가 없으면 쓸 수 없다**(칸 단위 대체 경로를 만들지 않았다). 지금은 적용되어 있으므로 영향이 없다.
- 복제 미리보기는 조회 결과를 30초 캐시한다. 그 사이 다른 곳에서 바뀌어도 저장 시에는 다시 조회해 계산한다.
- **결과 되돌리기는 충돌 검사를 하지 않는다.** 그 칸이 그 사이 삭제됐으면 복원 요청은 아무 칸도 바꾸지 않고 성공으로 보인다.
- ✓ 버튼은 **마우스를 올릴 때만** 보이는 편의 기능이다(키보드는 칸 편집 창 사용). 월 달력에는 넣지 않았다. 일부완료·미시설은 사유가 필수라 빠른 등록을 하지 않는다.
- 공휴일 표는 2025~2028년만 있다(`lib/holidays.ts`). 2029년 이후 날짜로 이어 배정하면 공휴일이 걸러지지 않는다.
- **S5**: 낙관적 표시 때문에 저장 실패 시 입력한 글이 사라지고 원래 값으로 돌아온다(토스트로 알린다). `Enter`는 이제 "저장 후 아래 칸 열기"다. 편집 가능한 열은 일일일정의 네 열(작업유형·중장비투입·작업내용·작업내용 상세)뿐이고 참조 열은 이동 대상이 아니다. Tab 이동의 포커스·화면 동작은 `.tsx` 테스트가 없어 화면 확인에 의존한다.
- 검색 바깥 클릭 처리는 열려 있는 모든 `role="dialog"` 안의 클릭을 무시한다(검색 패널이 열린 상태에서 다른 창을 누르면 패널이 닫히지 않을 수 있다).
