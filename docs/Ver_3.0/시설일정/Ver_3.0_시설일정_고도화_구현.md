설계의 **1단계 중 1A(화면 쪽 안전망, DB 변경 없음)** 를 구현했다. 1B(원자 저장·되돌리기)와 2·3단계는 아직이다. 구현은 agy가 하고 Claude가 diff를 검토했다.

## 직접 하실 일

시설일정(`일정관리 > 시설일정`)을 열어 확인한다. 관리자 계정으로 한다.

1. **보기 상태 유지**
   - 주 수(예: 3주)와 선택 열(예: 6팀·시험팀 표시)을 바꾸고 **새로고침**한다. 같은 설정으로 열리는지.
   - 다음 주로 넘긴 뒤 다른 메뉴(지도, CCTV 등)에 갔다가 돌아온다. **같은 주**가 열리는지.
   - 월 보기로 바꿔 새로고침한다. 월 보기가 유지되는지.
   - 다음 날(또는 PC 날짜를 바꿔) 열면 **오늘이 있는 주**로 열리는지(보던 날짜는 같은 날만 기억한다). 주 수·열 설정은 계속 남아 있어야 한다.
2. **검색 결과 위치 강조**: 국소 검색에서 결과를 눌렀을 때 그 날짜의 주로 이동하고, **그 칸이 약 3초 동안 노란 테두리로 강조**되며 화면 가운데로 스크롤되는지. 월 보기에서도 같은 칸이 강조되는지. 이동하는 주의 데이터가 느리게 오면 강조가 안 보일 수 있다(3초 안에 칸이 나타나지 않으면 생략).
3. **확인창**: 칸 편집 창에서 [전체 삭제] 후 저장하면 "N건을 삭제합니다. 계속할까요?"가 뜨는지, 취소하면 저장되지 않고 창이 그대로인지. 줄 2개 이상을 지우고 저장해도 같은 확인이 뜨는지. **줄 1개만** `×`로 지우고 저장하면 확인 없이 저장되는지(되돌리기가 생기는 1B 전까지는 이 경우 보호가 없다).
4. **드래그 알림**: 칸을 끌어 다른 칸과 맞바꾸면 "A와 B의 자리를 맞바꿨습니다"가, 팀 묶음을 옮기면 "N건을 옮겼습니다"가 뜨는지.
5. 이상이 없으면 "커밋"이라고 말씀해 주세요. 1B 진행도 알려 주세요(SQL을 한 번 적용해 주셔야 한다).

## 검토에서 확인한 것

- **선택 열 복원**: 열 데이터가 도착하기 전에 저장 effect가 빈 선택으로 덮어써서 저장된 값을 지우는 문제를 agy가 미리 막았다(복원 전에는 저장된 원본 값을 유지, 복원 뒤부터 현재 값 저장).
- 선택 열의 기본값이 비어 있어(숨김), "전부 숨김"과 기본값이 같아 복원 로직에 빈 목록 예외가 필요 없다.
- **변이 확인**: Claude가 `deleteConfirmMessage`의 기준(`>= 2` → `>= 3`)과 `loadDateState`의 같은 날 검사를 일부러 틀리게 바꿔 해당 테스트가 각각 빨개지는 것을 확인하고 원복했다.
- 설계 §3.2에서 정한 확인창 기준(전체 삭제·2건 이상, 1건 `×`는 제외)과 정확히 같다.

## 한계

- **UI 연결은 자동 테스트가 없다**(`.tsx` 테스트 미지원). 순수 규칙(`view-state`, `delete-confirm`)만 테스트로 지키고, 강조·스크롤·확인창·토스트는 위 화면 확인에 의존한다.
- 검색 결과를 같은 3초 안에 다시 누르면 타이머만 연장되고 스크롤은 다시 하지 않는다.
- **1건 `×` 삭제는 아직 보호가 없다.** 1B의 되돌리기가 들어오면 해결된다.
- 가로로 긴 화면에서 검색 결과 칸이 보이는 위치까지의 스크롤은 브라우저의 `scrollIntoView`에 맡겼다. 매우 좁은 창에서는 사람이 보기에 어색할 수 있다.
