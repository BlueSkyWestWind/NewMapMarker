### 1A

시설일정(`일정관리 > 시설일정`)을 열어 확인한다. 관리자 계정으로 한다.

1. **보기 상태 유지**
   - 주 수(예: 3주)와 선택 열(예: 6팀·시험팀 표시)을 바꾸고 **새로고침**한다. 같은 설정으로 열리는지.
   - 다음 주로 넘긴 뒤 다른 메뉴(지도, CCTV 등)에 갔다가 돌아온다. **같은 주**가 열리는지.
   - 월 보기로 바꿔 새로고침한다. 월 보기가 유지되는지.
   - 다음 날(또는 PC 날짜를 바꿔) 열면 **오늘이 있는 주**로 열리는지(보던 날짜는 같은 날만 기억한다). 주 수·열 설정은 계속 남아 있어야 한다.
2. **검색 결과 위치 강조**: 국소 검색에서 결과를 눌렀을 때 그 날짜의 주로 이동하고, **그 칸이 약 3초 동안 노란 테두리로 강조**되며 화면 가운데로 스크롤되는지. 월 보기에서도 같은 칸이 강조되는지. 이동하는 주의 데이터가 느리게 오면 강조가 안 보일 수 있다(3초 안에 칸이 나타나지 않으면 생략).
3. **확인창**: 칸 편집 창에서 [전체 삭제] 후 저장하면 "N건을 삭제합니다. 계속할까요?"가 뜨는지, 취소하면 저장되지 않고 창이 그대로인지. 줄 2개 이상을 지우고 저장해도 같은 확인이 뜨는지. **줄 1개만** `×`로 지우고 저장하면 확인 없이 저장되는지(되돌리기가 생기는 1B 전까지는 이 경우 보호가 없다).
4. **드래그 알림**: 칸을 끌어 다른 칸과 맞바꾸면 "A와 B의 자리를 맞바꿨습니다"가, 팀 묶음을 옮기면 "N건을 옮겼습니다"가 뜨는지.
5. 이상이 없으면 "커밋"이라고 말씀해 주세요. 1B 진행도 알려 주세요(SQL을 한 번 적용해 주셔야 한다).

### 되돌리기의 동작

- 되돌리기는 저장 직전 스냅샷(`before`)을 같은 함수로 다시 보낸다. 서버는 "방금 저장한 상태 그대로인지"(`base_ids`)를 검사해 **다른 곳에서 바뀌었으면 거부**한다(남의 변경을 덮어쓰지 않는다).
- 지운 칸은 **원래 id로 복원**된다. 그래서 더 이전 되돌리기 항목도 계속 유효하다. 시행 결과(완료·미시설·사유·미룬 날짜)도 함께 복원된다.
- 그룹 사이 이동은 그룹 처리 순서와 무관하게 되돌려지도록 2단계(먼저 삭제, 나중에 삽입)로 처리한다.
- 되돌리기 실패(`failed`, 예: 네트워크)는 항목을 스택에 되돌려 놓아 다시 시도할 수 있다. 충돌(`stale`)은 항목을 버린다.
- `Ctrl+Z`는 입력칸·편집 창이 열려 있으면 무시하고(글자 되돌리기를 그대로 둔다), 관리자의 시설일정 화면에서만 동작한다.

- 되돌리기 스택은 세션 메모리다. 새로고침하면 사라진다.
- 토스트의 [되돌리기]는 그 토스트의 작업이 아니라 **가장 최근 작업**을 되돌린다(스택 방식).
- 저장 내용이 전혀 바뀌지 않은 채 저장하면(변경 없음) 빈 되돌리기 항목이 쌓이고 행 정리는 일어나지 않는다. 화면 결과는 달라지지 않는다.
- 엑셀 가져오기(`replace_schedule_cells`)와 일일일정은 되돌리기 대상이 아니다.
- `Ctrl+Z` 리스너가 렌더마다 다시 등록된다(동작에는 영향 없음, 정리 후보).
