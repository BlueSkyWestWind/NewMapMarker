# Ver 3.0 위치 메뉴 국소 목록 구현

근거: `Ver_3.0_계획.md` 2장(위치 메뉴, 권한, 임시 마커 이동), 4장(저장 구조), 5장(백업), 8장(제안).

## 결정(2026-11-07 확인)

- 임시 마커 기능(`엑셀로 위치 찍기`, `주소로 위치 찍기`)을 대시보드로 옮기고 위치 메뉴에는 국소 목록만 남긴다.
- `site_list_members.marker_id`에 마커 외래 키를 두지 않는다.
- 작업 국소를 제거하면 해당 임시 마커도 함께 제거한다.
- 목록 색상은 마커 색상 15색과 같다.

## DB

`supabase/migrations/20261107000000_site_lists.sql`. 적용은 사용자가 한다. 첫 관리자 등록 SQL은 저장소에 넣지 않는다.

| 테이블 | 조회 | 쓰기 |
|---|---|---|
| `app_admins` | 자기 행만 | 앱에서 불가. SQL Editor로만 |
| `site_lists` | 로그인 사용자 | 일반 목록은 로그인 사용자, 관리자 목록은 관리자만 |
| `site_list_members` | 로그인 사용자 | 소속 목록을 수정할 수 있는 사용자 |

관리자가 만든 목록은 `is_admin_list = true`로 저장한다. 판별 함수 `is_app_admin()`, `can_edit_site_list(id)`는 `SECURITY INVOKER`다. 읽는 행을 RLS 조회 정책이 이미 허용하므로 DEFINER가 필요 없다(`20261107000100_site_lists_invoker_functions.sql`). 마이그레이션 전에는 목록 패널에만 안내가 나오고 지도와 다른 메뉴는 그대로 동작한다.

## 검색 열 (데이터 구조와 대조)

국소명 `name`, 최종 국소명 `finalStationName`, 통합시설코드 `facilityCode`, 프로젝트코드 `projectCode`, 사업구분 `businessType`, 도로명·지번 주소. `사업코드` 열은 데이터에 없어 사업구분과 프로젝트코드로 대신한다. 코드와 사업구분은 마커의 대표 `information` 행 값이다.

## 표시

- `selectActiveMarkers("location")`은 선택한 목록에 속한 장비 마커만 돌려준다. 맵으로 모아 같은 국소도 마커는 하나다. 마커가 없는 소속 행은 표시하지 않는다.
- 숨은 SUB도 목록에 등록했으면 표시한다.
- 목록 색상은 `siteListColors`(최대 3개)와 `siteListExtraCount`로 넘긴다. 저장 색상 `color`는 바꾸지 않는다. 수정 화면이 이 값을 저장하기 때문이다.
- 핀은 색을 세로로 나눠 칠하고, 남은 목록 수는 가운데에 `+2`처럼 쓴다.
- 위치 메뉴의 정보창과 상세·수정 화면은 장비 마커로 동작한다. 상세 화면에 전체 소속 목록을 보여 준다.
- 위치 메뉴의 마커를 옮기면 장비 마커 위치가 저장된다. 임시 마커는 `pendingLocationMarkers`에 있는지로 구분한다.

## 대시보드 이동

- 두 기능을 작업 국소가 있을 때와 없을 때 화면 모두에 넣는다. 길찾기 탭에는 넣지 않는다.
- 임시 마커는 위치 메뉴에 표시하지 않는다. 대시보드 지도에는 지금처럼 표시한다.
- 작업 국소를 제거하면 임시 마커도 제거한다. 장비 마커로 연결된 국소는 `tempMarkerId`로 원래 임시 마커를 찾는다.
- 빈 화면의 `지도로 이동`은 지도 메뉴 첫 단계로 간다.

## 백업

전체 백업 파일에 `국소목록`, `국소목록소속` 시트를 추가한다. 시트가 없는 옛 백업을 복원하면 현재 목록을 건드리지 않는다. 일반 사용자의 복원은 일반 목록만 다룬다. 목록 복원이 실패해도 장비 복원은 유지하고 따로 알린다.

## 화면

`지도 → 위치`: 목록 만들기(이름, 색상), 목록 선택, 이름·색상 수정, 삭제, 국소 관리, 표시 중인 국소 목록. 국소 관리는 대화상자에서 검색, 복수 선택 추가, 복수 선택 제외를 한다. 수정 권한이 없는 관리자 목록은 조회만 된다.

번들 기준을 지키기 위해 패널은 지연 로딩한다.

## 검증

단위 테스트(표시, 검색, 권한, 복원 계획, 핀), `tsc`, `eslint`, `npm test`, `next build`, 가짜 데이터로 화면 확인. 권한 정책과 실제 저장은 사용자가 마이그레이션을 적용한 뒤 확인한다.
