# Ver 3.0 그룹관리 구현

근거: `Ver_3.0_계획.md` 12장. 상태: **구현 완료** (브랜치 `feat/ver-3.0-group-admin`, 2026-11-07). 실제 DB 저장·삭제는 사용자가 백업 후 확인한다.

## 목적

비활성이던 `그룹관리` 메뉴를 **관리자 전용 국소 자료 수정 화면**으로 만든다. 국소를 조회해 자료를 고치고, 같은 국소에 여러 마커가 찍힌 경우를 정리하고, 위치를 바로잡는다.

## 확정한 결정 (2026-11-07)

| 항목 | 결정 |
|---|---|
| 수정 범위 | 국소 정보 수정, 같은 국소의 여러 마커 정리, 위치(좌표) 수정, 여러 건 일괄 수정 모두 |
| 관리자 전용 | **화면에서만** 막는다. DB 쓰기 정책은 바꾸지 않는다 |
| 화면 구성 | 패널(목록·선택) + 넓은 관리 창(표 수정). 위치는 지도에서 수정 |
| 목록 단위 | 같은 번지로 묶인 국소(대표와 SUB) |
| 업로드 덮어쓰기 | 1차는 막지 않고 화면에 안내 문구만 넣는다 |

## 화면

**패널 (380px)**
- 검색과 필터: 연도, 상태, 사업구분, **좌표 없음**, **중복 의심**(같은 번지인데 모두 단독).
- 번지 묶음 목록. 행마다 체크박스, 묶음 마커 수, 대표 국소명. 체크하면 지도에 표시한다(위치 목록과 같은 방식).
- 상단 **[전체 화면 관리]**, 선택이 있으면 **[일괄 수정]**.

**관리 창**
- 지도 위 큰 대화상자. 왼쪽 묶음 목록, 오른쪽 선택한 묶음의 마커 표.
- 열: 구분, 국소명, 통합시설코드, 사업연도, 사업구분, 시설일, 개통일, 주소, 좌표. 셀은 줄바꿈하지 않고 가로 스크롤을 쓰지 않는다. 폭이 모자라면 창을 넓히고 세로 스크롤만 쓴다(프로젝트 규칙).
- 칸을 고치면 바뀐 칸을 표시하고, **[저장]** 한 번에 반영한다. 저장 전에는 **[변경 취소]**로 되돌린다.

**위치 수정**
- **[지도에서 위치 잡기]**: 관리 창을 접고 지도에서 마커를 드래그한다. 기존 드래그 확인 창을 쓴다.
- 좌표를 직접 입력할 수도 있다. 위도 33~39, 경도 124~132 범위를 벗어나면 저장하지 않는다.

## 수정 대상

| 테이블 | 수정하는 열 |
|---|---|
| `markers` | `name`, `lat`, `lng`, `memo`, `tags`, `color`, `facility_team`, `facility_code`, `road_address`, `jibun_address`, `parent_marker_id`, `group_role`, `group_key`, `detached_visible` |
| `information` | `place_name`, `facility_code`, `project_code`, `facility_year`, `business_type`, `final_station_name`, `eq_class`, `eq_type`, `install_date`, `open_date` |

- `erp_details`는 수정하지 않는다(공정 시트 원본 보존).
- `information`은 마커 하나에 여러 행일 수 있다. 행 단위(`id`)로 고친다.
- 날짜는 `yyyy-mm-dd`만 받는다. 빈 값은 허용한다.
- `markers.facility_code`와 `information.facility_code`는 같이 바꾼다. 다르게 두지 않는다.

## 정리 동작

대표 지정, 단독 변경, SUB 변경은 `marker-detail-modal.tsx`의 기존 규칙(`changeMarkerGroupRole`)을 **그대로** 쓴다. 규칙이 두 곳에서 어긋나지 않도록 그 로직을 공용 함수로 꺼낸다.

| 동작 | 결과 |
|---|---|
| 대표 지정 | 선택 마커가 대표, 같은 묶음의 단독이 아닌 마커는 SUB |
| 단독으로 | 묶음에서 빠진다. 대표였으면 남은 마커 중 새 대표 승격, 1개만 남으면 단독 |
| 분리 | 선택 마커들에 새 `group_key`를 주어 같은 번지 안의 새 묶음으로 만든다 |
| 합치기 | 선택한 묶음들을 같은 `group_key`로 묶고 대표 1개를 정한다 |
| 삭제 | 마커를 지운다(`information`, `erp_details`는 함께 삭제). 대표를 지우면 남은 마커로 대표를 다시 정한다 |

- 삭제와 합치기는 확인 창을 거친다. 삭제는 건수와 국소명을 보여 준다.
- 합치기·분리의 `group_key` 규칙은 기존 `buildSplitGroupKey`, `getEffectiveGroupKey`를 따른다.

## 저장

- 변경분을 모아 두었다가 **마커 → 정보 → 삭제** 순서로 건별 반영한다.
- DB 함수가 없어 **여러 건을 한 번에 원자적으로 저장하지 못한다.** 중간에 실패하면 일부만 반영될 수 있다. 실패하면 어디까지 저장됐는지 알려 주고, 남은 변경은 그대로 두어 다시 저장할 수 있게 한다.
- 저장 후 마커 조회를 새로 읽는다. 삭제나 대표 변경이 있었으면 해당 묶음의 대표/SUB를 다시 계산한다.
- 전체 재계산(`구분 재정리`)은 부르지 않는다. 마커마다 요청이 나가 무겁기 때문이다.

## 관리자 전용

- `NavItem`에 관리자 전용 표시를 추가한다. 관리자가 아니면 **메뉴를 그리지 않는다**(비활성이 아니라 숨김). 판별 전(로딩 중)에도 그리지 않는다.
- 판별은 `app_admins` 조회다. 위치 목록 안에 있는 `fetchIsAppAdmin`을 공용 훅 `useIsAdmin`으로 꺼내 둘이 함께 쓴다.
- 보고 있던 메뉴가 관리자 전용인데 권한이 없어지면 대시보드로 보낸다(기존 `isNavAccessible` 규칙).
- **한계:** DB 정책은 그대로라 로그인한 사용자는 API로 직접 마커를 고칠 수 있다. 이 화면은 그것을 막지 않는다. 막으려면 쓰기 정책 변경이 필요하고 일반 사용자의 마커 수정과 업로드에 영향을 주므로 이번 범위에 넣지 않았다.

## 알려진 위험

1. **업로드 덮어쓰기:** 위치등록의 `[기존 N건 갱신]`은 국소명과 `information`을 파일 값으로 다시 쓴다. 관리자가 고친 값이 다음 업로드 때 원래 값으로 돌아갈 수 있다. 관리 창에 안내 문구를 넣는다. 보호하려면 수동 수정 표시를 DB에 추가해야 하며 2차로 미룬다.
2. **비원자적 저장:** 위 `저장` 항목 참고.
3. **삭제는 되돌릴 수 없다.** 저장 전 취소만 가능하다. 삭제 전에 백업을 권한다는 문구를 확인 창에 넣는다.
4. **구분이 비어 있는 마커(현재 229개):** 재정리 전에는 묶음 판정이 어긋난다. 이 화면은 `구분 재정리`를 대신하지 않는다.

## 스펙에서 줄인 부분

- 개별 표시(`detached_visible`) 함수는 공용 함수로 옮기지 않았다. 새 화면이 쓰지 않아 제외했고, 상세 모달의 해당 핸들러는 그대로 둔다.
- 좌표 없는 마커는 지도에 핀이 없어 좌표를 직접 입력해서만 채울 수 있다. 지도 클릭 배치는 후속 후보다.
- 닫기·묶음 전환 확인은 `window.confirm`을 쓴다(alert-dialog 미설치). 필요하면 사용자가 `npx shadcn@latest add alert-dialog`로 설치한다.
- 일괄 수정 창은 자기 변경분과 [저장]을 따로 가진다. 관리 창의 변경분은 묶음 단위라 여러 묶음을 담을 수 없기 때문이다.
- 저장은 비원자적이며 건별 요청이라, 수백 묶음을 일괄 수정하면 느릴 수 있다.

## 이번에 하지 않는 것

`erp_details` 수정, 변경 이력과 저장 후 되돌리기, 엑셀로 일괄 수정, DB 권한 변경, 수동 수정 보호.

## 검증

- 단위 테스트: 묶음 만들기, 필터, 변경분, 정리 계획(대표 승격·1개 남음·합치기·분리·삭제), 입력 검증, 저장 순서와 실패 보고(가짜 Supabase).
- `tsc`, `eslint`, `npm test`, `next build`, 홈 번들 295 kB 이하.
- 가짜 로그인과 가짜 DB로 화면 확인(패널, 관리 창, 관리자 아닐 때 메뉴 숨김, 모바일 시트).

## 구현 순서

1. 공용 훅 분리와 상세 화면 로직 추출(테스트로 기존 동작 고정)
2. 순수 로직(`build-groups`, `group-filters`, `edit-draft`, `group-actions`)
3. 관리자 전용 메뉴와 패널
4. 관리 창: 표 수정과 저장
5. 정리 동작(대표·단독·분리·합치기·삭제)
6. 위치 수정과 일괄 수정
