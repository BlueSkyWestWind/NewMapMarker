작성일 2026-11-15 · 대상: `zod` 3.25.76 → 4.6.7, 사용처 2개 파일 · 구현계획: [Ver_3.0_zod업그레이드_구현계획.md](Ver_3.0_zod업그레이드_구현계획.md) · 구현: [Ver_3.0_zod업그레이드_구현.md](Ver_3.0_zod업그레이드_구현.md) · 조사: [Ver_3.0_zod업그레이드_조사.md](Ver_3.0_zod업그레이드_조사.md)

## 1. 배경과 결정 사항

`npm audit --omit=dev`가 `zod`를 **높음(7.5, 메모리 소진 DoS)** 으로 보고한다(GHSA-mrhx-c7xc-m3w5, 영향 범위 `<4.6.6`). 조사(primary source 기반, [조사 문서](Ver_3.0_zod업그레이드_조사.md))의 결론은 세 가지다.

- **3.x용 수정은 배포되지 않았다.** `v3.25.x` 브랜치에 병합만 됐고 npm의 3.x 마지막 버전은 3.25.76 그대로다. 해소하려면 4.6.6 이상으로 올리는 방법뿐이다.
- **이 프로젝트의 실제 위험은 낮다(추정).** 서버 경로는 `kakao-route` 한 곳이고 로그인 필요 + 본문 32 KiB 상한이 있다. 다른 사용처(`settings-schema`)는 관리자가 쓰는 DB 값을 브라우저가 검증한다.
- **이전 비용이 작다.** 이 프로젝트는 zod를 두 파일에서만 쓰고, 필수 코드 변경은 `z.record(sourceRef)` 1줄이다.

## 2. 확인한 사실

조사 문서의 핵심만 옮긴다. 근거(URL·명령 출력)는 조사 문서에 있다.

- **취약점**: 배열 검증 때 상한(`.max()`)이 원소를 모두 순회한 뒤에 실행돼, 큰 입력이면 실패 이슈를 원소 수만큼 쌓아 메모리를 쓴다. 수정은 상한 검사를 순회 앞으로 옮겼다(PR #6652). 4.6.6에 포함. 워크어라운드는 어드바이저리에 없다.
- **노출**: `kakao-route`의 `stops: z.array(pointSchema).min(1).max(31)`은 `guardProxyRequest`(동일 출처·레이트리밋·로그인)와 `MAX_BODY_BYTES = 32 * 1024`를 통과한 뒤에만 파싱된다. 32 KiB로 만들 수 있는 원소는 최대 약 1.6만 개(추정)로, 어드바이저리 예시(100만 개)보다 두 자릿수 작다.
- **이전에서 바뀌는 것**:

| 대상 | 내용 | 사용처 |
|---|---|---|
| `z.record(sourceRef)` | 값 스키마만 받는 형태가 제거됨. 키·값 2개가 필수 | `site-survey/lib/settings-schema.ts:21` → `z.record(z.string(), sourceRef)` |
| `z.number().finite()` | 무한값은 기본 거부라 no-op, 비권장 | `app/api/kakao-route/route.ts:25,26` — 지워도 동작 같음 |
| `issue.message` 문구 | 기본 오류 문구가 바뀔 수 있음 | `settings-schema.ts:74`가 사용자에게 보임 |
| `z.object(Object.fromEntries(...))` | 동적 shape의 타입 추론이 달라질 수 있음 | `settings-schema.ts:32` |

- **환경**: 이 프로젝트는 TypeScript 5.9.3, `strict: true`, Node `>=22`로 v4 요구(TS 5.5 이상, strict)를 충족한다. `target: ES2017` 호환은 공식 문서에 기재가 없어 확인하지 못했다(빌드로 확인한다).
- **zod를 쓰는 다른 곳**: 직접 사용은 `src/app/api/kakao-route/route.ts`와 `src/features/site-survey/lib/settings-schema.ts` 둘뿐이다. 다른 패키지가 zod에 의존하는지(`npm ls zod`)는 구현 때 확인한다.

## 3. 설계

### 3.1 변경 범위

1. `package.json`: `"zod": "^3"` → `"zod": "^4.6.7"`, 락파일 갱신(`npm install zod@^4.6.7`).
2. `site-survey/lib/settings-schema.ts:21`: `z.record(sourceRef)` → `z.record(z.string(), sourceRef)`.
3. `app/api/kakao-route/route.ts`: `.finite()` 호출 제거(선택, 동작 동일). 제거하면 경고가 사라지고, 남겨도 동작은 같다.
4. 오류 문구에 의존하는 테스트가 있으면 새 문구에 맞게 바꾼다(문구를 고정한 테스트가 있는지는 실행해 본다).

### 3.2 회귀 방지

- 이전 전에 **현재 동작을 고정하는 테스트가 있는지** 확인한다: `settings-schema` 검증(`parseOverrides` 정상·오류 입력), `kakao-route`의 본문 검증(`route.test.ts`). 없는 부분은 이전 **전에** 특성화 테스트를 쓴다(TDD의 "먼저 동작을 고정" 순서).
- 추가 테스트 하나: `kakao-route`에 `stops`가 32개(상한 초과)일 때 400을 돌려주는 케이스. 상한이 이전 뒤에도 같은 응답을 주는지 확인한다.

## 4. 범위 밖

- 입력 크기 제한 강화나 다른 DoS 방어(이미 본문 32 KiB 상한이 있다).
- zod 외 취약점(`@opennextjs/*`, `postcss`, `exceljs`→`uuid`, `esbuild`). `npm audit`의 "수정 제안"은 옛 버전으로 내리라는 잘못된 제안이라 따르지 않는다. 별도 점검 대상이다.
- zod를 쓰는 새 코드 추가.

## 5. 위험과 검증

- **번들 크기**: zod v4의 크기가 v3와 다를 수 있다. `settings-schema`는 현장실사서(지연 로드 화면)의 클라이언트 코드라 홈 번들에는 들어가지 않을 것으로 보이나, 임시 distDir 빌드로 **홈 282 kB와 현장실사서 청크를 전후 비교**한다.
- **타입 추론**: `z.object(Object.fromEntries(...))` 한 곳의 타입이 바뀌면 `tsc`가 잡는다.
- **ES2017 타깃**: 문서에 기재가 없다. 빌드와 테스트로 확인하고, 문제가 있으면 이 작업을 멈추고 알린다.
- **오류 문구**: 사용자에게 보이는 문구(현장실사서 설정 오류 메시지)가 영어 기본 문구라면 바뀔 수 있다. 어떤 화면에 어떻게 보이는지 구현 때 확인한다.
- **공급망**: 결정 5의 확인을 구현 전에 한다.
- **검증**: `npx tsc --noEmit`, `npx eslint . --max-warnings=0`, `npm test`, `npm audit --omit=dev`(zod 항목이 사라졌는지), 임시 distDir 빌드.

## 6. 사용자 확인 필요 항목

1. **지금 올릴지**: 올린다(추천) / 3.x 패치 배포를 기다린다(배포 시점 불명) / 위험이 낮다고 보고 보류한다. 위험이 낮아도 `npm audit`의 높음 경고가 계속 남는다는 점이 판단 기준이다.
2. 공급망 확인에서 이상이 있으면 어떤 버전으로 고정할지는 그때 정한다.
