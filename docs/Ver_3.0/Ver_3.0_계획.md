# MapMarker Ver 3.0 계획서

작성일: 2026-11-05  
상태: 결정 사항 정리 완료, 검토 대기 — 검토 후 구현 문서를 만들어 한 번에 구현한다

## 1. 목적과 범위

지도 탭의 핵심 업무를 개선한다. 장비·축전지·위치/좌표는 유지하고, 위치는 기존 장비 국소를 목적별로 모아 보여주는 목록 중심 메뉴로 변경한다. 장비는 현재 연도의 시설 진행 상태를 색상과 필터로 표시한다. 업로드 엑셀과 데이터베이스도 함께 정비한다.

카카오와 네이버 지도 비교·전환은 별도 검토 사항이며 이번 계획에서 지도 제공자를 결정하지 않는다.

## 2. 위치 메뉴: 국소 목록

- 사용자가 `철거대상`, `고속도로`처럼 목록 이름을 만들고 색상을 지정한다.
- 기존 장비 국소를 국소명, 사업코드·프로젝트코드·통합시설코드, 주소로 검색해 목록에 등록한다. 실제 검색 열은 데이터 구조와 대조한다.
- 한 국소를 여러 목록에 등록할 수 있다. 여러 국소를 함께 선택해 추가하는 방안을 적용한다.
- 하나 또는 여러 목록을 선택하면 해당 국소만 지도와 목록에 표시한다. 같은 국소가 여러 목록에 있어도 마커는 하나다.
- 마커에 선택된 목록의 색상을 최대 3개와 나머지 목록 수(`+2` 등)로 표시한다. 상세 정보에서 전체 소속 목록을 확인한다.
- 목록에서 국소를 제외해도 기존 장비 국소는 삭제하지 않는다. 목록과 소속 정보는 여러 사용자가 다시 볼 수 있도록 저장한다.

### 권한

| 목록 | 조회 | 이름·색상 수정, 국소 추가·제외, 목록 삭제 |
|---|---|---|
| 관리자가 생성 | 로그인 사용자 | 관리자만 |
| 일반 사용자가 생성 | 로그인 사용자 | 모든 로그인 사용자 |

관리자 판별을 신뢰할 수 있는 서버 측 정보로 처리하고 DB 권한 정책으로도 보호한다. 현재 코드와 마이그레이션에는 관리자 구분이 없고 로그인 사용자의 권한이 모두 같다(2026-11-06 확인).

**관리자 판별(확정, 2026-11-06):** DB에 관리자 테이블을 새로 두고 권한 정책이 이 테이블을 확인한다. 추가·제외는 SQL로 하고 바로 적용된다. 일반 사용자는 이 테이블을 수정할 수 없게 한다. 저장소가 공개 상태이므로 관리자 이메일은 마이그레이션과 문서에 적지 않고, 사용자가 SQL Editor에서 별도로 등록한다. 첫 관리자는 사용자가 지정한 계정 1개다.

구현 내용은 `Ver_3.0_위치목록_구현.md`를 따른다.

### 기존 임시 마커 기능 이동(확정, 2026-11-06)

위치 메뉴의 `엑셀로 위치 찍기`와 `주소로 위치 찍기`를 대시보드 작업 등록으로 옮기고, 위치 메뉴에는 국소 목록만 남긴다. 두 기능은 이미 임시 마커를 오늘의 작업 국소에 함께 등록하므로 동작은 바꾸지 않고 위치만 옮긴다.

코드에서 확인한 수정 지점:

- **대시보드 화면:** `dashboard-panel.tsx`는 작업 국소가 없을 때 별도 화면을 반환한다. 옮긴 기능은 **작업 국소가 없을 때와 있을 때의 두 화면 모두**에 넣는다. 경로 탭에는 넣지 않는다.
- **빈 화면 안내:** "위치 탭에서 엑셀·주소로 위치를 등록" 문구와 `지도로 이동` 버튼의 위치 메뉴 이동을 새 흐름에 맞게 고친다.
- **지도 표시:** 위치 모드는 지금 임시 마커만 보여 주므로(`select-active-markers.ts`) 선택한 목록의 국소를 보여 주도록 바꾼다. 대시보드는 이미 작업 등록한 임시 마커를 지도에 표시한다.
- **건수 표시:** `app-shell.tsx`의 `위치 N건 · 임시`와 `work-panel.tsx`의 `위치 N건`을 목록 기준으로 고친다.
- **경로 기능:** 임시 마커를 스토어에서 읽으므로 스토어를 유지하면 영향이 없다. 구현 후 경로 후보에 임시 마커가 나오는지 확인한다.

구현 때 확인할 사항:

- **업로드 대상:** 대시보드는 `weather` 모드라 스토어의 저장 위치가 장비 임시 마커 쪽으로 잡힌다(`getPendingKey`). 옮긴 뒤에도 임시 마커가 위치 쪽에 저장되는지 확인한다.
- **임시 마커 제거:** 지금은 위치 메뉴의 `등록 위치` 목록에서 관리한다. 대시보드에서 작업 국소를 제거해도 임시 마커는 스토어에 남으므로 경로 후보에 계속 나올 수 있다. 제안은 작업 국소를 제거할 때 해당 임시 마커도 함께 제거하는 것이다(확인 필요).

## 3. 장비 시설 상태

현재 연도 사업 장비만 사용해 국소별 대표 상태를 판정한다. 예를 들어 2026년에는 2025년 장비를 제외하고 2026년 장비 전체를 확인한다.

| 조건 | 상태 | 지도 색상 |
|---|---|---|
| 올해 장비 중 하나라도 시설일이 없음 | 미시설 | 에메랄드 |
| 미시설은 없고 개통완료되지 않은 장비가 하나라도 있음 | 시설 | 회색 |
| 올해 장비가 모두 시설 및 개통완료 | 개통완료 | 흰색 |
| 올해 장비가 없음 | 올해 대상 없음 | 기존에 저장된 색상 |

상태 필터를 추가한다. 시설일이 없으나 개통일이 있는 예외 데이터는 미시설로 표시하는 방안이다.

**처음 화면(확정, 2026-11-06):** 해당 연도의 국소만 나오고 개통완료 국소는 보이지 않는다. 즉 처음에는 올해의 미시설·시설 국소만 표시한다. 개통완료 국소는 상태 필터에서 `개통완료`나 `전체`를 고르면 나타난다.

**필터 형태(제안, 확인 필요):** 기존 필터와 같은 복수 선택 드롭다운으로 만들고 값은 `미시설`·`시설`·`개통완료`·`올해 대상 없음`이다. 기본 선택은 `미시설`·`시설`이고, 모두 선택하면 버튼에 `전체`로 표시한다.

필터 동작(2026-11-06 사용자 답변 기준):

- 올해 장비가 없는 국소는 `미시설`·`시설`·`개통완료` 필터에 나오지 않는다. 해당하는 국소가 없으면 없는 대로 비어 있게 둔다.
- `전체`를 고르면 그 조건으로 걸러내지 않고 전체를 보여 준다. 올해 장비가 없는 국소는 기존 저장 색상으로 표시한다.
- 상태 필터와 연도 필터는 각각 독립적으로 적용한다. 어느 한쪽이 다른 쪽의 선택을 덮어쓰지 않는다.

향후 연도별 상태 판정이 가능하도록 기준 연도를 분리한다.

**대표/SUB 집계(확정, 2026-11-06):** 대표 마커는 자기 장비와 숨은 SUB의 올해 장비를 합쳐 판정한다. 개별 표시(`detachedVisible`)로 지정한 SUB는 자기 장비만으로 판정한다. 대표 장비가 개통완료여도 숨은 SUB가 미시설이면 대표 마커는 미시설로 표시한다.

**연도 필터(제안에 이의 없음, 2026-11-06):** 현재 연도 필터는 마커의 상세 정보 첫 행의 연도만 본다. 그래서 대표가 2025년이고 SUB가 2026년인 국소는 올해 필터에서 빠진다. 그룹 안의 장비 중 하나라도 선택한 연도에 해당하면 통과하도록 바꾼다.

**연도 기본값:** 커밋 전 코드의 `올해 + 미지정` 선택은 유지한다. 연도 미지정 국소는 상태가 `올해 대상 없음`이라 처음 화면에는 나오지 않으며, 상태 필터에서 `올해 대상 없음`이나 `전체`를 고르면 나타난다. 올해 마커가 하나도 없을 때 연도를 전체 선택하는 동작은 처음 화면이 어차피 비므로 제거한다.

**색상 필터(확정, 2026-11-06):** 지도에 보이는 색을 기준으로 거른다. 지도·필터·클러스터·캡처가 같은 표시색을 쓰고, DB의 저장 색상은 바꾸지 않는다.

**색상 겹침(제안, 확인 필요):** 기본 저장 색상 `#10b981`이 미시설 에메랄드와 같아, `전체`에서 올해 대상이 없는 국소가 미시설처럼 보일 수 있다. 색상을 따로 바꾸지 않고, 구분이 필요하면 상태 필터를 쓰는 방안이다. 회색 `#64748b`는 마커 색상 선택지에 없어 저장 색상으로는 드물다.

**마커 색상 5개 추가(사용자 요청, 2026-11-06):** 현재 10개인 마커 색상 선택지를 15개로 늘린다. 아래 색상과 적용 범위는 제안이며 확인이 필요하다.

- **고른 기준:** 기존 선택지, 상태색(에메랄드·회색·흰색), 임시 마커 빨강(`#ef4444`), 대기 마커 골드(`#f59e0b`)와 겹치지 않는 색이다.
- **수정 지점:** `marker-edit-modal.tsx`의 `COLOR_OPTIONS`, `facility-teams.ts`의 `LEGACY_COLOR_NAMES`·`COLOR_NAME_ALIASES`·`COLOR_FILTER_ORDER`. 이름 표를 함께 고쳐야 백업·복원에서 색상 이름이 유지된다.

- **재업로드 초기화:** 공정관리 파일을 다시 올리면 기존 마커의 색상·메모·태그·담당팀이 기본값으로 덮어써지는 것으로 보인다. 이 네 값을 보존하도록 고친 뒤에 운영 데이터를 다시 올린다.

상태색은 표시용으로 적용하고 기존 저장 색상을 보존하는 방안이다. 흰색 마커의 배경 대비, 기존 색상 필터·클러스터·캡처와의 일관성을 검증한다.

## 4. 데이터베이스

- 국소 목록, 색상, 생성자·관리자 목록 구분, 목록과 국소의 연결을 저장하는 구조를 설계한다. 동일 목록에 같은 국소가 중복 저장되지 않도록 한다.
- 로그인 사용자의 조회와 일반 목록 공동 편집, 관리자 목록 보호를 DB 정책으로 검증한다. 목록에서 제거하거나 목록을 삭제해도 원본 장비가 삭제되지 않게 한다.
- 저장소의 장비 상세 `information`에는 이미 `facility_year`, `install_date`, `open_date`가 있다. 현재 코드가 대표 정보 한 건을 지도 모델에 사용하는 만큼, 모든 올해 장비를 판정에 활용하도록 조회 구조를 검토한다.
- `open_date`는 현재 화면에서 개통일로 사용된다. 이것이 업무상 시험완료·개통완료와 같은 의미인지와 운영 DB의 실제 열·값을 먼저 확인한다. 의미가 같으면 기존 필드 재사용을 우선 검토하고, 다르면 필요한 필드를 별도 설계한다. 신규 필드 추가는 확정되지 않았다.
- Supabase 스키마와 권한 변경은 마이그레이션 SQL로 준비한다. 프로젝트 규칙에 따라 사용자가 적용한다. 기존 데이터 보존, 적용 순서와 복구 방법을 함께 정리한다.

### 위치 목록 저장 구조(확정, 2026-11-07)

| 테이블 | 주요 열 | 역할 |
|---|---|---|
| `app_admins` | `user_id`(기본 키) | 관리자 목록. 일반 사용자는 수정할 수 없다 |
| `site_lists` | `id`, `name`, `color`, `is_admin_list`, `created_by`, `created_at`, `updated_at` | 국소 목록 |
| `site_list_members` | `list_id`, `marker_id`, `added_by`, `created_at`, 기본 키 (`list_id`, `marker_id`) | 목록과 국소의 연결. 기본 키로 중복을 막는다 |

- **관리자 목록 구분:** 관리자가 만든 목록은 `is_admin_list = true`다. 권한 정책이 `app_admins`를 확인해 일반 사용자가 이 값을 바꾸거나 관리자 목록을 수정하지 못하게 막는다.
- **마커 참조:** `site_list_members.marker_id`에 `markers`로 향하는 외래 키를 두지 않는다. 마커 삭제나 전체 복원으로 관리자 목록을 포함한 소속이 지워지지 않게 하기 위해서다. 복원 후 같은 ID의 마커가 돌아오면 소속이 그대로 이어진다. 마커가 없는 소속 행은 화면에서 표시하지 않는다.
- **목록 삭제:** `site_list_members.list_id`는 `site_lists`를 `ON DELETE CASCADE`로 참조한다. 목록을 지우면 소속만 지워지고 원본 장비는 남는다.
- **적용:** 마이그레이션 SQL을 사용자가 적용한다. 첫 관리자 등록 SQL은 이메일이 들어가므로 저장소에 넣지 않고 구현 때 따로 전달한다.

## 5. 엑셀 업로드 양식 정비

- 실제 사용 중인 장비 업로드 엑셀을 받아 열 이름·입력 예·코드·날짜 형식과 기존 업로드 종류를 조사한다.
- 국소명, 사업연도, 프로젝트코드, 통합시설코드, 주소, 시설일, 개통일 및 실제 필수 열을 정리한다. 사업코드와 프로젝트코드의 관계도 확인한다.
- 변경할 업로드 양식과 파서를 함께 설계한다. 기존 코드에는 시설일과 개통일 인식 및 업로드 처리가 있으므로 중복 필드를 만들기 전에 사용 의미와 현행 흐름을 대조한다.
- 빈 양식과 작성 예시, 필수·선택 열 설명을 제공하는 방안이다. 기존 파일 호환 여부와 열이 없거나 날짜가 잘못된 경우의 처리는 확정 후 명시한다.
- **옛 양식 처리(확정, 2026-11-06):** 시설일 열이나 개통일 열을 찾지 못하면 저장 전에 업로드를 중단하고 새 양식의 날짜 열을 찾지 못했다고 안내한다. 업로드가 기존 상세 정보를 지우고 다시 넣으므로, 옛 양식을 그대로 받으면 기존 날짜가 사라지고 해당 올해 국소가 모두 미시설로 바뀌기 때문이다. `ACTA 구축완료일`을 날짜로 대신 쓰지 않는다. 열이 있고 일부 행의 값만 비어 있는 경우는 지금처럼 미시설·미개통으로 판정한다.
- **위치 목록의 엑셀 처리(확정, 2026-11-06):** 엑셀 일괄 등록은 이번에 만들지 않고, 검색과 복수 선택으로 등록한다. 목록과 소속은 기존 전체 백업에 포함해 복원 때 함께 되살린다. 목록 데이터가 없는 옛 백업 파일을 복원하면 현재 목록은 건드리지 않는다. 관리자 목록은 관리자가 복원할 때만 되살리고, 일반 사용자의 복원은 권한 정책에 따라 일반 목록만 다룬다.
- 업로드 미리보기·오류 안내·일치하지 않는 국소 및 코드 처리, 대량 업로드를 검증한다.
- 엑셀 내보내기 및 백업·복원에서 필요한 데이터가 사라지지 않는지 확인한다. 목록을 엑셀로 일괄 등록하거나 백업할지는 별도 결정 사항이다.

## 6. 작업 단계와 검증

1. **현황 확인:** 관리자 권한, 운영 DB 스키마, 연도 및 날짜 필드 의미, 실제 엑셀 양식, 대표/SUB 관계를 확인한다.
2. **상세 설계:** 목록 저장·권한과 기존 위치 기능 처리, 상태 및 기존 연도/색상 필터 연동, 엑셀 양식·호환 방침을 확정한다.
3. **장비 상태:** 재업로드 시 색상·메모·태그·담당팀을 보존하도록 고친다. 필요한 DB 변경 및 엑셀 처리를 준비하고 현재 연도 전체 장비의 상태 계산·색상·필터를 구현한다.
4. **위치 목록:** 목록 저장·공유 권한·검색·복수 선택·색상 표시를 구현한다.
5. **로그인 세션:** 로그인 후 7일 만료를 구현한다(9장).
6. **검증:** 혼합 연도, 부분 미시설, 부분 개통, 모두 개통, 올해 대상 없음, 날짜 누락, 대표/SUB, 재업로드 후 값 보존, 목록 중복·권한 우회, 업로드·백업 복원, 흰색 마커 대비, 세션 만료를 확인한다. 타입 검사·린트·단위 테스트·빌드 및 주요 화면 테스트를 수행한다.
7. **적용 준비:** DB 마이그레이션 적용 순서와 복구 방법, 배포 후 점검을 정리한다. 재업로드 보존 수정을 배포한 뒤 새 양식을 운영에 올리는 순서를 포함한다.

## 7. 구현 전 결정 사항

1. 기존 개통일이 시험완료·개통완료와 동일한 의미인지, 운영 DB에 실제로 값이 있는지.
2. 실제 업로드 엑셀 파일과 열 구성, 기존 양식 호환 여부.
3. 관리자 계정 구분 방법과 관리자 목록 권한 정책.
4. 올해 사업연도 기준 필드와 대표/SUB 국소의 장비 집계 범위.
5. 기존 위치 메뉴의 주소·엑셀 임시 마커 기능을 어디에 유지할지.
6. 올해 장비 없는 국소의 개별 상태 필터 처리 및 기존 색상 필터와의 관계.
7. 위치 목록의 엑셀 일괄 등록·백업 필요 여부.

각 항목의 현재 상태는 8장을 따른다. 운영 DB 변경은 아직 수행하지 않았다.

## 8. 진행 현황 (2026-11-06 갱신)

### 엑셀 업로드 양식: 공정관리 시트(`공정_일정관리.xlsb`) 반영 완료

기존 공정관리(ERP) 업로드 경로(`erp-parse.ts`)를 새 양식에 맞췄다. 새 업로드 경로를 만든 것이 아니다.

- **읽는 시트:** `일정관리`. 열 위치는 `프로젝트` A열, `통합시설코드` B열이다. 같은 이름의 열이 뒤에 또 있으면(CG~CM열 사본) 앞쪽 열을 기준으로 한다. 이전에는 뒤쪽 값이 덮어썼다.
- **시설일:** `장비 공사` 열. **개통일:** `시험 완료` 열. 이전에는 둘 다 `ACTA 구축완료일`이었다. 이 대응은 사용자가 확정했다(2026-11-06).
- **날짜 처리:** `3/27/26` 형식을 `yyyy-mm-dd`로 바꾼다. `불필요`·`미확정` 같은 글자는 빈 값으로 처리한다.
- **파일 형식:** 장비 엑셀 업로드가 `.xlsb`도 받는다.
- **양식 변경 대응:** 읽을 열 이름과 시트 이름은 `erp-columns.ts` 한 곳에서만 정한다. `장비설치`·`개통일` 전용 열이 생기면 자동으로 우선 사용한다.
- **현재 파일의 날짜 입력 현황(`일정관리` 시트, 112행):** `장비 공사` 50행, `시험 완료` 2행. 값이 비면 미시설·미개통으로 판정한다.
- **검증:** 단위 테스트(`erp-parse.test.ts`), 타입 검사, 린트 통과. 실제 파일을 앱에서 올려 본 확인은 아직 하지 않았다.

### 결정 사항 갱신

- 2번 결정 사항(실제 업로드 엑셀과 기존 양식 호환)은 확정했다. 실제 파일과 열 구성을 확보했고, 호환 방침은 5장을 따른다.
- 1번 결정 사항(개통일 의미)은 확정했다. 시설일은 `장비 공사`, 개통일(개통완료 판정 기준)은 `시험 완료` 열이다. 운영 DB의 `open_date` 의미와 기존 값은 구현 전에 한 번 더 대조한다.
- 3번 결정 사항(관리자)은 확정했다. 관리자 테이블로 판별한다(2장).
- 4번 결정 사항 중 대표/SUB 집계 범위는 확정했다(3장). 올해 기준 필드는 현재 코드의 `facility_year`를 쓰는 방안이다.
- 5번 결정 사항(임시 마커 기능)은 확정했다. 대시보드 작업 등록으로 옮긴다(2장).
- 6번 결정 사항(상태 필터 처리, 색상 필터와의 관계)은 확정했다(3장).

### 그 밖의 진행 내용

- **연도 필터 기본값(커밋 전):** 기본 선택을 `올해 + 미지정`으로 바꿨고, 버튼에 선택한 연도 이름을 표시한다. 올해 마커가 하나도 없으면 전체를 선택하는 동작은 구현 때 제거한다(3장).
- **구현 방식:** 남은 결정 사항을 정리한 뒤 한 번에 구현한다. 장비 상태를 먼저, 위치 목록을 다음에 진행한다.
- **문서 운영:** Ver 3.0의 계획과 결정은 이 문서에만 추가하고 이전 버전 문서를 모아 둔 `docs/이전버젼/` 폴더는 수정하지 않는다. 코드를 변경할 때는 이 문서를 보고 구현 문서를 `docs/Ver_3.0/`에 만든 뒤 그 문서에 따라 작업한다.

- 7번 결정 사항(위치 목록의 엑셀 처리)은 확정했다(5장).
- **장비 상태 구현 문서(2026-11-07):** 3장의 상태 판정·표시색·상태 필터·연도 필터 보정·색상 5개를 `Ver_3.0_장비상태_구현.md`로 정리했다. 8장 "확인할 제안"은 사용자가 달리 정하지 않아 제안대로 적용한다.

### 구현 문서 작성 전 확인할 제안

사용자가 다르게 정하지 않으면 아래 제안대로 구현 문서를 작성한다.

- **상태 필터 형태:** 복수 선택 드롭다운, 값 4개, 기본 `미시설`·`시설`(3장).
- **색상 겹침:** 색상을 바꾸지 않고 상태 필터로 구분한다(3장).
- **추가 색상:** 네이비·스카이·옐로·브라운·버건디, 위치 목록도 같은 15색을 쓴다(3장).
- **임시 마커 제거:** 작업 국소를 제거하면 해당 임시 마커도 함께 제거한다(2장).
- **위치 목록 저장 구조:** 소속 테이블에 마커 외래 키를 두지 않는다(4장).
- **전체 복원 권한:** 소속이 마커 삭제의 영향을 받지 않으므로 복원 권한은 지금처럼 유지한다.
- **문서 경로:** `docs/이전버젼/` 이동으로 어긋난 `README.md`와 `AGENTS.md`의 경로를 구현 때 고친다.


## 9. 로그인 세션 유지 기간

현재는 직접 로그아웃하기 전까지 로그인이 계속 유지된다. 로그인 후 7일이 지나면 자동으로 로그아웃되도록 바꾼다(사용자 요청, 2026-11-06). 아직 구현하지 않았다.

- **기준 시각:** 마지막 사용 시점이 아니라 로그인한 시점부터 7일이다(제안에 이의 없음, 2026-11-06). 매일 사용해도 7일이 지나면 다시 로그인한다.
- **시각을 읽는 곳:** 액세스 토큰의 인증 시각(`amr`)을 쓰고, 값이 없으면 `user.last_sign_in_at`을 쓴다. 토큰에 이 값이 있는지는 구현할 때 실제 토큰으로 확인한다.
- **판정 시점:** 앱을 열 때, 세션이 바뀔 때, 만료 시각이 됐을 때, 탭이 다시 보일 때.
- **만료 시 동작:** 해당 기기에서 로그아웃하고 기존 로그인 화면(`AuthGate`)으로 돌아간다.
- **수정 범위:** 판정 함수와 테스트(`src/features/map-marker/lib/session-expiry.ts`)를 새로 만들고 `auth-provider.tsx`에서 호출한다. DB 변경은 없다.
- **보안 범위:** 앱 화면에서 로그아웃시키는 방식이다. 이미 유출된 토큰까지 막으려면 Supabase 대시보드의 세션 시간 제한을 168시간으로 설정해야 하며, 사용 중인 요금제에서 가능한지 확인이 필요하다.
- **배포 직후:** 로그인한 지 7일이 넘은 사용자는 배포 후 앱을 열 때 한 번 로그아웃된다.


## 10. 사이드바 재설계

레일과 패널 구조를 드릴다운 사이드바로 바꾼다(디자인 확정, 2026-11-06. 구현 완료, 2026-11-07). 참고한 디자인은 MiHCM 디자인 시스템 Main Sidebar의 `variant=drilldown` + `collapsible=icon`이다. 시안은 [MapMarker 사이드바 디자인안](https://claude.ai/artifact/Fb9TsUBGmVwYBxR6yRJ2ov)에 있다.

### 데스크톱·태블릿(768px 이상)

- **레일:** 56px 아이콘 레일. 활성 메뉴는 칸 전체를 채워 표시한다. 메뉴 이름은 툴팁과 패널 제목으로 보여 주며 줄이지 않는다.
- **패널 첫 단계:** 제목, 설명, 검색, 하위 메뉴 목록. 지도는 장비·축전지·위치·위치/좌표, 마커관리는 장비·축전지다. 하위 메뉴가 없는 메뉴는 기존 패널을 바로 보여 준다.
- **패널 상세 단계:** 상위 메뉴 이름, 뒤로, 제목과 기존 패널 내용. 필터는 2×2 그리드로 줄인다.
- **펼친 트리:** 원형 화살표로 256px 트리와 레일을 전환한다. 메뉴 검색, 안내선, 건수 배지를 넣는다.
- **기존 동작 유지:** 비로그인 잠금, `setMapSegment`·`setMode`, 메뉴 표기, 지연 로딩을 그대로 둔다.

### 모바일(768px 미만)

현재는 패널이 `100vw - 56px` 폭으로 지도를 덮고, `isSidebarOpen` 기본값이 `true`라 첫 화면부터 지도가 거의 보이지 않는다(사용자 지적, 2026-11-06). 모바일에는 레일과 트리를 쓰지 않고 아래 구조로 바꾼다.

- **하단 메뉴:** 대시보드, 지도, 마커관리, CCTV, 더보기. 그룹관리, 바코드/QR, 데이터백업/복원, 설정은 더보기에 둔다. 비로그인 숨김 규칙은 그대로 적용한다.
- **하단 시트:** 패널을 지도 위 시트로 바꾼다. 높이는 낮음(제목만), 절반, 전체 세 단계이고 손잡이로 조절한다. 드릴다운과 뒤로는 시트 안에서 동작한다.
- **지도 복귀:** 검색 결과나 목록 항목을 고르면 시트를 낮음으로 내려 지도에서 위치를 바로 보여 준다. 활성 메뉴 탭을 다시 눌러도 내려간다.
- **첫 화면:** 시트를 낮음으로 시작해 지도가 먼저 보이게 한다.
- **예외:** 지도가 없는 바코드/QR은 시트를 전체 높이로 연다.
- **함께 고칠 곳:** `cctv-video-modal.tsx`와 `barcode-lightbox.tsx`가 뷰포트 왼쪽 오프셋으로 데스크톱 폭을 쓰므로 모바일에서는 0으로 처리한다.

## 11. 위치등록 업로드: 신규 확인 후 저장(확정, 2026-11-06)

공정관리 파일 전체를 한 번에 저장하던 방식을, 행을 나눠 신규 건만 사용자가 위치를 확인한 뒤 저장하는 방식으로 바꾼다. 구현 내용은 `Ver_3.0_위치등록_신규확인_구현.md`를 따른다.

- **업로드 위치:** 공정 파일은 `마커관리 → 장비`의 `위치등록 업로드` 한 곳에서 올린다. 10장의 사이드바에서도 `마커관리 → 장비` 상세 단계에 둔다.
- **`추가항목 업데이트` 제거:** 공정 정보 갱신은 `기존 N건 갱신`이 맡으므로 버튼을 없앤다. information 양식 파일은 더 이상 올릴 수 없다.
- **판단 기준:** 통합시설코드로 신규·기존을 나눈다. 코드가 없는 행은 저장하지 않고 안내한다.
- **주소 없는 행:** 주소가 비었거나 `불필요`·`미확정`인 행은 마커로 등록하지 않는다. `임시_LTE_예비품전환_서부`, `임시_5G_예비품전환_서부`도 불필요 데이터로 확정해 이 규칙으로 제외한다.
- **신규 확인:** 주소 변환만으로는 넓은 부지의 정확한 위치를 알 수 없으므로 신규 건을 모두 직접 확인한다. 좌표가 없는 기존 건도 같은 목록에서 확인한다.
- **저장 시점:** [확인]을 누를 때 건별로 바로 저장한다(B안).
- **주소 대조:** [확인] 때 마커 위치의 주소를 엑셀 주소와 비교한다. 같으면 저장하고 다음 건으로 넘어간다. 다르거나 비교할 수 없으면 두 주소를 보여 주고 사용자가 결정한다.
- **임시 저장:** 확인하지 못한 건과 옮긴 위치를 브라우저에 자동 저장하고 다음 접속 때 복원한다. 같은 브라우저·같은 계정에서만 이어서 할 수 있다.
- **기존 건:** 좌표·메모·태그·색상·담당팀·등록일·주소를 유지한다. 국소명과 공정 정보만 파일 값으로 갱신한다.
- **지도 메뉴 업로드:** 공정관리 시트도 DB에 저장하지 않고 임시 마커로만 표시한다.
- **옛 양식:** 5장의 결정대로 시설일이나 개통일 열이 없으면 저장 전에 중단한다.

### `일정표_New` 구조(엑셀에서 확인)

- 날짜마다 **10행** 블록이다(`6/29/26` ~ `1/3/27`, 195일). 날짜는 A열 모든 행에, 요일은 B열 첫 행에 있다.

- 입회자·신호수·스카이 같은 항목은 별도 열이 아니라 같은 팀 열 안의 행에 `입회 : 이름`, `신호수 : 이름`, `스카이`처럼 글자로 적는다. 그래서 칸 내용은 자유 글이고, 행 위치가 의미를 가진다.
- **날짜별 이름(정정, 2026-11-07):** 블록 4번째 행의 B열에 사람 이름이 들어 있다(61일, 서로 다른 이름 9개). 주간 배포 이미지에서도 요일 아래에 보이므로 일정의 일부다. 무슨 역할인지는 확인하지 못해 앱에서는 `날짜 메모`로 부른다(UI 문구는 사용자가 정한다).
- **칸 색(추가 확인, 2026-11-07):** 팀 열 쌍의 배경색이 날짜×팀 단위로 한 블록 10행 전체에 칠해져 있다(10행 균일 1,898건, 일부 행만 다른 경우 52건). 색은 5가지: `D9F2D0`(초록, 1,282칸) · `F2CFEE`(분홍) · `4E95D9`(파랑) · `FF5050`(빨강) · `D1D1D1`(회색). 의미는 확인하지 못했다.
- 맨 위 1~4행의 중장비 범례와 끝 행(`끝`)은 일정이 아니라서 가져오지 않는다.

### 데이터 모델(결정)

일정표의 한 칸 쌍 = 한 행으로 저장한다.

- `schedule_columns`: 열 설정(팀 이름, 팀장 이름, 순서). 첫 마이그레이션이 팀 이름 10개를 넣고, 팀장 이름은 비워 둔다. 팀장은 직원 실명이라 공개 저장소에 적지 않고, 가져오기나 화면에서 입력한다.
- `schedule_cells`: `work_date`, `column_id`, `row_no`, `main_text`, `sub_text`, `text_color`(없음 또는 `0070C0`·`FF0000`). 같은 날짜·열·행에는 하나만 둔다(고유 키). 빈 칸은 저장하지 않는다.
- `schedule_days`: 날짜별 메모(`work_date` 기본 키, `note`). 위 `날짜 메모`다.
- `schedule_marks`: 날짜×팀 칸 색(`work_date`, `column_id`, `color`, 기본 키는 앞의 둘). 색은 위 5가지 중 하나이고, 지우면 색 없음이다.
- 이동은 날짜·열·행 값을 바꾸는 것이다. 대상 칸이 차 있으면 둘을 맞바꾼다.
- 읽기는 로그인 사용자 전체, 쓰기는 `is_app_admin()`만(DB 정책으로 막는다).

### 주간 배포 내보내기(추가 요청, 2026-11-07)

| 단위 | 항상 월~일 한 주씩. 시작 주와 주 수(1~12주)를 고른다. 기간 중간 날짜를 고르면 그 주 전체가 들어간다 |

**새 패키지 필요(결정 필요):** 지금 쓰는 `xlsx`(SheetJS 무료판)는 배경색·테두리·글자색·쪽 나눔을 파일에 쓰지 못한다. 위 모양을 만들려면 `exceljs`가 필요하다. 브라우저에서 내려받기 직전에만 `dynamic import`로 불러 홈 번들(295 kB)에는 들어가지 않는다. 설치 크기는 약 22 MB(node_modules)다. PDF로 바로 만드는 방법도 있으나 이번에는 엑셀만 한다.

**내보내기 세 가지:** 같은 창에서 `주간 배포용`(위 모양, 기본), `월간 배포용`(월 달력), `일정표_New 형식`(열 구성이 원본과 같고 범례·날짜 메모·색·글자색을 포함해 가져오기와 왕복 가능)을 고른다. 세 파일 모두 `exceljs`로 쓴다. 읽기는 `xlsx`가 하고 글자색만 `exceljs`가 읽는다.

**가져오기가 읽는 값:** 날짜 메모(블록 안 B열의 요일이 아닌 이름), 칸 색(블록 첫 행 팀 앞 칸의 배경색, 5가지 외 색은 무시), 글자색(각 항목 칸의 글자색, 위 규칙으로 파랑·빨강만)도 함께 읽는다.

**화면 변경:** 일정표에서 날짜 칸을 누르면 날짜 메모를 고치고, 칸 창에 이 칸의 글자색 선택(없음·`축전지수거`·`빨강 글자`)과 이 팀·이날의 칸 색 선택(5색 + 없음, 이름이 있는 색은 이름도 표시)을 둔다. 일정표에서도 같은 색이 팀 블록 전체에 연하게 칠해지고 글자색이 글에 적용된다. 일정표 위에 범례를 보여 준다.

### 범례·색 지정(확정, 2026-11-07)

사용자가 보낸 범례 이미지(엑셀 `일정표_New` 1~4행) 기준이다. 색은 **관리자가 앱에서 직접 지정**한다.

| 이름 | 종류 | 색 |
|---|---|---|
| 중장비 | 칸 색(날짜×팀) | 초록 `D9F2D0` |
| 승주 | 칸 색(날짜×팀) | 분홍 `F2CFEE` |
| K대응 | 칸 색(날짜×팀) | 파랑 `4E95D9` |
| 축전지수거 | **글자색**(칸의 글) | 파랑 `0070C0` |
| (이름 없음) | 칸 색 | 빨강 `FF5050`(190칸), 회색 `D1D1D1`(10칸) — 범례에 없어 `빨강 칸`·`회색 칸`으로만 부른다 |
| (이름 없음) | 글자색 | 빨강 `FF0000`(13칸) — `빨강 글자` |

- **글자색은 칸(국소 항목) 하나마다** 정한다. 날짜×팀 칸 색과 달리 그 글만 색이 바뀐다. 파일에서 파랑 계열 세 가지(`0070C0`·`00B0F0`·테마 파랑)는 모두 `축전지수거` 파랑 하나로 합치고, 빨강만 따로 두며, 나머지(기본 검정 등)는 글자색 없음으로 읽는다.
- 일정표 화면에 범례(이름과 색 견본)를 보여 주고, `일정표_New 형식` 파일 맨 위 1~4행에 원본과 같은 범례를 쓴다. 주간·월간 배포 파일에는 범례를 넣지 않는다(원본 인쇄 영역에도 없다).
- 글자색을 읽으려면 `exceljs`가 필요하다. `xlsx`(SheetJS 무료판)는 글자색을 읽지 못한다(확인함). 그래서 `exceljs`를 쓰기와 글자색 읽기에 함께 쓰고, 시트·행·배경색은 지금처럼 `xlsx`가 읽는다.

### 월간 달력(확정, 2026-11-07)

월간 보기는 **월 달력(월~일 7열 격자)** 이다. 주간 배포와 같은 월요일 시작이다.

- **앱:** 일정표 창에서 `주간`·`월간`을 전환한다. 월간은 조회 전용이고, 날짜를 누르면 그 날짜의 주간 보기로 가서 거기서 수정한다. 달력에는 이전·다음 달 날짜가 섞이며(흐리게 표시), 달에 따라 4~6주다.
- **날짜 칸:** 날짜 숫자와 날짜 메모, 그 아래 일정이 있는 팀마다 한 줄 `팀 · 국소1 (모국1), 국소2`. 칸 색은 줄 앞 네모, 글자색은 항목 글자색으로 보인다. 줄이 많으면 앱은 6줄까지 보이고 `외 N팀`으로 줄인다.
- **월간 배포용 엑셀:** 한 달 한 쪽, 달력 격자, 칸 색·글자색·날짜 메모를 반영한다. 칸 안 글은 줄바꿈을 허용해(엑셀) 모두 보이고, 행 높이는 줄 수로 계산한다. 용지는 A3/A4 가로.

### 칸 창 보강(확정, 2026-11-07)

- **팀·날짜 목록 편집(변경, 2026-11-07):** 칸을 열면 클릭한 칸 하나가 아니라 **그 팀·날짜의 모든 국소가 한 목록**으로 보인다(행 번호, 국소·작업, 모국·장비·메모, 글자색 바꾸기, ×로 빼기). 목록에서 글을 고치고, ×로 빼고, **국소 검색해서 추가**(등록된 장비 국소의 국소명·주소·별칭을 검색, 클릭하면 목록에 항목으로 추가되고 이어서 여러 개 고를 수 있다) 또는 **빈 항목 추가**·입력창 Enter로 직접 입력해 추가한다. 저장하면 한 번에 반영된다: 빠진 항목은 삭제, 바뀐 항목만 수정, 새 항목은 마지막 항목 아래의 빈 행에 차례로 기록(엑셀처럼). 처음 사용자가 "여러 국소를 등록했는데 다시 열면 한 국소만 보여 고치기 어렵다"고 해서 칸 하나씩 고치던 방식에서 바꿨다. 글을 모두 지운 기존 항목은 저장되지 않고 안내한다(지우려면 ×). 날짜·팀 옮기기는 처음 클릭한 일정 하나에만 적용된다.
- **국소 검색(2026-11-07 보강):** 목록의 각 줄 `국소·작업` 입력에 글을 쓰면 그 줄 아래에 등록된 장비 국소 검색 결과가 펼쳐지고, 고르면 그 줄의 국소명이 바뀐다. 아래 `국소 검색해서 추가`도 같은 검색을 쓴다. 검색 대상은 **국소명·통합시설코드·프로젝트코드**·주소·별칭이고, 국소명 시작·포함 일치 → 코드 일치 → 주소·별칭 일치 순으로 보여 준다(공백·대소문자 무시, 코드는 일부만 입력해도 된다). 결과에는 주소와 통합시설코드·프로젝트코드가 함께 나온다. 코드는 마커가 가진 대표 정보 행의 값 하나씩이라, 한 국소의 다른 정보 행 코드로는 찾지 못한다. 줄 입력의 검색 결과도 **여러 개 선택**이 된다: 결과에서 고르면 체크가 켜지고 목록은 열려 있으며, 첫 번째는 검색하던 줄에, 이어서 고른 국소는 바로 아래 줄에 차례로 들어가고, 다시 누르면 선택이 풀린다(원래 목록에 있던 국소는 눌러도 바뀌지 않는다).
- **입회·신호수 체크:** 칸 창에 `입회`·`신호수` 체크박스와 이름 입력을 둔다. 체크하면 엑셀과 같이 **같은 팀·날짜의 아래 빈 행에 별도 칸**(`입회 : 이름`, `신호수 : 이름`, 국소 칸은 비어 있음)이 만들어진다. 이미 있으면 체크된 상태로 보이고, 이름을 고치면 그 칸이 수정되며, 체크를 풀면 그 칸이 삭제된다. `모국·장비·메모` 입력은 그대로 둔다(모국·장비 입력이 계속 필요해서). 입회·신호수 칸 자체를 고칠 때는 체크 영역을 숨기고 뒤 칸 글을 직접 고친다.
- **날짜 블록 10행:** 주간 보기도 엑셀처럼 날짜마다 최소 10행을 보인다.

### 대시보드 연동(확정, 2026-11-07)

오늘 날짜 시설일정의 국소를 대시보드의 **오늘의 작업 국소**(날씨 판정 보드)에 자동으로 담는다(사용자 선택: 자동 등록).

- **대상:** 오늘 일정 칸의 `국소·작업` 글만(입회·신호수·장비 줄은 제외). 장비 국소명·이름·별칭과 공백·하이픈·대소문자를 무시하고 같으면 연결한다. 이름이 다르거나 좌표가 없으면 제외하고 안내에 건수를 보인다. SUB 국소는 대표 마커의 id·좌표·주소로 연결한다(지도에는 대표만 있다).
- **표시:** 자동 등록한 국소에는 등록 날짜(`SiteMatch.scheduleDate`)를 달고 목록에 `일정` 배지를 붙인다. 직접 담은 국소는 건드리지 않고 중복해서 넣지 않는다.
- **날짜가 바뀌면:** 지난 날짜로 자동 등록된 국소는 오늘 일정에 없으면 뺀다(있으면 오늘 날짜로 유지). 직접 담은 국소는 유지한다.
- **직접 뺀 국소 존중:** 같은 날 사용자가 `×`나 전체 삭제로 뺀 국소는 다시 넣지 않는다(그날 넣어 본 국소 id를 저장소에 기록, `scheduleSync`). 일정에 새 국소가 생기면 그것만 추가한다.
- **마커창 자동 펼침·지도 맞춤(사용자 요청):** 대시보드를 열면 오늘의 작업 국소 **전체의 마커창(날씨 카드)을 지도에 자동으로 펼치고**, 지도를 작업 국소가 모두 한 화면에 들어오게 자동으로 맞춘다(가장자리 여백 120px, 한 곳이면 확대해 이동). 새로 담긴 국소(시설일정 자동 등록 등)는 열린 뒤에도 이어서 펼친다. 사용자가 직접 닫았거나 `마커창 전체 숨김`으로 끈 국소는 대시보드가 열려 있는 동안 다시 펼치지 않는다(대시보드를 다시 열면 처음부터). 목록의 행을 누르면 지금처럼 그 국소의 마커창만 보인다. 구현: `planAutoOpen`(순수 함수) + `useAutoOpenWorksites` 훅 + 저장소 `mapFitRequest` 요청을 지도 캔버스가 처리. **수정(같은 날):** 처음 구현에서는 마커창이 안 펼쳐졌다. 원인은 (1) 지도 캔버스의 마커 그리기 효과가 `filters`·`isMarkersVisible`·`isClusteringEnabled`가 바뀔 때 열린 마커창을 모두 닫는데 마커창 효과는 이 값들을 감시하지 않아 다시 열지 않던 기존 결함, (2) 대시보드가 첫 행만 단독 선택하던 효과와 전체 펼침이 충돌해 개발 모드(Strict Mode)의 효과 이중 실행 때 선택이 한 국소로 줄던 문제다. 마커창 효과가 같은 값을 감시하게 하고, 첫 행 단독 선택 효과를 없앴으며, 펼친 선택이 곧바로 되돌려지면 한 번 다시 적용한다.
- **마커창 겹침 방지·가장자리 열 배치(사용자 요청, 2026-11-07):** 같은 자리에 핀이 몰린 국소들은 마커창이 한 곳에 쌓여 수정할 수 없었다. 처음에는 핀 둘레의 빈자리로 흩었으나 사용자가 원한 모양은 **지도 양쪽 가장자리에 카드를 세로로 쌓고 연결선으로 핀과 잇는 보드 형태**였다. 그래서 지도가 자리 잡은(`idle`) 뒤 핀이 화면 왼쪽 절반이면 왼쪽 열, 오른쪽 절반이면 오른쪽 열에 **핀이 위에 있는 순서로 위에서 아래로** 쌓는다. **통일감(사용자 요청):** 카드는 핀 높이를 따라 흩어지지 않고, 양쪽 열이 같은 높이(위 여백 52px)에서 시작해 모든 카드를 같은 칸 높이(가장 큰 카드 기준)·같은 간격(16px)으로 쌓는다. 오른쪽 열은 지도 컨트롤(줌·위치 버튼)을 가리지 않도록 오른쪽 끝에서 72px 안쪽에 둔다. 한쪽에 몰려 열이 늘어나면 가운데에 가까운 국소를 반대쪽으로 나눠 담고, 그래도 한 열에 안 들어가면 **카드를 줄여서**(최대 70%까지, `data-panel-scale` + CSS `scale`) 가운데가 아니라 양쪽 가장자리 열에만 둔다. 줄여도 모자랄 때만 안쪽에 열을 더한다. 자동 배치한 정보창은 연결선 간격을 36px로 고정한다(기존 간격 규칙은 오프셋에 따라 16↔36으로 바뀌어 경계에서 위치가 20px 튀고 카드가 겹쳤다). 지도를 맞출 때도 좌우에 카드 열이 들어갈 여백(`boardFitPadding`: 좌우 412px·상하 90px)을 두어 핀이 가운데 모이게 한다. 계산은 순수 함수 `arrangeOverlayPanels`(`overlay-arrange.ts`, 핀 화면 좌표·패널 크기 → 패널 오프셋)이고 `syncOverlayLeader`와 같은 식으로 오프셋↔위치를 바꾼다. 패널 크기는 실제로 잰 값과 최소 340×270 중 큰 값을 쓴다. 사용자가 **직접 끌어 옮긴 마커창은 건드리지 않는다**(그 창과 겹칠 수는 있다). 배치는 대시보드가 열릴 때와 `마커창 전체 표시`를 누를 때(`requestMapFit(ids, { arrange: true })`) 하고, **대시보드가 떠 있는 동안에는 지도를 확대·축소·이동해 멈출 때(`idle`)마다 다시 배치한다**(`overlayBoardActive`, 정보창이 핀에 붙어 있어 다시 배치하지 않으면 확대·축소 때 핀을 따라 흩어졌다). 결과가 그대로면 정보창을 다시 그리지 않는다. 대시보드를 닫으면 꺼지므로 평소 지도 사용에는 영향이 없다. 한계: 카드를 70%로 줄여도 한쪽 열 둘(대략 국소 14~16개 이상)을 넘으면 안쪽 열이 핀을 가리거나 겹칠 수 있다.
- **안전장치:** 일정 조회가 성공한 뒤에만 목록을 바꾼다. 오류·테이블 없음·로그인 전에는 기존 목록을 건드리지 않는다. 대시보드가 열려 있을 때 동작하고, 목록은 각자 브라우저(localStorage)에 저장된다.
- **안내:** 대시보드(빈 상태·목록 모두)에 `오늘 시설일정 국소 N개 중 M개가 등록된 장비 국소와 일치해 작업 국소에 담깁니다` 한 줄을 보인다. 일정을 입력할 때 `국소 검색해서 추가`로 고르면 이름이 정확히 같아 자동 등록된다.

### 14.2 근거 자료(직접 열어 확인)

- **상세 시트:** 머리글 24열(2행), 국소 한 건이 한 행. 1행은 빈 줄(높이 26), 머리글 높이 42, 데이터 높이 약 25. 머리글은 굵게·가운데·연한 청회색(테마 3, 밝기 +0.9)이고 **X열(작업내용 상세)만 연한 초록**, 글꼴 뫼비우스 Regular, 틀 고정 9열×2행. 파일의 작은 문제: 작업일이 날짜가 아니라 일련번호(46335)로 들어 있다. 머리글에 `작업구분`이 두 번(G, S) 나온다.
- **`261109_시설일정_수정2.xlsx`:** 시트 3개(`일정표_Old` 숨김, `일정표_New`, `2026-11-09`). `일정표_New`는 앱의 가져오기 로직으로 오류 없이 읽힌다(189일, 2026-06-29 ~ 2027-01-03, 칸 2,319건, 날짜 메모 62, 칸 색 195). 웹 DB에는 지금 일정이 15건뿐(11/07 3팀 7건, 11/09 1팀·4팀 8건)이다. 11/09를 상세 시트와 대조하면 일정표의 5팀 칸에는 CDU 4건의 국소명 없이 `여수봉산 · 트레이고정` 요약만 있고, 입회자·신호수 이름이 없다 — **상세표를 일정에서 만들려면 일정에 국소명과 이름이 먼저 들어 있어야 한다.**
- **참조 저장소 `New_Automation_Tools`**(비공개, Electron 툴)에 이 상세 시트를 만드는 도구가 이미 있다. 코드는 가져오지 않고 검증된 규칙만 따른다(14.3, 14.4).
- **웹 DB:** 공정관리 원본 열 이름이 `erp_details.raw`에 그대로 들어 있다(`방식`·`세부사업 유형`·`사업 구분`·`국소명-최종`·`주소(전체)`·`모국 (&기지국)`·`부동산 형태`·`장비위치` 등). 다만 `erp_details`는 마커가 있는 712행뿐이고 11/09의 9건이 하나도 없다. 마커·정보와는 9건 중 6건이 일치한다(5G AAU 3건 없음). 웹에는 공정관리 머리글 이름으로 읽는 파서(`erp-parse.ts`)가 이미 있다.

### 14.3 행을 만드는 규칙(참조 도구와 같다)

1. 그날 일정표에서 **팀 대표 열**(1팀~7팀·6팀·시험팀·실사&재하도급, 비고 제외)의 국소명을 모은다. 국소명이 비어 있는 칸(입회·신호수·메모)은 행이 되지 않는다.
2. 이름을 공백 제거·소문자로 비교해 **같은 국소는 한 행**으로 합친다(강광고속장암 F2·F1은 1팀·4팀에 모두 있지만 상세에서는 2행). 순서는 처음 나온 위치(팀 열 순서 → 행 순서)다.
3. **작업자 = 그 국소를 맡은 모든 팀의 팀장 이름을 쉼표로 이은 값**(`박경훈,이동화`). 행에서 고칠 수 있다.
4. **입회자·신호수 = 같은 규칙**으로, 그 국소를 맡은 팀들의 `입회 : 이름`·`신호수 : 이름` 칸의 이름을 모아 쉼표로 잇는다(참조 도구는 비워 뒀지만 웹에는 이 칸이 있다).

### 14.5 저장(마이그레이션, 사용자가 적용)

- **`schedule_day_details`:** (작업일, 정규화한 국소명)별 사용자 입력 — 작업구분(G)·작업구분(S)·작업시간·작업유형·중장비투입·작업내용·작업내용 상세, 작업자·입회자·신호수의 직접 수정값, 자동 열의 덮어쓴 값. 팀을 옮기거나 칸을 맞바꿔도 상세가 그대로 남고, 같은 국소 행을 여러 팀이 공유한다.
- **`schedule_option_lists`:** 드롭다운 목록(목록 이름, 값, 순서). 처음 값은 `C:/Users/celyo/OneDrive/Desktop/통합 문서1.xlsx`의 `List` 시트(사업분류 13·사업유형 6·공사유형 5·작업구분 12·작업유형 9·중장비투입 17·작업내용 7)에 `작업시간`(주간·야간)을 더해 채운다. 값은 **추가·삭제할 수 있고**, 입력하면서 `목록에 추가`도 누를 수 있다. 목록에서 지워도 이미 쓰인 상세의 값은 보존한다. 중장비투입은 `이동식크레인,굴착기`처럼 **여러 장비를 쉼표로 이은 조합이 항목 하나**다.
- 조회는 로그인 사용자, 쓰기는 관리자(`is_app_admin()`) — 일정 테이블과 같은 정책이다.
- **엑셀 가져오기(`replace_schedule_cells`)는 일정 칸을 지워도 상세는 지우지 않는다**(상세가 칸이 아니라 (날짜, 국소)에 묶이기 때문). 일정을 다시 가져와도 입력한 상세가 남는다.

### 14.6 화면

- 시설일정 헤더의 보기 전환을 `주간 | 월간 | 일자별 | 누적`으로 늘린다(`누적`은 14.12). 일자별은 날짜 선택(기본 내일)·이전 날·다음 날·`내일` 버튼과 **그날의 24열 표 한 장**이다.
- 표 규칙(프로젝트 공통): 셀 줄바꿈 금지, 가로 스크롤 금지(24열이 한 화면에 들어가게 열 폭을 줄이고 긴 값은 말줄임 + 마우스를 올리면 전체), 세로 스크롤만 허용.
- 행을 누르면 **작업 상세 창**이 열려 직접 입력 열과 자동 열의 덮어쓰기를 고친다. 여러 행을 체크해 **같은 값을 한꺼번에 적용**할 수 있다(같은 현장의 행들이 거의 같은 값이고, 작업시간을 한 번에 `야간`으로 바꾸는 데도 쓴다).
- 참조에서 못 찾은 국소는 표 위에 `공정관리 정보가 없는 국소 N건`으로 알리고 해당 칸을 눈에 띄게 한다.
- 관리자가 아니면 읽기 전용이다. `목록 관리`는 관리자 전용이다.

### 14.7 표 복사 · 엑셀 내려받기

- **표 복사:** 24열 데이터를 **제목 줄 없이** 탭으로 구분해 클립보드에 복사한다. 원본 엑셀의 날짜 시트 데이터 행에 그대로 붙여넣는다. 작업일은 `yyyy-mm-dd`(엑셀이 날짜로 읽는다), 빈 값은 빈칸이다.
- **엑셀 내려받기:** 고른 날짜의 시트 하나를 가진 `.xlsx`. **제목 줄(머리글)이 있다**(14.2의 서식 그대로: 1행 빈 줄, 2행 머리글, 색, 글꼴, 틀 고정 9×2, 열 폭, 행 높이, 테두리, 작업일 날짜 서식). 시트 이름은 `yyyy-mm-dd`, 파일 이름은 `yymmdd_시설일정_상세.xlsx`(고른 날짜). T·U·V·W(와 D·E·F·G)에는 드롭다운을 건다. 중장비투입 값에 쉼표가 있어 엑셀의 쉼표 목록 방식을 쓸 수 없으므로 **숨김 시트에 목록을 적어 그 범위를 참조**한다. `exceljs`는 내려받기를 누를 때만 불러 첫 화면 번들을 늘리지 않는다.

### 14.8 이번 범위 밖

- `.xlsb` 읽기, 공정관리 붙여넣기 칸(공정관리는 `위치등록` 업로드로 DB에 넣는다. 필요해지면 나중에 더한다), 만들어 둔 상세 시트를 읽어 들이는 기능, 여러 날짜를 한 파일에 담는 내려받기, 작업시간·작업유형 등의 자동 추정, `일정표_New` 내보내기 변경.

### 14.12 누적 관리(2026-11-07 추가 — 만든 상세를 쌓아 두고 나중에 참조해 가져온다)

참조 도구의 `List` 시트와 같은 역할이다. 도구는 메일을 만들 때 그날 시트의 B~X열을 `List`에 쌓고 작업일 내림차순으로 정렬하며, 다음에 같은 국소가 나오면 공정관리에 없을 때 `List`에서 값을 찾는다(`C D E F H J L M Q R` 열). 웹에도 같은 쌓기·찾기를 둔다.

- **저장:** 새 테이블 `schedule_archive_rows`. (작업일, 정규화한 국소명)마다 **그날 상세표 한 행의 24열 값을 그대로 복사해** 저장한다(저장한 시각·저장한 사람 포함). 일정표를 다시 올려 일정이 지워지거나 공정관리 값이 바뀌어도 **만든 당시의 값이 남는다.** 같은 날짜를 다시 저장하면 그날 행을 새 값으로 바꾼다.
- **언제 쌓나(제안):** ① 일자별 화면의 `누적 저장` 버튼, ② `표 복사`와 `엑셀 내려받기`를 누를 때 자동으로. 둘 다 같은 저장 기능을 쓴다. 복사·내려받기는 상세표를 "완성해 가져가는" 마지막 동작이라 자동으로 쌓는 것이 도구의 메일 작성 때 누적과 같다.
- **누적 보기:** 헤더 보기 전환의 `누적`. 쌓인 행을 **작업일 내림차순**(최근 날짜 먼저)으로 24열 표에 보이고, 기간·국소명·프로젝트·통합시설코드로 거른다. 거른 결과를 **표 복사**(제목 줄 없이)하거나 **엑셀로 내려받을** 수 있다(제목 줄 포함, 시트 이름 `List`, 일자별 내려받기와 같은 서식). 관리자는 잘못 쌓은 행을 지울 수 있다.
- **참조해서 가져오기 두 가지:**
  1. **이전 입력 불러오기:** 일자별 표의 행(또는 체크한 여러 행)에서 버튼을 누르면 **같은 국소의 가장 최근 누적 행**에서 작업시간·작업유형·중장비투입·작업내용·작업내용 상세를 가져와 채운다(자동으로 덮어쓰지 않고 누른 행만).
  2. **공정관리에 없는 국소의 자동 열 채우기:** 공정관리(DB)에서 못 찾은 국소는 **누적의 가장 최근 행**에서 통합시설코드·사업분류·사업유형·공사유형·지역·장비타입·주소·모국·부동산형태·장비위치를 가져온다(도구와 같은 열이며 프로젝트 열은 도구가 가져오지 않아 같게 뺀다). 예: 11/09의 5G AAU 3건처럼 공정관리에 없는 국소의 값을 한 번 직접 입력해 누적에 쌓아 두면, 같은 국소가 다시 나올 때 자동으로 채워진다.
- 찾는 순서는 공정관리(DB) → 누적 → 마커·정보 → 빈칸이다. 모두 못 찾으면 추측하지 않고 비운다.

**확인이 필요한 것**

1. **누적에 쌓는 시점:** 위 제안(`누적 저장` 버튼 + `표 복사`·`엑셀 내려받기`를 누를 때 자동)으로 괜찮은지. 자동이 부담스러우면 버튼으로만 쌓는다.
2. **누적의 쓰임:** 위 두 가지(이전 입력 불러오기, 공정관리에 없는 국소의 자동 열 채우기)와 누적 보기(검색·복사·내려받기)면 충분한지.


## 15. Supabase 일시정지 방지 (Keep-Alive 워크플로, 2026-11-07 결정)

Supabase 무료 플랜은 7일 동안 웹 접속이나 DB 쿼리가 없으면 프로젝트가 자동으로 일시정지(Pausing)된다. 명절이나 장기 미사용 등으로 인한 중단을 방지하기 위해 매주 일요일 00:00(KST)에 자동으로 DB에 가벼운 쿼리(Keep-Alive 핑)를 전달하는 워크플로를 구축한다.

- **접근 방식:** GitHub Actions 스케줄러(Cron) 활용 (Cloudflare 빌드 영향 없음, 무료, GitHub UI에서 동작 확인 가능).
- **스케줄:** 매주 토요일 15:00 UTC = **매주 일요일 00:00 KST** (`cron: '0 15 * * 6'`).
- **수동 실행 지원:** `workflow_dispatch`를 포함하여 GitHub Actions 탭에서 언제든 [Run workflow]로 즉시 테스트 실행 가능.
- **동작 내용:** Supabase REST API(`$NEXT_PUBLIC_SUPABASE_URL/rest/v1/`)로 익명 키(`NEXT_PUBLIC_SUPABASE_ANON_KEY`)를 사용해 가벼운 요청(루트 스펙/헬스체크 쿼리)을 1회 호출하여 서버 활성 상태를 갱신.
- **파일 위치:** `.github/workflows/supabase-keepalive.yml`
