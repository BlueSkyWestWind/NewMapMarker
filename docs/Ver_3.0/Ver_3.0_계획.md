# MapMarker Ver 3.0 계획서

작성일: 2026-11-05  
상태: 결정 사항 정리 완료, 검토 대기 — 검토 후 구현 문서를 만들어 한 번에 구현한다

## 1. 목적과 범위

지도 탭의 핵심 업무를 개선한다. 장비·축전지·위치/좌표는 유지하고, 위치는 기존 장비 국소를 목적별로 모아 보여주는 목록 중심 메뉴로 변경한다. 장비는 현재 연도의 시설 진행 상태를 색상과 필터로 표시한다. 업로드 엑셀과 데이터베이스도 함께 정비한다.

카카오와 네이버 지도 비교·전환은 별도 검토 사항이며 이번 계획에서 지도 제공자를 결정하지 않는다.

## 2. 위치 메뉴: 국소 목록

- 사용자가 `철거대상`, `고속도로`처럼 목록 이름을 만들고 색상을 지정한다.
- 기존 장비 국소를 국소명, 사업코드·프로젝트코드·통합시설코드, 주소로 검색해 목록에 등록한다. 실제 검색 열은 데이터 구조와 대조한다.
- 한 국소를 여러 목록에 등록할 수 있다. 여러 국소를 함께 선택해 추가하는 방안을 적용한다.
- 하나 또는 여러 목록을 선택하면 해당 국소만 지도와 목록에 표시한다. 같은 국소가 여러 목록에 있어도 마커는 하나다.
- 마커에 선택된 목록의 색상을 최대 3개와 나머지 목록 수(`+2` 등)로 표시한다. 상세 정보에서 전체 소속 목록을 확인한다.
- 목록에서 국소를 제외해도 기존 장비 국소는 삭제하지 않는다. 목록과 소속 정보는 여러 사용자가 다시 볼 수 있도록 저장한다.

### 권한

| 목록 | 조회 | 이름·색상 수정, 국소 추가·제외, 목록 삭제 |
|---|---|---|
| 관리자가 생성 | 로그인 사용자 | 관리자만 |
| 일반 사용자가 생성 | 로그인 사용자 | 모든 로그인 사용자 |

관리자 판별을 신뢰할 수 있는 서버 측 정보로 처리하고 DB 권한 정책으로도 보호한다. 현재 코드와 마이그레이션에는 관리자 구분이 없고 로그인 사용자의 권한이 모두 같다(2026-11-06 확인).

**관리자 판별(확정, 2026-11-06):** DB에 관리자 테이블을 새로 두고 권한 정책이 이 테이블을 확인한다. 추가·제외는 SQL로 하고 바로 적용된다. 일반 사용자는 이 테이블을 수정할 수 없게 한다. 저장소가 공개 상태이므로 관리자 이메일은 마이그레이션과 문서에 적지 않고, 사용자가 SQL Editor에서 별도로 등록한다. 첫 관리자는 사용자가 지정한 계정 1개다.

### 기존 임시 마커 기능 이동(확정, 2026-11-06)

위치 메뉴의 `엑셀로 위치 찍기`와 `주소로 위치 찍기`를 대시보드 작업 등록으로 옮기고, 위치 메뉴에는 국소 목록만 남긴다. 두 기능은 이미 임시 마커를 오늘의 작업 국소에 함께 등록하므로 동작은 바꾸지 않고 위치만 옮긴다.

코드에서 확인한 수정 지점:

- **대시보드 화면:** `dashboard-panel.tsx`는 작업 국소가 없을 때 별도 화면을 반환한다. 옮긴 기능은 **작업 국소가 없을 때와 있을 때의 두 화면 모두**에 넣는다. 경로 탭에는 넣지 않는다.
- **빈 화면 안내:** "위치 탭에서 엑셀·주소로 위치를 등록" 문구와 `지도로 이동` 버튼의 위치 메뉴 이동을 새 흐름에 맞게 고친다.
- **지도 표시:** 위치 모드는 지금 임시 마커만 보여 주므로(`select-active-markers.ts`) 선택한 목록의 국소를 보여 주도록 바꾼다. 대시보드는 이미 작업 등록한 임시 마커를 지도에 표시한다.
- **건수 표시:** `app-shell.tsx`의 `위치 N건 · 임시`와 `work-panel.tsx`의 `위치 N건`을 목록 기준으로 고친다.
- **경로 기능:** 임시 마커를 스토어에서 읽으므로 스토어를 유지하면 영향이 없다. 구현 후 경로 후보에 임시 마커가 나오는지 확인한다.

구현 때 확인할 사항:

- **업로드 대상:** 대시보드는 `weather` 모드라 스토어의 저장 위치가 장비 임시 마커 쪽으로 잡힌다(`getPendingKey`). 옮긴 뒤에도 임시 마커가 위치 쪽에 저장되는지 확인한다.
- **임시 마커 제거:** 지금은 위치 메뉴의 `등록 위치` 목록에서 관리한다. 대시보드에서 작업 국소를 제거해도 임시 마커는 스토어에 남으므로 경로 후보에 계속 나올 수 있다. 제안은 작업 국소를 제거할 때 해당 임시 마커도 함께 제거하는 것이다(확인 필요).

## 3. 장비 시설 상태

현재 연도 사업 장비만 사용해 국소별 대표 상태를 판정한다. 예를 들어 2026년에는 2025년 장비를 제외하고 2026년 장비 전체를 확인한다.

| 조건 | 상태 | 지도 색상 |
|---|---|---|
| 올해 장비 중 하나라도 시설일이 없음 | 미시설 | 에메랄드 |
| 미시설은 없고 개통완료되지 않은 장비가 하나라도 있음 | 시설 | 회색 |
| 올해 장비가 모두 시설 및 개통완료 | 개통완료 | 흰색 |
| 올해 장비가 없음 | 올해 대상 없음 | 기존에 저장된 색상 |

상태 필터를 추가한다. 시설일이 없으나 개통일이 있는 예외 데이터는 미시설로 표시하는 방안이다.

**처음 화면(확정, 2026-11-06):** 해당 연도의 국소만 나오고 개통완료 국소는 보이지 않는다. 즉 처음에는 올해의 미시설·시설 국소만 표시한다. 개통완료 국소는 상태 필터에서 `개통완료`나 `전체`를 고르면 나타난다.

**필터 형태(제안, 확인 필요):** 기존 필터와 같은 복수 선택 드롭다운으로 만들고 값은 `미시설`·`시설`·`개통완료`·`올해 대상 없음`이다. 기본 선택은 `미시설`·`시설`이고, 모두 선택하면 버튼에 `전체`로 표시한다.

필터 동작(2026-11-06 사용자 답변 기준):

- 올해 장비가 없는 국소는 `미시설`·`시설`·`개통완료` 필터에 나오지 않는다. 해당하는 국소가 없으면 없는 대로 비어 있게 둔다.
- `전체`를 고르면 그 조건으로 걸러내지 않고 전체를 보여 준다. 올해 장비가 없는 국소는 기존 저장 색상으로 표시한다.
- 상태 필터와 연도 필터는 각각 독립적으로 적용한다. 어느 한쪽이 다른 쪽의 선택을 덮어쓰지 않는다.

향후 연도별 상태 판정이 가능하도록 기준 연도를 분리한다.

**대표/SUB 집계(확정, 2026-11-06):** 대표 마커는 자기 장비와 숨은 SUB의 올해 장비를 합쳐 판정한다. 개별 표시(`detachedVisible`)로 지정한 SUB는 자기 장비만으로 판정한다. 대표 장비가 개통완료여도 숨은 SUB가 미시설이면 대표 마커는 미시설로 표시한다.

**연도 필터(제안에 이의 없음, 2026-11-06):** 현재 연도 필터는 마커의 상세 정보 첫 행의 연도만 본다. 그래서 대표가 2025년이고 SUB가 2026년인 국소는 올해 필터에서 빠진다. 그룹 안의 장비 중 하나라도 선택한 연도에 해당하면 통과하도록 바꾼다.

**연도 기본값:** 커밋 전 코드의 `올해 + 미지정` 선택은 유지한다. 연도 미지정 국소는 상태가 `올해 대상 없음`이라 처음 화면에는 나오지 않으며, 상태 필터에서 `올해 대상 없음`이나 `전체`를 고르면 나타난다. 올해 마커가 하나도 없을 때 연도를 전체 선택하는 동작은 처음 화면이 어차피 비므로 제거한다.

**색상 필터(확정, 2026-11-06):** 지도에 보이는 색을 기준으로 거른다. 지도·필터·클러스터·캡처가 같은 표시색을 쓰고, DB의 저장 색상은 바꾸지 않는다.

**색상 겹침(제안, 확인 필요):** 기본 저장 색상 `#10b981`이 미시설 에메랄드와 같아, `전체`에서 올해 대상이 없는 국소가 미시설처럼 보일 수 있다. 색상을 따로 바꾸지 않고, 구분이 필요하면 상태 필터를 쓰는 방안이다. 회색 `#64748b`는 마커 색상 선택지에 없어 저장 색상으로는 드물다.

**마커 색상 5개 추가(사용자 요청, 2026-11-06):** 현재 10개인 마커 색상 선택지를 15개로 늘린다. 아래 색상과 적용 범위는 제안이며 확인이 필요하다.

- **고른 기준:** 기존 선택지, 상태색(에메랄드·회색·흰색), 임시 마커 빨강(`#ef4444`), 대기 마커 골드(`#f59e0b`)와 겹치지 않는 색이다.
- **수정 지점:** `marker-edit-modal.tsx`의 `COLOR_OPTIONS`, `facility-teams.ts`의 `LEGACY_COLOR_NAMES`·`COLOR_NAME_ALIASES`·`COLOR_FILTER_ORDER`. 이름 표를 함께 고쳐야 백업·복원에서 색상 이름이 유지된다.

- **재업로드 초기화:** 공정관리 파일을 다시 올리면 기존 마커의 색상·메모·태그·담당팀이 기본값으로 덮어써지는 것으로 보인다. 이 네 값을 보존하도록 고친 뒤에 운영 데이터를 다시 올린다.

상태색은 표시용으로 적용하고 기존 저장 색상을 보존하는 방안이다. 흰색 마커의 배경 대비, 기존 색상 필터·클러스터·캡처와의 일관성을 검증한다.

## 4. 데이터베이스

- 국소 목록, 색상, 생성자·관리자 목록 구분, 목록과 국소의 연결을 저장하는 구조를 설계한다. 동일 목록에 같은 국소가 중복 저장되지 않도록 한다.
- 로그인 사용자의 조회와 일반 목록 공동 편집, 관리자 목록 보호를 DB 정책으로 검증한다. 목록에서 제거하거나 목록을 삭제해도 원본 장비가 삭제되지 않게 한다.
- 저장소의 장비 상세 `information`에는 이미 `facility_year`, `install_date`, `open_date`가 있다. 현재 코드가 대표 정보 한 건을 지도 모델에 사용하는 만큼, 모든 올해 장비를 판정에 활용하도록 조회 구조를 검토한다.
- `open_date`는 현재 화면에서 개통일로 사용된다. 이것이 업무상 시험완료·개통완료와 같은 의미인지와 운영 DB의 실제 열·값을 먼저 확인한다. 의미가 같으면 기존 필드 재사용을 우선 검토하고, 다르면 필요한 필드를 별도 설계한다. 신규 필드 추가는 확정되지 않았다.
- Supabase 스키마와 권한 변경은 마이그레이션 SQL로 준비한다. 프로젝트 규칙에 따라 사용자가 적용한다. 기존 데이터 보존, 적용 순서와 복구 방법을 함께 정리한다.

### 위치 목록 저장 구조(제안, 확인 필요)

| 테이블 | 주요 열 | 역할 |
|---|---|---|
| `app_admins` | `user_id`(기본 키) | 관리자 목록. 일반 사용자는 수정할 수 없다 |
| `site_lists` | `id`, `name`, `color`, `is_admin_list`, `created_by`, `created_at`, `updated_at` | 국소 목록 |
| `site_list_members` | `list_id`, `marker_id`, `added_by`, `created_at`, 기본 키 (`list_id`, `marker_id`) | 목록과 국소의 연결. 기본 키로 중복을 막는다 |

- **관리자 목록 구분:** 관리자가 만든 목록은 `is_admin_list = true`다. 권한 정책이 `app_admins`를 확인해 일반 사용자가 이 값을 바꾸거나 관리자 목록을 수정하지 못하게 막는다.
- **마커 참조:** `site_list_members.marker_id`에 `markers`로 향하는 외래 키를 두지 않는다. 마커 삭제나 전체 복원으로 관리자 목록을 포함한 소속이 지워지지 않게 하기 위해서다. 복원 후 같은 ID의 마커가 돌아오면 소속이 그대로 이어진다. 마커가 없는 소속 행은 화면에서 표시하지 않는다.
- **목록 삭제:** `site_list_members.list_id`는 `site_lists`를 `ON DELETE CASCADE`로 참조한다. 목록을 지우면 소속만 지워지고 원본 장비는 남는다.
- **적용:** 마이그레이션 SQL을 사용자가 적용한다. 첫 관리자 등록 SQL은 이메일이 들어가므로 저장소에 넣지 않고 구현 때 따로 전달한다.

## 5. 엑셀 업로드 양식 정비

- 실제 사용 중인 장비 업로드 엑셀을 받아 열 이름·입력 예·코드·날짜 형식과 기존 업로드 종류를 조사한다.
- 국소명, 사업연도, 프로젝트코드, 통합시설코드, 주소, 시설일, 개통일 및 실제 필수 열을 정리한다. 사업코드와 프로젝트코드의 관계도 확인한다.
- 변경할 업로드 양식과 파서를 함께 설계한다. 기존 코드에는 시설일과 개통일 인식 및 업로드 처리가 있으므로 중복 필드를 만들기 전에 사용 의미와 현행 흐름을 대조한다.
- 빈 양식과 작성 예시, 필수·선택 열 설명을 제공하는 방안이다. 기존 파일 호환 여부와 열이 없거나 날짜가 잘못된 경우의 처리는 확정 후 명시한다.
- **옛 양식 처리(확정, 2026-11-06):** 시설일 열이나 개통일 열을 찾지 못하면 저장 전에 업로드를 중단하고 새 양식의 날짜 열을 찾지 못했다고 안내한다. 업로드가 기존 상세 정보를 지우고 다시 넣으므로, 옛 양식을 그대로 받으면 기존 날짜가 사라지고 해당 올해 국소가 모두 미시설로 바뀌기 때문이다. `ACTA 구축완료일`을 날짜로 대신 쓰지 않는다. 열이 있고 일부 행의 값만 비어 있는 경우는 지금처럼 미시설·미개통으로 판정한다.
- **위치 목록의 엑셀 처리(확정, 2026-11-06):** 엑셀 일괄 등록은 이번에 만들지 않고, 검색과 복수 선택으로 등록한다. 목록과 소속은 기존 전체 백업에 포함해 복원 때 함께 되살린다. 목록 데이터가 없는 옛 백업 파일을 복원하면 현재 목록은 건드리지 않는다. 관리자 목록은 관리자가 복원할 때만 되살리고, 일반 사용자의 복원은 권한 정책에 따라 일반 목록만 다룬다.
- 업로드 미리보기·오류 안내·일치하지 않는 국소 및 코드 처리, 대량 업로드를 검증한다.
- 엑셀 내보내기 및 백업·복원에서 필요한 데이터가 사라지지 않는지 확인한다. 목록을 엑셀로 일괄 등록하거나 백업할지는 별도 결정 사항이다.

## 6. 작업 단계와 검증

1. **현황 확인:** 관리자 권한, 운영 DB 스키마, 연도 및 날짜 필드 의미, 실제 엑셀 양식, 대표/SUB 관계를 확인한다.
2. **상세 설계:** 목록 저장·권한과 기존 위치 기능 처리, 상태 및 기존 연도/색상 필터 연동, 엑셀 양식·호환 방침을 확정한다.
3. **장비 상태:** 재업로드 시 색상·메모·태그·담당팀을 보존하도록 고친다. 필요한 DB 변경 및 엑셀 처리를 준비하고 현재 연도 전체 장비의 상태 계산·색상·필터를 구현한다.
4. **위치 목록:** 목록 저장·공유 권한·검색·복수 선택·색상 표시를 구현한다.
5. **로그인 세션:** 로그인 후 7일 만료를 구현한다(9장).
6. **검증:** 혼합 연도, 부분 미시설, 부분 개통, 모두 개통, 올해 대상 없음, 날짜 누락, 대표/SUB, 재업로드 후 값 보존, 목록 중복·권한 우회, 업로드·백업 복원, 흰색 마커 대비, 세션 만료를 확인한다. 타입 검사·린트·단위 테스트·빌드 및 주요 화면 테스트를 수행한다.
7. **적용 준비:** DB 마이그레이션 적용 순서와 복구 방법, 배포 후 점검을 정리한다. 재업로드 보존 수정을 배포한 뒤 새 양식을 운영에 올리는 순서를 포함한다.

## 7. 구현 전 결정 사항

1. 기존 개통일이 시험완료·개통완료와 동일한 의미인지, 운영 DB에 실제로 값이 있는지.
2. 실제 업로드 엑셀 파일과 열 구성, 기존 양식 호환 여부.
3. 관리자 계정 구분 방법과 관리자 목록 권한 정책.
4. 올해 사업연도 기준 필드와 대표/SUB 국소의 장비 집계 범위.
5. 기존 위치 메뉴의 주소·엑셀 임시 마커 기능을 어디에 유지할지.
6. 올해 장비 없는 국소의 개별 상태 필터 처리 및 기존 색상 필터와의 관계.
7. 위치 목록의 엑셀 일괄 등록·백업 필요 여부.

각 항목의 현재 상태는 8장을 따른다. 운영 DB 변경은 아직 수행하지 않았다.

## 8. 진행 현황 (2026-11-06 갱신)

### 엑셀 업로드 양식: 공정관리 시트(`공정_일정관리.xlsb`) 반영 완료

기존 공정관리(ERP) 업로드 경로(`erp-parse.ts`)를 새 양식에 맞췄다. 새 업로드 경로를 만든 것이 아니다.

- **읽는 시트:** `일정관리`. 열 위치는 `프로젝트` A열, `통합시설코드` B열이다. 같은 이름의 열이 뒤에 또 있으면(CG~CM열 사본) 앞쪽 열을 기준으로 한다. 이전에는 뒤쪽 값이 덮어썼다.
- **시설일:** `장비 공사` 열. **개통일:** `시험 완료` 열. 이전에는 둘 다 `ACTA 구축완료일`이었다. 이 대응은 사용자가 확정했다(2026-11-06).
- **날짜 처리:** `3/27/26` 형식을 `yyyy-mm-dd`로 바꾼다. `불필요`·`미확정` 같은 글자는 빈 값으로 처리한다.
- **파일 형식:** 장비 엑셀 업로드가 `.xlsb`도 받는다.
- **양식 변경 대응:** 읽을 열 이름과 시트 이름은 `erp-columns.ts` 한 곳에서만 정한다. `장비설치`·`개통일` 전용 열이 생기면 자동으로 우선 사용한다.
- **현재 파일의 날짜 입력 현황(`일정관리` 시트, 112행):** `장비 공사` 50행, `시험 완료` 2행. 값이 비면 미시설·미개통으로 판정한다.
- **검증:** 단위 테스트(`erp-parse.test.ts`), 타입 검사, 린트 통과. 실제 파일을 앱에서 올려 본 확인은 아직 하지 않았다.

### 결정 사항 갱신

- 2번 결정 사항(실제 업로드 엑셀과 기존 양식 호환)은 확정했다. 실제 파일과 열 구성을 확보했고, 호환 방침은 5장을 따른다.
- 1번 결정 사항(개통일 의미)은 확정했다. 시설일은 `장비 공사`, 개통일(개통완료 판정 기준)은 `시험 완료` 열이다. 운영 DB의 `open_date` 의미와 기존 값은 구현 전에 한 번 더 대조한다.
- 3번 결정 사항(관리자)은 확정했다. 관리자 테이블로 판별한다(2장).
- 4번 결정 사항 중 대표/SUB 집계 범위는 확정했다(3장). 올해 기준 필드는 현재 코드의 `facility_year`를 쓰는 방안이다.
- 5번 결정 사항(임시 마커 기능)은 확정했다. 대시보드 작업 등록으로 옮긴다(2장).
- 6번 결정 사항(상태 필터 처리, 색상 필터와의 관계)은 확정했다(3장).

### 그 밖의 진행 내용

- **연도 필터 기본값(커밋 전):** 기본 선택을 `올해 + 미지정`으로 바꿨고, 버튼에 선택한 연도 이름을 표시한다. 올해 마커가 하나도 없으면 전체를 선택하는 동작은 구현 때 제거한다(3장).
- **구현 방식:** 남은 결정 사항을 정리한 뒤 한 번에 구현한다. 장비 상태를 먼저, 위치 목록을 다음에 진행한다.
- **문서 운영:** Ver 3.0의 계획과 결정은 이 문서에만 추가하고 이전 버전 문서를 모아 둔 `docs/이전버젼/` 폴더는 수정하지 않는다. 코드를 변경할 때는 이 문서를 보고 구현 문서를 `docs/Ver_3.0/`에 만든 뒤 그 문서에 따라 작업한다.

- 7번 결정 사항(위치 목록의 엑셀 처리)은 확정했다(5장).

### 구현 문서 작성 전 확인할 제안

사용자가 다르게 정하지 않으면 아래 제안대로 구현 문서를 작성한다.

- **상태 필터 형태:** 복수 선택 드롭다운, 값 4개, 기본 `미시설`·`시설`(3장).
- **색상 겹침:** 색상을 바꾸지 않고 상태 필터로 구분한다(3장).
- **추가 색상:** 네이비·스카이·옐로·브라운·버건디, 위치 목록도 같은 15색을 쓴다(3장).
- **임시 마커 제거:** 작업 국소를 제거하면 해당 임시 마커도 함께 제거한다(2장).
- **위치 목록 저장 구조:** 소속 테이블에 마커 외래 키를 두지 않는다(4장).
- **전체 복원 권한:** 소속이 마커 삭제의 영향을 받지 않으므로 복원 권한은 지금처럼 유지한다.
- **문서 경로:** `docs/이전버젼/` 이동으로 어긋난 `README.md`와 `AGENTS.md`의 경로를 구현 때 고친다.


## 9. 로그인 세션 유지 기간

현재는 직접 로그아웃하기 전까지 로그인이 계속 유지된다. 로그인 후 7일이 지나면 자동으로 로그아웃되도록 바꾼다(사용자 요청, 2026-11-06). 아직 구현하지 않았다.

- **기준 시각:** 마지막 사용 시점이 아니라 로그인한 시점부터 7일이다(제안에 이의 없음, 2026-11-06). 매일 사용해도 7일이 지나면 다시 로그인한다.
- **시각을 읽는 곳:** 액세스 토큰의 인증 시각(`amr`)을 쓰고, 값이 없으면 `user.last_sign_in_at`을 쓴다. 토큰에 이 값이 있는지는 구현할 때 실제 토큰으로 확인한다.
- **판정 시점:** 앱을 열 때, 세션이 바뀔 때, 만료 시각이 됐을 때, 탭이 다시 보일 때.
- **만료 시 동작:** 해당 기기에서 로그아웃하고 기존 로그인 화면(`AuthGate`)으로 돌아간다.
- **수정 범위:** 판정 함수와 테스트(`src/features/map-marker/lib/session-expiry.ts`)를 새로 만들고 `auth-provider.tsx`에서 호출한다. DB 변경은 없다.
- **보안 범위:** 앱 화면에서 로그아웃시키는 방식이다. 이미 유출된 토큰까지 막으려면 Supabase 대시보드의 세션 시간 제한을 168시간으로 설정해야 하며, 사용 중인 요금제에서 가능한지 확인이 필요하다.
- **배포 직후:** 로그인한 지 7일이 넘은 사용자는 배포 후 앱을 열 때 한 번 로그아웃된다.


## 10. 사이드바 재설계

레일과 패널 구조를 드릴다운 사이드바로 바꾼다(디자인 확정, 2026-11-06). 아직 구현하지 않았다. 참고한 디자인은 MiHCM 디자인 시스템 Main Sidebar의 `variant=drilldown` + `collapsible=icon`이다. 시안은 [MapMarker 사이드바 디자인안](https://claude.ai/artifact/Fb9TsUBGmVwYBxR6yRJ2ov)에 있다.

### 데스크톱·태블릿(768px 이상)

- **레일:** 56px 아이콘 레일. 활성 메뉴는 칸 전체를 채워 표시한다. 메뉴 이름은 툴팁과 패널 제목으로 보여 주며 줄이지 않는다.
- **패널 첫 단계:** 제목, 설명, 검색, 하위 메뉴 목록. 지도는 장비·축전지·위치·위치/좌표, 마커관리는 장비·축전지다. 하위 메뉴가 없는 메뉴는 기존 패널을 바로 보여 준다.
- **패널 상세 단계:** 상위 메뉴 이름, 뒤로, 제목과 기존 패널 내용. 필터는 2×2 그리드로 줄인다.
- **펼친 트리:** 원형 화살표로 256px 트리와 레일을 전환한다. 메뉴 검색, 안내선, 건수 배지를 넣는다.
- **기존 동작 유지:** 비로그인 잠금, `setMapSegment`·`setMode`, 메뉴 표기, 지연 로딩을 그대로 둔다.

### 모바일(768px 미만)

현재는 패널이 `100vw - 56px` 폭으로 지도를 덮고, `isSidebarOpen` 기본값이 `true`라 첫 화면부터 지도가 거의 보이지 않는다(사용자 지적, 2026-11-06). 모바일에는 레일과 트리를 쓰지 않고 아래 구조로 바꾼다.

- **하단 메뉴:** 대시보드, 지도, 마커관리, CCTV, 더보기. 그룹관리, 바코드/QR, 데이터백업/복원, 설정은 더보기에 둔다. 비로그인 숨김 규칙은 그대로 적용한다.
- **하단 시트:** 패널을 지도 위 시트로 바꾼다. 높이는 낮음(제목만), 절반, 전체 세 단계이고 손잡이로 조절한다. 드릴다운과 뒤로는 시트 안에서 동작한다.
- **지도 복귀:** 검색 결과나 목록 항목을 고르면 시트를 낮음으로 내려 지도에서 위치를 바로 보여 준다. 활성 메뉴 탭을 다시 눌러도 내려간다.
- **첫 화면:** 시트를 낮음으로 시작해 지도가 먼저 보이게 한다.
- **예외:** 지도가 없는 바코드/QR은 시트를 전체 높이로 연다.
- **함께 고칠 곳:** `cctv-video-modal.tsx`와 `barcode-lightbox.tsx`가 뷰포트 왼쪽 오프셋으로 데스크톱 폭을 쓰므로 모바일에서는 0으로 처리한다.
- **구현할 때 확인할 것:** 가상 키보드가 올라올 때 시트 위치, 시트 드래그와 지도 제스처 충돌, 노치·홈 바 안전 영역, 시트 안의 필터 드롭다운.

### 구현 방식과 남은 결정

- **구현 방식(제안):** `@mihcm/ui`는 설치하지 않고 기존 Tailwind와 shadcn으로 직접 구현한다. 문서에서 라이선스를 확인하지 못했고, 테마 CSS 충돌과 홈 번들 기준(295 kB) 초과 위험이 있다.
- **트리 모드의 필터 위치(제안):** 하위 메뉴를 누르면 트리 옆에 상세 패널을 연다. 왼쪽 폭이 636px로 현재보다 56px 넓어지며, X로 닫을 수 있다.
- **강조색(미정):** 주황 또는 인디고. 제안은 인디고다.
- **패널의 장소 검색(제안):** 패널에서 빼고 상단 검색바로 일원화한다.

## 11. 위치등록 업로드: 신규 확인 후 저장(확정, 2026-11-06)

공정관리 파일 전체를 한 번에 저장하던 방식을, 행을 나눠 신규 건만 사용자가 위치를 확인한 뒤 저장하는 방식으로 바꾼다. 구현 내용은 `Ver_3.0_위치등록_신규확인_구현.md`를 따른다.

- **업로드 위치:** 공정 파일은 `마커관리 → 장비`의 `위치등록 업로드` 한 곳에서 올린다. 10장의 사이드바에서도 `마커관리 → 장비` 상세 단계에 둔다.
- **`추가항목 업데이트` 제거:** 공정 정보 갱신은 `기존 N건 갱신`이 맡으므로 버튼을 없앤다. information 양식 파일은 더 이상 올릴 수 없다.
- **판단 기준:** 통합시설코드로 신규·기존을 나눈다. 코드가 없는 행은 저장하지 않고 안내한다.
- **주소 없는 행:** 주소가 비었거나 `불필요`·`미확정`인 행은 마커로 등록하지 않는다. `임시_LTE_예비품전환_서부`, `임시_5G_예비품전환_서부`도 불필요 데이터로 확정해 이 규칙으로 제외한다.
- **신규 확인:** 주소 변환만으로는 넓은 부지의 정확한 위치를 알 수 없으므로 신규 건을 모두 직접 확인한다. 좌표가 없는 기존 건도 같은 목록에서 확인한다.
- **저장 시점:** [확인]을 누를 때 건별로 바로 저장한다(B안).
- **주소 대조:** [확인] 때 마커 위치의 주소를 엑셀 주소와 비교한다. 같으면 저장하고 다음 건으로 넘어간다. 다르거나 비교할 수 없으면 두 주소를 보여 주고 사용자가 결정한다.
- **임시 저장:** 확인하지 못한 건과 옮긴 위치를 브라우저에 자동 저장하고 다음 접속 때 복원한다. 같은 브라우저·같은 계정에서만 이어서 할 수 있다.
- **기존 건:** 좌표·메모·태그·색상·담당팀·등록일·주소를 유지한다. 국소명과 공정 정보만 파일 값으로 갱신한다.
- **지도 메뉴 업로드:** 공정관리 시트도 DB에 저장하지 않고 임시 마커로만 표시한다.
- **옛 양식:** 5장의 결정대로 시설일이나 개통일 열이 없으면 저장 전에 중단한다.
