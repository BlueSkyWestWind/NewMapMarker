# Ver 3.0 시설일정 일자별 상세 구현

근거: `Ver_3.0_계획.md` 14장(14.1~14.12), 작업 순서는 `Ver_3.0_시설일정_일자별_구현계획.md`. 상태: **구현 완료, 화면 확인 전** (브랜치 `feat/schedule-day-ui`, 2026-11-08). **`supabase/migrations/20261111000000_schedule_day_details.sql`을 적용해야 화면이 동작한다.** 적용은 사용자가 한다.

## 목적

사용자가 날짜별로 쓰는 **작업 상세표**(`261109_시설일정_수정3.xlsx`의 `2026-11-09` 시트, 24열)를 앱에서 만들고 고치고 복사·내려받는다. 시설일정 헤더의 보기 전환을 `주간 | 월간 | 일자별 | 누적`으로 늘렸다.

- **일자별:** 그날 일정에서 국소 목록이 자동으로 나오고, 공정관리 정보로 자동 열이 채워진다. 사용자는 작업시간·작업유형·중장비투입·작업내용·작업내용 상세 등을 입력한다.
- **누적:** 만든 상세를 쌓아 두었다가 검색·복사·내려받기와 이전 입력·자동 열 참조에 쓴다(참조 도구의 `List` 시트와 같은 역할).

## 순수 함수 규칙

### 행 만들기(14.3)

1. 그날 일정에서 팀 대표 열(`비고`만 제외, 시험팀·실사&재하도급 포함)의 국소명을 모은다. 국소명이 빈 칸(입회·신호수·메모)은 행이 되지 않는다.
2. 공백 제거·소문자로 비교해 같은 국소는 한 행으로 합친다. 순서는 처음 나온 위치(팀 열 순서 → 행 순서).
3. 작업자는 그 국소를 맡은 모든 팀의 팀장 이름을 쉼표로 이은 값, 입회자·신호수는 같은 규칙으로 `입회 : 이름`·`신호수 : 이름` 칸의 이름을 모은 값이다. 행에서 고칠 수 있다.
4. 값 우선순위: 덮어쓴 값(`overrides`) > 참조 값 > 빈칸. 입력 열은 저장한 값 > 기본값(작업구분 `HW`, Level `Level1`, 작업시간 `주간`).

### 24열의 출처와 값 변환(14.4)

| 열 | 출처 | 변환 |
|---|---|---|
| A 순번 | 자동 | 1, 2, … |
| B 프로젝트 · C 통합시설코드 | 공정관리 | 그대로 |
| D 사업분류 | 공정관리 `방식` | 광중계기→중계기, 기지국→기지국, 광분산·인빌딩→인빌딩, 그 밖은 원문 |
| E 사업유형 | 공정관리 `세부사업 유형` | `Legacy`→WCDMA, `-`·`이동전화공통`→빈칸, 5G·LTE·WCDMA 그대로, 그 밖은 원문 |
| F 공사유형 | 공정관리 `사업 구분` | `부대장비증설`→증설, 그 밖은 원문 |
| G 작업구분 · S Level · T 작업시간 | 입력(기본값) | 목록에서 고른다 |
| H 지역 · J 장비타입 · L 주소 · M 모국 · Q 부동산형태 · R 장비위치 | 공정관리 | 주소는 원본 그대로, 모국은 `raw`의 `모국 (&기지국)` |
| I 국소명 · K 작업일 | 일정 | 작업일은 `yyyy-mm-dd` |
| N 작업자 · O 입회자 · P 신호수 | 일정 | 위 3번 |
| U 작업유형 · V 중장비투입 · W 작업내용 · X 상세 | 입력 | 중장비투입은 `이동식크레인,굴착기`처럼 쉼표로 이은 조합이 항목 하나 |

### 참조 층

찾는 순서는 **공정관리(`erp_details`) → 누적 → 마커·정보 → 빈칸**이다. 값이 하나라도 있는 첫 층을 **통째로** 쓰고 층 사이에 열을 섞지 않는다(`mergeRefTiers`). 모두 못 찾으면 추측하지 않고 비운다. 어느 층에서 왔는지(`refSource`)는 행에 남아 `공정관리 정보가 없는 국소 N건` 안내에 쓰인다.

- 공정관리: 일정의 국소명을 `erp_details.station_final`과 비교(`.in()`)해 찾는다. 같은 국소가 여러 행이면 id가 가장 큰(최근 등록) 행.
- 누적: 국소마다 **보고 있는 날보다 앞선** 날짜의 가장 최근 행. 프로젝트 열은 주지 않는다(통합시설코드·사업분류·사업유형·공사유형·지역·장비타입·주소·모국·부동산형태·장비위치).
- 마커·정보: 최종 국소명 일치가 먼저, 다음으로 이름 일치. 프로젝트·통합시설코드·공사유형·장비타입·주소를 준다.

### 표 복사

24열을 **제목 줄 없이** 열은 탭, 행은 줄바꿈(LF)으로 잇는다. 값 안의 탭·줄바꿈은 공백 하나로 바꾼다(쉼표는 그대로). 작업일은 `yyyy-mm-dd`, 빈 값은 빈칸.

### 엑셀 레이아웃

고른 날짜 시트 하나. 1행 빈 줄(높이 26.25), 2행 머리글(높이 42, 굵게·가운데·연한 청회색, X열만 연한 초록), 3행부터 데이터(높이 24.95), 글꼴 뫼비우스 Regular, 틀 고정 9열×2행, 확대 80%, 작업일은 날짜 값(`mm/dd` 서식). D·E·F·G·T·U·V·W열에 드롭다운을 걸고, 쉼표가 든 값이 쪼개지지 않도록 숨김 시트(`목록`)에 목록을 적어 그 범위를 참조한다. 일자별은 시트 이름 `yyyy-mm-dd`·파일 이름 `yymmdd_시설일정_상세.xlsx`, 누적은 시트 이름 `List`·파일 이름 `시설일정_누적_yymmdd.xlsx`다.

## 화면 흐름

**일자별**
- 처음 열면 날짜는 **내일**이다(오늘 + 1일). 공통 날짜 선택기, 이전 날·다음 날, `내일` 버튼으로 바꾼다(과거 날짜 포함).
- 24열 표 한 장. 셀 줄바꿈 금지, 가로 스크롤 금지(열 폭을 줄이고 긴 값은 말줄임 + 툴팁), 세로 스크롤만 허용. 공정관리 값이 아닌(누적·마커·없음) 국소는 표 위에 `공정관리 정보가 없는 국소 N건 (누적 a건 · 마커 b건 · 없음 c건)`으로 알리고, 그 행의 참조 열 칸에는 배경색을 입혀 빈칸도 눈에 띄게 한다.
- `표 복사`·`엑셀 내려받기`: 관리자는 끝난 뒤 그날을 **누적에 자동 저장**한다(저장이 실패해도 복사·내려받기는 그대로). **자동 저장은 오늘과 앞으로의 날짜만** 한다(지난 날짜는 조용히 건너뜀). `누적 저장` 버튼으로도 저장하며, 지난 날짜면 확인 창을 먼저 띄운다. 불러오는 중이거나 실패했거나 국소가 없거나 테이블이 없으면 막힌다. 저장·복사·내려받기는 한 번에 하나만 돈다.
- 행을 누르면 **작업 상세 창**: 입력 열과 자동 열의 덮어쓰기를 고친다. `이전 입력 불러오기`는 같은 국소의 가장 최근 누적에서 작업시간·작업유형·중장비투입·작업내용·상세를 채운다(누른 행만, 자동으로 덮어쓰지 않음). 입력 칸은 목록에서 고르거나 `목록에 추가`로 값을 더한다.
- 행을 체크하면 `선택한 N건 일괄 적용`으로 같은 값을 한꺼번에 넣는다. 일괄 창의 `선택한 N건 이전 입력 불러오기`는 행마다 이전 누적의 입력 열을 **미리보기 없이 바로 저장**하고 `N건 불러옴 · M건 이전 누적 없음`으로 알린다.
- `목록 관리`(관리자): 목록 8종의 값을 추가·삭제한다. 목록에서 지워도 이미 쓰인 상세의 값은 남는다.
- 관리자가 아니면 읽기 전용(저장·목록 관리·누적 저장 숨김).

**누적**
- 쌓인 행을 작업일 내림차순으로 24열 표에 보인다. 기간(시작·끝)과 검색어(국소·프로젝트·통합시설코드)로 거른다. 최근 500건까지만 보이고, 넘으면 좁히라는 안내가 나온다.
- 거른 결과를 `표 복사`(제목 줄 없이)하거나 `엑셀 내려받기`(시트 `List`)한다. 관리자는 행을 골라 `선택 삭제`한다(확인 창 후, 되돌릴 수 없음). 필터를 바꾸는 동안에는 이전 결과에 복사·내려받기·삭제가 실행되지 않는다.

## 데이터 흐름 메모

- `schedule_day_details`·`schedule_archive_rows`는 **(날짜, 국소)에 묶여 있고 일정 칸을 참조하지 않는다.** 그래서 일정표를 다시 가져와(`replace_schedule_cells`) 칸이 지워져도 **상세와 누적은 지워지지 않는다.** 팀을 옮기거나 칸을 맞바꿔도 상세가 남는다.
- `saveDetails`는 캐시된 값이 아니라 **저장 시점에 DB에서 다시 읽은 행**에 패치를 합친다(다른 관리자의 수정이나 연달아 한 저장을 덮지 않는다). 패치의 빈 글(`""`)은 그대로 저장하고, `overrides`는 키별로 합치며 값이 `""`인 키는 덮어쓰기를 지운다.
- `saveArchiveRows`는 그날 행을 upsert한 뒤 그날의 다른 국소 행(일정에서 빠진 국소)을 지운다. 행이 0개면 아무것도 하지 않는다.
- `fetchLatestArchive`는 보고 있는 날 **이전** 날짜의 행만 본다. 그날 자신의 저장본이 참조가 되지 않게 하려는 것이다.
- 마이그레이션 적용 전에는 테이블이 없다는 오류를 `isTableMissing`으로 받아 안내 문구를 보이고 일정표는 계속 열린다. 목록이 비어 있으면 처음 값(`OPTION_LIST_SEEDS`)을 쓴다.

## 알려진 제한

- (a) 일정의 국소명이 `erp_details.station_final`과 **글자까지 같아야** 공정관리 값을 찾는다(공백·대소문자 차이는 못 찾음).
- (b) 공정관리 열은 `위치등록`으로 공정관리를 올려야 채워진다(작성 시점 DB에는 11/09 국소 9건이 없었다).
- (c) 국소명에 큰따옴표(`"`)가 있으면 공정관리 조회가 실패할 수 있다(`.in()`의 따옴표 처리).
- (d) 누적 저장은 관리자만 하고, 그날 국소가 0개면 아무것도 하지 않아 예전 누적이 남는다.
- (e) 공정관리 층이 프로젝트 값 하나만 있어도 통째로 채택되어 누적·마커 층을 막는다(계획의 "통째로" 규칙).
- (f) 엑셀은 넘겨받은 행 아래 24행까지 드롭다운만 있고 서식은 없다.
- (g) 복사·내려받기를 진행하는 동안 행을 열어 저장하면 반응이 없다.
- (h) 화면(브라우저) 확인은 구현 중에 하지 않았다. 마이그레이션 적용 후 사용자와 함께 한다.
- (i) 자동 누적 저장은 오늘과 앞으로의 날짜만 한다. 지난 날짜의 누적은 확인 창을 거친 `누적 저장` 버튼으로만 바뀌고, 그때 지금 일정에 없는 국소는 누적에서 빠진다.
- (j) 누적을 다시 저장하면 `saved_by`·`saved_at`은 BEFORE UPDATE 트리거가 새로 고친다(앱은 보내지 않는다).
- (k) 누적 보기·복사에서 같은 날 안의 순서는 국소 키 순이고 순번 열은 저장 당시 값이다. 누적 엑셀은 순번을 1부터 다시 매긴다.
- (l) 목록의 값을 모두 지우면 화면에는 처음 값이 다시 나타난다. 마이그레이션을 다시 실행하면 지운 처음 값이 DB에 다시 들어간다.
- (m) 입력 칸 글자 수는 화면에서 제한한다(짧은 칸·참조 덮어쓰기 200자, 작업내용 상세 500자, 목록 값 100자). DB 한도도 같다.
