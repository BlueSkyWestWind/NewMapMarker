# TBM 엑셀 내보내기 결정 (설계)

작성일 2026-11-15 · 대상: `src/features/worksite-weather/lib/export-tbm.ts` · 구현계획: [Ver_3.0_TBM내보내기결정_구현계획.md](Ver_3.0_TBM내보내기결정_구현계획.md) · 구현: [Ver_3.0_TBM내보내기결정_구현.md](Ver_3.0_TBM내보내기결정_구현.md)

## 1. 배경과 결정 사항

`export-tbm.ts`(105줄, `exportTbmWorkbook`)는 국소 작업 안전 날씨를 TBM(작업 전 안전교육) 자료 엑셀로 저장하는 함수다. 날씨 패널(`worksite-weather-panel.tsx`)에서만 호출됐는데, 그 패널을 Ver 2.3(2026-10-21 커밋 `8764d75`)에서 미참조 파일로 삭제하면서 호출처가 없어졌다. 그때 "복원/삭제 결정 전까지 파일만 남겨 둔다"고 정했고 지금까지 결정이 나지 않았다. 이 문서는 **복원·삭제·보류 중 무엇을 할지 고르는 데 필요한 사실과 선택지**를 정리한다.

**사용자가 정한 것**

| # | 결정 | 날짜 |
|---|---|---|
| 1 | 복원/삭제 결정 전까지 파일은 건드리지 않는다(AGENTS.md) | 2026-10-21 |
| 1-1 | **TBM 엑셀은 사용하지 않는다. 삭제(A)로 한다** | 2026-11-15 |

**설계에서 정한 것(사용자 확인 대상은 §6)**

| # | 결정 |
|---|---|
| 2 | 이 작업의 결과는 **사용자의 선택**이다. Claude는 사용 여부를 모르므로 추천은 "사용 안 한다면 삭제, 쓴다면 복원"의 조건부로 둔다 |
| 3 | 어느 선택이든 태풍 모달의 안내 문구(§2.2)는 현재 상태와 맞게 고친다 |

## 2. 확인한 사실

### 2.1 코드 상태

- `exportTbmWorkbook(site: SiteMatch, data: WorksiteWeatherResponse): Promise<void>` — `xlsx`를 호출 시점에 지연 로드하고, "작업안전날씨" 시트 한 장을 `TBM_작업안전날씨_<국소명>_<일자>.xlsx`로 저장한다. 국소명·주소·작업 형태(옥상·철탑(고소)/지상)·조회 일자·예보 발표·종합 판정·권장 시간대, 시각별 표(기온·체감·습도·풍향·풍속·강수확률·판정·사유·출처), 위험 요약(폭염·강풍·강수·한파), 발효 특보, 태풍, 주의, 법정 기준 고지문을 적는다(시트 구성은 `buildRows`).
- 전체 `src`에서 이 함수를 부르는 곳이 없다. 이 파일을 테스트하는 파일도 없다.
- 입력 타입 `SiteMatch`·`WorksiteWeatherResponse`는 `worksite-weather/types/weather.ts`에 있다.

### 2.2 화면과 안내 문구의 불일치

`worksite-weather/components/typhoon-modal.tsx`(약 429~431줄)는 태풍 내습 시 수칙으로 "3. 작업 전 TBM 엑셀 출력 및 안전교육 실시 — 당일 기상 상황을 TBM 엑셀 서식으로 출력하여 현장 작업자들에게 공유하고 비상 연락망을 재확인합니다."라고 안내한다. **출력 기능이 화면에서 사라졌는데 안내 문구는 남아 있다.** 사용자가 어디서 출력하는지 찾게 된다.

### 2.3 데이터 연결 가능성

지금 대시보드는 기상청 저장 데이터(`kma_forecast_cache`)와 [현재 데이터로 갱신] 버튼을 쓴다(기상청호출관리). 복원하려면 `exportTbmWorkbook`이 요구하는 `WorksiteWeatherResponse`를 현재 대시보드가 쓰는 데이터에서 만들 수 있는지부터 확인해야 한다. 같은 모양이 아니면 변환 함수를 더하거나 `buildRows`를 고쳐야 한다. 이 확인은 복원을 고른 경우에만 구현계획 Task에서 한다.

## 3. 선택지

| 선택 | 내용 | 해야 할 일 | 위험·비용 |
|---|---|---|---|
| **A. 삭제** | `export-tbm.ts`를 지운다 | 파일 삭제, 태풍 모달 문구 수정, AGENTS.md의 보류 문장 삭제 | 가장 작다. 나중에 필요하면 git 기록(`46fb126`, `8764d75`)에서 복원할 수 있다 |
| **B. 복원** | 대시보드의 국소 행(또는 상세)에 [TBM 엑셀] 버튼을 다시 둔다 | 데이터 모양 확인·변환, 버튼 UI, 호출 연결, `buildRows` 테스트 | 중간. 현재 데이터 구조와 맞춰야 하고 화면 설계가 필요하다 |
| **C. 보류 유지** | 지금처럼 파일만 남긴다 | 태풍 모달 문구만 고친다 | 죽은 파일이 남고 결정이 계속 미뤄진다 |

**추천(조건부):** TBM 엑셀을 실제로 쓰지 않으면 **A**, 쓴다면 **B**. C는 결정을 미루는 선택이라 권하지 않는다.

## 4. 범위 밖

- 태풍 모달의 다른 수칙 내용.
- TBM 서식 자체의 개편.
- 날씨 판정 로직 변경.

## 5. 위험과 검증

- **법정 기준 고지(삭제 시)**: `buildRows`의 주석은 법정 기준 고지문을 "화면과 저장 자료 양쪽에" 남기라고 한다(CR-004 §2.1). 내보내기를 없애면 저장 자료 쪽은 없어지고 화면 쪽만 남는다. 화면에 고지가 실제로 표시되는지 삭제 전에 확인한다.
- **삭제(A)**: `tsc`가 참조 누락을 잡는다. 이 파일은 참조가 없어 컴파일 영향이 없다. `git log`로 복원 경로를 구현 문서에 적어 둔다.
- **복원(B)**: 서버가 아닌 브라우저에서 `xlsx` 저장을 하므로 지연 로드(`import("xlsx")`)를 유지해 홈 번들에 영향이 없어야 한다. 임시 distDir 빌드로 홈 First Load JS 변화가 없는지 확인한다.
- **검증**: `npx tsc --noEmit`, `npx eslint . --max-warnings=0`, `npm test`.

## 6. 사용자 확인 필요 항목

1. **A 삭제 / B 복원 / C 보류 유지** 중 선택. 현장에서 TBM 엑셀을 출력해 쓰는지가 기준이다.
2. B를 고르면 버튼을 둘 위치(대시보드 국소 행 / 국소 상세 / 태풍 모달 안)와 파일 형식(지금 서식 그대로 / 변경)을 정한다.
