# 시설일정 — 여러 팀 동시 등록 · 국소별 입회·신호수 불필요 표시 · 편집 창 확대 (설계)

작성일 2026-11-08 · 대상 화면: 일정관리 > 시설일정의 칸 편집 창(`schedule-cell-dialog.tsx`)과 일일일정(일자별 상세)

## 1. 배경 (사용자 피드백, 2026-11-08)

1. 국소를 등록할 때 시설팀 여러 곳이 동시에 들어가는데, 팀마다 같은 입력을 반복해야 한다.
2. 같은 팀·같은 날이라도 국소마다 입회·신호수 필요 여부가 다르다. 전주 국소(신월금호4, 신월코아루외부)는 필요하고, 건물 옥상인 국동신월은 필요 없다. 이를 묶어 정리할 방법이 없다.
3. 건물 실내인 여수봉산중심국도 별도로 구분해야 하는데 방법이 없다.
4. 일정 수정 입력 창이 좁다.

## 2. 현재 구조 (코드에서 확인한 사실)

- 입회·신호수는 **팀·날짜당 한 쌍**이다. 같은 팀 열의 별도 행에 `입회 : 이름`, `신호수 : 이름` 칸(`mainText === ""`)으로 저장된다(`lib/companions.ts`).
- 일일일정은 `buildDayStations`(`lib/day-stations.ts`)가 국소를 이름으로 합쳐, 그 국소를 맡은 팀들의 팀장·입회자·신호수 이름을 모은다. 입회·신호수는 **팀 열 단위**로만 모은다.
- 칸 편집 창은 한 팀·한 날짜의 국소 목록을 `EntryDraft[]`로 보여 주고, 저장할 때 `planGroupSave`류 순수 함수(`lib/group-edit.ts`)가 지움·고침·추가를 정한다.
- 창 폭은 `max-w-2xl`로 박혀 있다. 폭 상수는 `features/shell/constants.ts` 단일 소스다.
- `schedule_cells`에는 `main_text`, `sub_text`, `text_color` 등이 있고 쓰기는 관리자 전용 RLS다.

## 3. 목표와 비목표

**목표**
- 같은 날짜의 여러 팀에 같은 국소를 한 번에 등록한다.
- 국소마다 "입회·신호수 불필요"를 표시하고, 일일일정에서 그 국소의 입회자·신호수를 비운다.
- 편집 창을 넓히고 높이를 더 쓴다.

**비목표 (이번에 하지 않는다)**
- 이름 붙인 국소 그룹(전주/옥상/실내)과 그룹별 입회·신호수 행. 사용자가 A안(국소별 표시)을 선택했다.
- 여러 날짜에 걸친 동시 등록(같은 날짜의 여러 팀만).
- 월간·주간 일정표와 엑셀 내보내기 모양의 변경. "불필요" 표시는 엑셀 가져오기·내보내기에 실리지 않는다.
- 이미 등록된 일정의 일괄 수정(새로 추가할 때만 팀을 고른다).

## 4. 설계

### 4.1 데이터: `schedule_cells.no_companion`

- 마이그레이션 `supabase/migrations/20261114000000_schedule_cells_no_companion.sql`:
  `ALTER TABLE public.schedule_cells ADD COLUMN IF NOT EXISTS no_companion boolean NOT NULL DEFAULT false;`
  기본 false라 기존 일정의 동작은 바뀌지 않는다. 적용은 사용자가 한다. README 마이그레이션 표에 한 줄 추가.
- 타입: `ScheduleCell.noCompanion?: boolean`(없으면 false). `ScheduleTextInput`에 `noCompanion?: boolean`을 더한다.
- 입회·신호수 칸 자체(`isCompanionCell`)에는 의미가 없다. 국소 칸(`mainText !== ""`)에서만 쓴다.
- 읽기·쓰기 경로(`api.ts`의 칸 조회·생성·수정, `read-schedule`·`schedule-excel` 가져오기)가 이 열을 읽고 쓴다. 엑셀 가져오기는 새 칸을 만들 때 false로 둔다.
- 마이그레이션이 적용되기 전에도 앱이 깨지지 않게, 칸 조회는 컬럼이 없으면(`42703`/`PGRST204`) `noCompanion` 없이 읽는다(기존 `detached_visible` 패턴과 같다).

### 4.2 일일일정에서 반영 (`lib/day-stations.ts`)

- `StationDraft`에 열별 표시를 담는다: 국소를 맡은 열 번호 → `noCompanion`(그 열의 해당 국소 칸이 불필요로 표시됐는지).
- 입회자·신호수를 모을 때 `noCompanion`인 열은 건너뛴다. 팀장 이름은 지금처럼 모은다.
- 같은 국소를 여러 팀이 맡았고 한 팀만 불필요이면, 불필요가 아닌 팀의 입회자·신호수는 남는다.

### 4.3 칸 편집 창: 국소별 표시와 팀 동시 등록

- `EntryDraft`에 `noCompanion: boolean`을 추가한다. 국소 행마다 체크박스 "입회·신호수 불필요"를 둔다.
- `group-edit.ts`: 글·뒤 칸·글자색에 더해 `noCompanion`이 바뀐 기존 칸도 고친다(`update`의 `text`에 포함). 새 칸 생성에도 값을 싣는다.
- "국소 검색해서 추가" 영역에 **"함께 등록할 팀"** 체크 목록(같은 날짜의 다른 팀 열, 비고 열 제외)을 둔다. 체크한 팀이 없으면 지금과 동작이 같다.
- 새 순수 함수 `planCrossTeamCreate(cells, columns, input)`(`lib/group-edit.ts` 또는 새 파일 `lib/cross-team.ts`):
  - 입력: 추가할 국소 초안들, 대상 팀 열 id 목록, 날짜, 현재 칸들.
  - 출력: 팀별 `create` 연산 목록과 **건너뛴 팀**(빈 행 부족: `full`). 팀마다 마지막 일정 아래 빈 행(없으면 위로 돌아감)에 차례로 배정하는 기존 규칙을 그대로 쓴다.
  - 원래 팀의 저장은 기존 `planGroupSave` 결과 그대로다. 함께 등록한 팀은 그 위에 더해진다.
- 저장 오류 처리: 한 팀의 행이 모자라면 그 팀만 건너뛰고 나머지는 정상 저장한다. 저장 뒤 안내 문구에 건너뛴 팀 이름을 적는다. 일부 팀 저장이 실패하면 기존 일부 실패 처리(성공한 건수·남은 변경 표시)를 따른다.
- 입회·신호수 칸은 팀마다 따로이므로 함께 등록으로 복사하지 않는다(국소 칸과 불필요 표시만 복사).

### 4.4 창 크기

- `features/shell/constants.ts`에 `SCHEDULE_CELL_DIALOG_MAX_WIDTH_PX` 상수를 추가하고(권장 값 1024), `schedule-cell-dialog.tsx`의 `max-w-2xl`을 `style={{ maxWidth: … }}` + `w-[96vw]`로 바꾼다(`group-bulk-dialog.tsx`와 같은 방식). 높이는 `max-h-[92vh]`를 유지하되 국소 목록 영역이 남는 높이를 쓰도록 한다.
- 표는 줄바꿈 금지·가로 스크롤 금지 규칙(`.cursor/rules/table-no-wrap.mdc`)을 따른다. 폭을 키워서 해결한다.

## 5. 오류·경계 조건

- 국소 칸이 아닌 입회·신호수 칸의 `noCompanion`은 무시한다.
- 팀을 함께 등록할 때 대상 팀의 같은 날짜에 이미 같은 국소(같은 `mainText`)가 있으면 중복으로 만들지 않고 건너뛴 것으로 알린다.
- 함께 등록 대상에 원래 팀은 나오지 않는다.
- 관리자가 아니면 편집 창이 읽기 전용이다(기존 `canEdit`). 새 체크박스와 팀 목록도 `canEdit`일 때만 보인다.

## 7. 구현 순서

1. 창 크기(4.4) — 독립, 바로 효과.
2. 불필요 표시(4.1·4.2·4.3 앞부분) — 마이그레이션 필요, 사용자가 적용.
3. 여러 팀 동시 등록(4.3 뒷부분) — 2번의 `noCompanion` 복사에 의존하므로 마지막.

## 8. 가정 (사용자 확인됨 / 확인 필요)

- 확인됨: 표시 방식은 A안(국소별), 효과는 일일일정의 입회자·신호수 칸, 동시 등록은 같은 날짜.
- 확인 필요: 월간 일정표에 보이는 `입회 : 이름` 행은 그대로 둔다(불필요 국소가 있어도 팀·날짜 단위 행은 유지).
