개정 2026-11-13 · 검토(grilling) 10건 반영: ① 인빌딩 기본 규칙에서 철탑 규격·공중선 형상 `1` 제외 ② `useMokukOnly` 방식 옵션 ③ Site명 기본 꺼짐과 규칙 확정 ④ 알려진 방식 목록과 경고 ⑤ `NW구조혁신` 기본 치환 ⑥ 사용자가 직접 바꾼 칸 유지 ⑦ 가져오기·내보내기·읽는 위치 편집·`세부_27년`은 2차 ⑧ 읽을 때 색인만 보관·4개씩 병렬 ⑨ 첫 저장 거부(`42501`) 구분

## 1. 배경과 결정 사항

공정 파일(`공정_일정관리.xlsb`)의 `세부_26년`·`세부_27년` 시트에는 국소마다 80개 칸이 있다. 그중 상당수를 현장실사서(국소마다 1개씩 받는 엑셀·PDF)를 보고 **손으로 옮겨 적는다.** 실사서 엑셀을 올리면 세부 시트에 옮겨 적을 값을 만들어 주는 기능을 만든다.

**사용자가 정한 것**

| # | 결정 |
|---|---|
| 1 | 결과는 **세부 시트와 같은 열 구성의 엑셀**로 내려받는다. 공정 xlsb는 건드리지 않는다. |
| 2 | **실사서만 올린다.** 공정 xlsb를 읽어 현재 값과 비교하지 않는다. |
| 3 | **엑셀(xlsx)만 지원하고 PDF는 제외한다.** PDF는 엑셀과 같은 내용이다. |
| 4 | 공중선 형상은 **숫자만** 넣는다(`1S` → `1`). |
| 5 | 모국명·상위국명의 `(공동)`, `(도서)`는 지운다. |
| 6 | **SCAN 국사**는 이름에 `집중국`·`통합국`·`중심국`·`전송실`이 있는 것이다. 그 밖(기지국 이름 등)은 `비SCAN`이다. |
| 7 | **모국(&기지국)**: `(LTE)전송로 상위국명`이 있으면 그 값, 없으면 모국명. 단 **방식이 인빌딩이면 모국명**을 쓴다. 집중국은 모국명 기준이다. |
| 8 | 통합국과 중심국은 이름만 다르고 **같은 건물이라 위치가 같다.** LTE는 중심국, 5G는 통합국으로 혼용한다. 이름만 다를 때 경고하지 않는다. |
| 9 | **인빌딩 기본 규칙**: 방식 `인빌딩`→`광분산`, 철탑 형태 `인빌딩`, 장비위치는 치국현황의 `장비설치 층`, 모국은 모국명. 철탑 규격·공중선 형상 `1`은 근거가 약해(각 47%·53%) 기본 규칙에서 빼고 실사서 원본값을 쓴다. |
| 10 | `문제점 세부내역`은 본문의 **모든 `기타N` 항목**(`기타1`, `기타2`, `기타3` …)과 상세출입방법·건물구분의 값을 이어 붙인다. 기본 꺼짐이다. |
| 11 | 규칙을 코드에 고정하지 않고 **환경설정 창에서 세세하게 설정**한다. 설정은 **Supabase에 저장하고 관리자만 수정**한다. |
| 12 | **사이드바의 일정관리 아래에 `공정관리` 메뉴를 만들고, 그 하위에 `현장실사서`를 둔다.** 화면은 일정관리처럼 메인 영역을 직접 쓴다. |

## 2. 확인한 사실 (파일을 직접 열어 확인)

### 2.1 세부 시트 (`세부_26년` 6,958행 / `세부_27년` 27행)

- 4행 그룹(일반현황·공정진행현황·계획 및 문제점 현황·Eng's 현황·기타현황·원상복구확인서·한전공가), 5·6행 머리글, 7행부터 데이터. A~CB 80열.
- 행은 `프로젝트`(B열) + `통합시설코드`(C열)로 유일하다.

### 2.2 현장실사서 양식

- 시트 1개짜리 서식 문서. 병합 셀이 약 735개, 값이 있는 칸은 약 380개다.
- 섹션: `1. 일반현황 / 2. 치국현황 / 3. 안전관리 / 4. 엔지니어링 정보 / 5. 공중선계 / 6. 부대장비` + 사진. 섹션 제목은 A열에 `N. 이름`으로 있다.
- 칸 배치는 두 가지다. ① 라벨 줄 바로 **아래 줄**에 값(`방식`, `확정국소명`, `철탑형태` 등), ② 라벨 **오른쪽**에 값(`프로젝트 코드`, `치국목적`, `투자목적 대분류`, `기타1`, `상세출입방법` 등).
- 파일마다 행 수(176~186)가 달라 **좌표가 아니라 라벨 글자로** 찾아야 한다.
- 파일명: `프로젝트코드_통합시설코드_국소명_…_팀이름.xlsx`.
- **옥상형·3G·인빌딩 모두 섹션과 라벨이 같은 서식이다.** 다른 것은 값의 모양과 세부 시트에 적는 관행이다(§4.4).
- PDF는 `pdftotext -enc UTF-8`로 한글이 읽히지만 표 칸이 줄 단위로 뒤섞여 라벨로 값을 찾기 어렵다. 그래서 엑셀만 지원한다.

### 2.3 샘플 (엑셀 13건)

| 구분 | 건수 | 세부 시트 | 용도 |
|---|---|---|---|
| 수완포레외부 (5G AAU 2, LTE RRU 1) | 3 | 입력됨 | 정답 |
| 아트박스여수점 (5G 1, LTE 5) | 6 | 입력됨 | 정답 |
| 돌산무슬목 (LTE 공동 RRU) | 2 | **비어 있음**(6747·6748행) | 이 기능의 대상 |
| 여수남면WMC (3G WCDMA, 기존망개선) | 1 | 입력됨(6200행) | 정답 |
| 무안오룡희망초등학교 1층 A (인빌딩 5G) | 1 | 일부 칸만 입력됨(6467행) | 부분 정답 |
| 화정아이파크 101동 B3층 (인빌딩) | PDF만 | 방식만 입력됨(5862행) | **엑셀을 받아 구현 때 검증** |

- 실사서 13건 모두 `세부_26년`에 정확히 1행씩 있다(프로젝트코드 + 통합시설코드). `일정관리` 시트에는 없다.
- 폴더에는 엑셀을 열어 두는 동안 생기는 **임시 잠금 파일**(`~$…xlsx`)이 섞일 수 있다.

### 2.4 정답 대조 결과 (분석 스크립트로 확인)

- 실사서 값을 그대로 쓰면 **9/9 일치**하는 칸이 16개다(§4.3 "확실", 수완포레·아트박스).
- 변환 규칙을 13개 엑셀에 적용해 세부 시트에 값이 있는 행과 비교했다.

| 칸 | 일치 |
|---|---|
| 방식 | 10/10 |
| 모국(&기지국) | 11/11 |
| 집중국 | 11/11 |
| 철탑 형태 | 11/11 |
| 철탑 규격 | 11/11 |
| 장비위치 | 11/11 |
| 공중선 형상 | 8/11 |

※ 철탑 규격·공중선 형상의 일치율은 인빌딩 `1` 고정을 포함한 값이다. 개정 뒤에는 인빌딩(무안오룡 1건)이 원본값을 쓰므로 기대치를 **철탑 규격 10/10, 공중선 형상 7/10(무안오룡 제외)** 로 하고, 무안오룡은 원본값과 세부 시트 값을 따로 비교해 기록한다.

- 공중선 형상의 불일치 3건은 사용자가 `1S`·`3S`로 입력해 둔 수완포레 행이다. 결정 4(숫자만)를 따른 결과다.
- `문제점 세부내역`: 사용자가 넣은 항목(일반현황 기타1·2, 상세출입방법, 건물구분, 치국현황 기타1·2·3)을 같은 순서로 이으면 수완포레 3건과 정확히 일치한다. 아트박스 6건은 사용자가 앞에 `10/28 K대응 3차사업 발행…` 같은 **수기 메모**를 붙여 둔 것이라 다르다.

### 2.5 `기타N` 항목 전수 확인

- 본문 1~5 섹션에 `기타N` 라벨이 12개 있다(일반현황 1·2, 치국현황 1·2·3, 안전관리 1·2, 엔지니어링 1·2, 공중선계 1·2·3). 값이 있는 개수는 파일마다 6~8개다.
- **부대장비 섹션 아래의 `기타1`~`기타11`은 메모가 아니다.** `현장조사 사진` 머리글 아래 사진 칸의 **이름표**라서 값이 없고, 오른쪽에는 다음 이름표(`기타2`)만 있다. 읽으면 안 된다.
- `기타(광공유모듈)`, `기타(OM)`, `기타(정류기, 축전지)` 같은 **괄호가 붙은 항목**은 `해당없음` 등의 선택 값이거나 별도 칸이라 대상이 아니다.

### 2.6 세부 시트의 입력 관행

- **인빌딩 장비**(국소명에 `GIRS(인…)`·`GIRO(인…)`, 장비최종이 `RO-GIR…`) 300행 중 철탑 형태·장비위치가 채워진 276행:

| 칸 | 값 (행 수) |
|---|---|
| 방식 | `광분산` 208, `광중계기` 59 (`인빌딩`은 시트 전체에 **0행**) |
| 철탑 형태 | `인빌딩` 154, `광분산` 14 |
| 철탑 규격 | `1` 129, `2` 28, `0` 11 |
| 공중선 형상 | `1` 146, `OMNI` 13 |
| 장비위치 | `EPS실`·`3층~4층 사이 PIT실` 같은 **층 표기**, `실내`, `지하` 등 |

- **모국·집중국**: 모국 이름에 `통합국`·`집중국`이 있는 2,295행의 98.5%, `중심국`이 있는 1,515행의 97.3%가 집중국에 **같은 이름**을 적었고 `비SCAN`은 0행이다. `전송실`도 집중국에 같은 이름을 적는다(`S제주전송실` 760행). 기지국 이름(`섬진강수련원기지국`, `세지L` 등)은 `비SCAN`이 많다.
- **주소**: 첫 단어가 `전남광주통합특별시` 2,187행, `전북` 1,502행, `전남` 1,018행, `광주` 360행으로 통일되어 있지 않다. 여수남면WMC·무안오룡은 사용자가 `전남광주통합특별시`를 줄이거나 고쳐 적었다. 실사서 값을 그대로 쓰고 이 차이는 사용자가 손본다.
- **사업구분 중분류**: 여수남면WMC 실사서는 `NW구조혁신`, 세부 시트는 `NW슬림화`다. 대분류 `기존망개선` 2,737행이 `NW슬림화`이고 `NW구조혁신`은 한 건도 없다.
- **비SCAN 표기**: `비SCAN` 781행, 오타(`비SCSAN`, `비SAN`, `비SCNA`) 1행씩.
- **방식 값(2026-11-13 집계)**: `광중계기` 5,455, 빈 칸 587, `광분산` 563, `기지국` 310, `터널` 48, `끝` 1. 이 값들이 세부 시트의 방식 어휘다.
- **Site명(BU)(2026-11-13 집계)**: `세부_26년` 6,958행 중 값이 있는 행은 818개뿐이고 `불필요` 2,533, 빈 칸 3,607이다. 값이 있는 818행 중 국소명 꼬리만 지워서 맞는 것은 506행(62%)이다. 안 맞는 것은 인빌딩에서 동·층까지 지운 경우(`조촌아너스빌108동B3-GIRO(인-공K3)_L1P2`→`조촌아너스빌`)와 이름을 바꿔 적은 경우(`한국에너지공대외부2_1-AAU`→`한국에너지대학교외부2`)다. `(공동)` 접두는 Site명에서 지워진다(`(공동)백운산한재-RRU(F1)`→`백운산한재`).

## 3. 목표와 비목표

**목표**
- 실사서 xlsx를 여러 개 올리면 파일마다 세부 시트의 한 행에 해당하는 값을 만든다.
- 어떤 칸을 내려받을지 사용자가 고른다.
- 세부 시트와 같은 열 순서·같은 머리글의 엑셀(`.xlsx`)을 내려받는다.
- 방식(옥상형·인빌딩 등)에 따라 달라지는 입력 관행을 규칙으로 처리한다(§4.4).
- 못 읽거나 이상한 값은 경고로 알린다.
- 관리자가 환경설정 창에서 치환표·국사 규칙·방식별 규칙을 코드 수정 없이 바꾼다(§4.8).

**비목표**
- 공정 xlsb 읽기·쓰기, 세부 시트 직접 수정, 현재 값과의 비교.
- PDF 읽기, 사진 처리.
- 실사서 파일과 결과의 서버 전송·저장. 읽기와 변환은 모두 브라우저에서 하고, DB에는 **환경설정 1행만** 저장한다(§4.8).
- 실사서에서 만들 수 없는 칸(§4.3 "만들지 않는 칸")을 추측해서 채우는 것.

## 4. 설계

### 4.1 화면과 흐름

1. 좌측 메뉴 **공정관리 > 현장실사서**(일정관리 바로 아래).
2. 실사서 xlsx를 여러 개 끌어다 놓거나 선택한다. 파일마다 읽은 결과가 한 줄로 나온다: 프로젝트코드, 통합시설코드, 국소명, 방식, 채워진 칸 수, 경고 수.
3. **내려받을 칸 체크리스트**. 믿을 만한 정도별 그룹이다.
   - 확실: 기본 켜짐
   - 규칙 변환(방식별 예외 포함): 기본 켜짐
   - 수기 메모와 섞이는 칸(문제점 세부내역, Site명): 기본 꺼짐
   - 사용자가 직접 바꾼 칸은 설정이 바뀌어도 그 선택을 유지하고, 나머지는 설정의 기본값을 따른다. **기본값으로** 버튼이 직접 바꾼 선택을 모두 지운다.
4. 줄을 펼치면 칸별 값(원본 → 변환 결과)이 보인다. 라벨을 못 찾은 칸은 "찾지 못함"으로 표시한다. 방식별 예외 규칙이 적용된 칸에는 "인빌딩 규칙" 같은 표시를 붙인다.
5. **엑셀 내려받기**.
6. 화면 오른쪽 위의 **환경설정** 버튼으로 설정 창을 연다(§4.8). 설정을 바꾸면 이미 올린 파일의 결과가 **즉시 다시 계산**된다(파일을 다시 읽지 않는다).
7. 안내 문구: "현재 값을 읽지 않으므로 **행 전체를 붙여넣으면 빈 칸이 기존 값을 지웁니다. 칸(열) 단위로 복사하세요.**"

### 4.2 결과 엑셀

- **시트 `세부_입력값`**: 세부 시트 양식 그대로(첨부 `현장실사서.xlsx`). **1~6행은 머리글 블록**(3행 개수 합계, 4행 그룹 이름, 5·6행 머리글)이고 초록 머리글·필터·고정 칸·열 너비 등 서식도 양식과 같다. **데이터는 7행부터** 파일 1개가 1행이며 업로드 순서를 따른다(2026-11-13 개정). 열 순서는 A~CB. 식별 칸(`연도`·`프로젝트`·`통합시설코드`)은 항상 채운다. 체크한 칸만 값이 있고 나머지는 **빈 칸**이다.
- **시트 `경고`**: 파일명, 항목, 내용. 값이 없으면 만들지 않는다.
- 파일 이름: `세부_입력값_YYYYMMDD.xlsx`.

### 4.3 칸 규칙 (기본값)

규칙의 **기본값**은 `constants/survey-fields.ts`(칸 규칙)와 `constants/default-settings.ts`(치환표·SCAN 단어·방식별 규칙 등) 두 곳에만 둔다. 이 표의 값은 기본값이고, 관리자가 §4.8의 환경설정으로 덮어쓸 수 있다. 각 항목은 `세부 열`, `섹션 번호`, `라벨`, `방향(below|right)`, `변환 이름`, `그룹`으로 이루어진다.

**식별 칸** (항상 포함): `연도`(A) ← 일반현황 `사업년도`(below), `프로젝트`(B) ← 일반현황 `프로젝트 코드`(right), `통합시설코드`(C) ← 일반현황 `통합시설코드`(right). 라벨 위치는 여수남면WMC·무안오룡 2건에서 확인했고 나머지는 구현 때 확인한다.

- 건물유형, 공용화 단독/공용: 기존 입력이 일정하지 않다.
- 장비최종·장비계획 대분류: AAU는 `AEQN` 같은 코드가 실사서에 없다.
- 협력사, 청약·전기·ERP 활용구분, 시험 계획, 한전공가 등 다른 절차에서 채우는 칸.

### 4.4 방식별 예외 규칙

세부 시트의 입력 관행은 **방식**에 따라 다르다. 인빌딩은 실사서 값을 그대로 쓰지 않고 다르게 적는다(§2.6). 값 치환표만으로는 `광분산`을 쓰는 옥상형 사이트의 철탑 형태까지 바뀔 수 있어, **방식에 조건을 건 예외 규칙**을 둔다.

- **조건**: `방식` 칸의 **원본 값**(치환 전)이 목록의 값과 정확히 같을 때. 첫 단계에서는 `방식`만 조건으로 쓴다.
- **동작**: ① 이 칸에 **고정값**을 넣는다. ② 이 칸을 **다른 원본 위치**(섹션·라벨·방향)에서 읽는다. ③ 방식 옵션 `useMokukOnly`: 모국(&기지국)에서 상위국명을 무시하고 모국명을 쓴다(칸이 아니라 방식에 거는 옵션이다).
- 인빌딩 판별은 국소명이나 장비 이름이 아니라 **실사서의 방식 칸**이다. 세부 시트에는 인빌딩 장비인데 `광중계기`로 적은 행도 59개 있어, 이름으로는 자동 구분할 수 없다.

**기본값 (인빌딩)** — 결정 9

| 세부 열 | 동작 | 근거 |
|---|---|---|
| 방식 (J) | 칸별 치환표 `인빌딩` → `광분산` | 세부 시트에 `인빌딩`은 0행, `광분산` 208행 |
| 철탑 형태 (BF) | 고정값 `인빌딩` | 276행 중 154행 |
| 장비위치 (BB) | 원본 `2 / 장비설치 층 / below` | 무안오룡 `1층 EPS_A 실` |
| 모국(&기지국) (Y) | 방식 옵션 `useMokukOnly` 켜짐: 상위국명을 쓰지 않고 모국명을 쓴다(§4.5) | 무안오룡 `S목포옥암통합국` |

- **철탑 규격·공중선 형상은 기본 규칙에 넣지 않는다.** 세부 시트의 인빌딩 값 `1`은 각 129행(47%)·146행(53%)이고 실사서 근거는 무안오룡 한 건이라 절반쯤 틀릴 수 있다. 실사서의 `0`·`OMNI`를 `1`로 바꾸는 뜻도 확인하지 못했다(§6). 의미가 확인되면 관리자가 설정 창에서 고정값 규칙으로 추가한다.
- 사용자가 새 방식(터널, 기지국 등)의 규칙을 직접 추가할 수 있다(§4.8).

### 4.5 모국(&기지국)·집중국

- **읽는 칸**: 실사서 `4. 엔지니어링 정보`의 `모국명`과 `(LTE)전송로 상위국명`. 5G는 `모국명`만 있는 경우가 많고, LTE는 둘 다 있다.
- **이름 다듬기** (결정 5): ① 앞의 `(공동)`·`(도서)` 태그를 **모두** 지운다(`(공동)(도서)…`처럼 연달아 있어도 전부). ② 첫 `-NN_`(`NN`은 숫자 두 자리), `_`, `.55.` 중 가장 먼저 나오는 곳 앞까지만 남긴다. 셋 다 없으면 그대로 둔다.
  - `(공동)S여수봉산중심국_돌산L-DUF5-AC.55.LTE.DU20(내` → `S여수봉산중심국`
  - `S광주쌍암통합국-01_A-CDUH20(A12).55.5G.CDU20(내)(N…` → `S광주쌍암통합국`
  - `S여수봉산중심국_1-DU30-1.55.LTE W.DU30(내)-WL` → `S여수봉산중심국`
  - `(도서)남면우학W.55.WCDMA.E3R-NODEB(외)` → `남면우학W`
- **집중국** (결정 6): 다듬은 **모국명**에 `집중국`·`통합국`·`중심국`·`전송실` 중 하나가 있으면 그 이름, 없으면 `비SCAN`. `비SCAN`은 항상 이 표기로 만든다.
- **모국(&기지국)** (결정 7): 다듬은 `(LTE)전송로 상위국명`이 있으면 그 값, 없으면 다듬은 모국명. 단 **방식 원본이 `인빌딩`이면 상위국명을 무시하고 모국명을 쓴다**(방식 옵션 `useMokukOnly`로 정하며 기본값은 `인빌딩` 하나다).
- **통합국·중심국 혼용** (결정 8): 모국명이 `S목포옥암통합국`이고 상위국명이 `S목포옥암중심국`처럼 이름만 다르면 같은 건물이라 위치가 같다. LTE는 중심국, 5G는 통합국으로 적는 것이 관행이다. 이런 차이는 경고하지 않는다.

| 사례 | 모국명 → 상위국명 | 모국(&기지국) | 집중국 |
|---|---|---|---|
| 5G 통합국 (수완포레) | `S광주쌍암통합국…` / 없음 | `S광주쌍암통합국` | `S광주쌍암통합국` |
| LTE 중심국 (아트박스) | `S여수봉산중심국…` / 같음 | `S여수봉산중심국` | `S여수봉산중심국` |
| 3G 기지국 (여수남면WMC) | `(도서)남면우학W.55.WCDMA…` / 없음 | `남면우학W` | `비SCAN` |
| 인빌딩 (무안오룡) | `S목포옥암통합국…` / `S목포옥암중심국…` | `S목포옥암통합국` | `S목포옥암통합국` |
| 공동 LTE (돌산무슬목) | `(공동)S여수봉산중심국_돌산L…` / 같음 | `S여수봉산중심국` | `S여수봉산중심국` |

- 인빌딩이 **아닌데** 모국명과 상위국명이 다른 경우(옥상형에서 5G와 LTE가 섞인 경우)는 실제 실사서로 확인하지 못했다. 기존 규칙대로 상위국명을 우선한다(§6).

### 4.6 문제점 세부내역 및 대책방안 (기본 꺼짐)

- **원본**: 본문의 모든 `기타N` 항목(`기타1`, `기타2`, `기타3` … 번호만 붙은 라벨, 오른쪽 값)과 치국현황의 `상세출입방법`·`건물구분`.
- **변환**: 문서에 나오는 순서(일반현황 → 치국현황 → 안전관리 → 엔지니어링 → 공중선계)대로 값이 있는 것만 `/`로 이어 붙인다. 치국현황에서는 `상세출입방법`, `건물구분`이 기타 앞에 온다.
- **기타N 수집 규칙**: 본문(섹션 1~5 및 6의 본문)에서 글자가 `기타` + 숫자(`기타1`, `기타 1`)인 라벨만 대상이다. `기타(…)`처럼 괄호가 붙은 라벨은 제외한다. 오른쪽 칸의 글자가 또 다른 `기타N` 라벨이면 값이 없는 것으로 본다. `현장조사 사진` 줄부터 아래는 읽지 않는다(§4.7).
- 사용자가 지금까지 넣은 값보다 **길어진다**(수완포레 188자 → 324~357자, 아트박스 126자 → 175자, 돌산무슬목 137·149자). 안전관리·엔지니어링·공중선계의 기타까지 모으기 때문이며 의도한 변경이다.
- 사용자가 앞에 쓴 수기 메모를 덮어쓸 수 있어 기본 꺼짐이다.

### 4.7 실사서 읽기 (라벨 찾기)

- 판별: 첫 시트에 `현장조사서`(공백 제거 후)가 있고 A열에 `1. 일반현황`이 있어야 실사서다. 아니면 그 파일을 오류로 표시한다.
- 섹션: A열의 `^\d\.\s`로 시작하는 줄을 경계로 구간을 나눈다.
- 라벨 찾기: 지정한 섹션 안에서 글자가 정확히 같은 칸(공백·줄바꿈 정리 후)을 찾는다. 같은 글자가 여럿이면 순서(`nth`)로 고른다.
- 값 위치: `below`는 라벨 바로 아래 줄의 같은 열, `right`는 라벨의 병합 영역 끝 다음에 오는 같은 줄의 첫 번째 값이 있는 칸.
- 값 정리: 앞뒤 공백·줄바꿈 정리, 빈 문자열은 "값 없음".
- **본문 끝**: `현장조사 사진`(공백 제거 후) 머리글이 있는 줄부터는 사진 이름표 영역이라 읽지 않는다. `기타N`을 모을 때 필수다(§2.5).
- **선택한 파일 걸러내기**: 이름이 `~$`로 시작하는 파일은 엑셀의 임시 잠금 파일이라 건너뛰고 "건너뜀 N개"로 알린다. 확장자가 `.xlsx`가 아닌 파일(PDF 등)도 건너뛴다.
- **메모리와 동시성**: 파일을 읽을 때 섹션·라벨→값 색인만 만들어 보관하고 파싱된 워크북은 바로 놓아준다. 파일은 4개씩 병렬로 읽는다. 한 번에 올리는 파일 수에 상한은 없고 50개를 넘으면 안내 문구만 보인다.
- 파일명의 프로젝트코드·통합시설코드와 셀 값이 다르면 경고한다(셀 값을 쓴다).

### 4.8 환경설정 (관리자만 수정)

샘플로 확인한 규칙은 일부다. 새로운 별칭(`NW구조혁신`→`NW슬림화` 같은 것), 새 표기 형태, 새 국사 단어, 새 방식의 입력 관행은 계속 나온다. 이런 것을 코드를 고치지 않고 관리자가 설정 창에서 바로 추가·수정한다.

#### 4.8.1 설정할 수 있는 것

기본값은 `constants/default-settings.ts`에 있고, 관리자가 바꾼 부분만 DB에 저장한다.

| 구분 | 설정 항목 | 기본값 |
|---|---|---|
| **칸별** | 기본 켜짐/꺼짐 | §4.3의 그룹 규칙 |
| | **치환표**: 원본 값 → 넣을 값 (글자가 정확히 같을 때만, 앞뒤 공백 무시) | 공용화 주관사 `LGT`→`LGU+`, 방식 `인빌딩`→`광분산`, 사업구분 중분류 `NW구조혁신`→`NW슬림화` |
| | 읽는 위치(섹션 번호, 라벨, 방향 below/right) — **2차**(1차에서는 설정 창에 두지 않는다. 코드의 규칙표만 쓴다) | §4.3 규칙표 |
| **방식별 예외** | 방식(원본 값)별 목록: 칸 → 고정값 또는 다른 원본 위치, 방식 옵션 `useMokukOnly` | 인빌딩 3개(철탑 형태 고정값, 장비위치 원본 변경, `useMokukOnly` 켜짐) |
| | **알려진 방식 목록**(목록 밖의 방식 값은 경고) | `광중계기`, `광분산`, `기지국`, `터널`, `인빌딩` |
| **국사** (모국·집중국) | 지울 접두 태그 목록 | `(공동)`, `(도서)` |
| | 자르는 구분 목록(`#`은 숫자 한 자리) | `-##_`, `_`, `.55.` |
| | SCAN 국사 단어 목록 | `집중국`, `통합국`, `중심국`, `전송실` |
| | SCAN이 아닐 때 집중국에 넣을 표기 | `비SCAN` |
| **문제점 세부내역** | 포함 항목: 본문의 모든 `기타N`, `상세출입방법`, `건물구분` 각각 켜기/끄기 | 모두 켜짐 |
| | 항목 사이 구분자 | `/` |
| **주소·지역** | 번지 뒤에 `번지` 자동으로 붙이기 | 켜짐 |
| | 지역 구분 매핑표(주소 첫 단어 → 지역 구분) | `전남광주통합특별시`·`광주`·`전남`→`전남`, `전북…`→`전북`, `제주`·`제주시`·`서귀포시`→`제주` |
| **공중선 형상** | 끝의 `S` 지우기 | 켜짐 |

`사업구분 중분류`의 `NW구조혁신`→`NW슬림화`는 세부 시트에서 대분류 `기존망개선` 2,737행이 모두 `NW슬림화`이고 `NW구조혁신`은 0행이라 기본 치환표에 **넣는다**. 틀렸다고 보면 관리자가 설정 창에서 지운다. 화면에 `치환` 표시가 붙어 조용히 바뀌지는 않는다.

#### 4.8.2 적용 순서

1. 실사서에서 **원본 값**을 읽는다(`lib/parse-survey.ts`). 설정에 영향을 받지 않는다.
2. 칸별 내장 변환을 설정 값으로 적용한다(국사 규칙, 번지 붙이기, S 지우기 등).
3. **방식별 예외 규칙**을 적용한다. 조건은 방식의 **원본 값**(치환 전)으로 판단한다.
4. 칸별 **치환표**를 적용한다(정확히 일치하면 바꾼다).
5. 칸이 꺼져 있으면 결과에서 뺀다.

읽기(1)와 변환(2~5)이 나뉘어 있어서 설정을 바꾸면 이미 올린 파일을 다시 읽지 않고 즉시 다시 계산한다.

#### 4.8.3 권한

- **수정은 관리자만.** 판별은 기존 `useIsAdmin()`(화면)과 DB 함수 `public.is_app_admin()`(쓰기 정책)이다. 화면에서 입력을 숨기는 것만으로 끝내지 않고 **DB 정책이 직접 막는다**(그룹관리와 달리 쓰기 정책을 둔다).
- **읽기는 로그인한 모든 사용자.** 결과를 계산하려면 설정이 필요하다.
- 관리자가 아니면 설정 창을 **읽기 전용**으로 보여 준다(입력 비활성, "관리자만 수정할 수 있습니다" 표시). 어떤 규칙으로 값이 만들어졌는지 확인할 수 있게 하려는 것이다.

#### 4.8.4 저장 (Supabase)

테이블 `public.survey_settings` — 항상 1행.

| 열 | 내용 |
|---|---|
| `id text primary key` | `'default'` 고정(`check (id = 'default')`) |
| `settings jsonb not null` | 기본값과 다른 부분만 담은 설정. 안에 `version`을 둔다 |
| `updated_at timestamptz not null default now()` | 마지막 저장 시각 |
| `updated_by uuid references auth.users` | 마지막으로 저장한 사용자 |

- **RLS**: `ENABLE ROW LEVEL SECURITY`. `SELECT`는 `authenticated` 전체. `INSERT`·`UPDATE`는 `is_app_admin()`일 때만(`USING`과 `WITH CHECK` 모두). `DELETE` 정책은 두지 않는다(삭제 불가). "기본값으로 되돌리기"는 `settings`를 `{}`로 저장하는 것이다.
- **기본값과 다른 부분만 저장**하므로, 코드의 기본값을 고치면 관리자가 건드리지 않은 항목은 자동으로 따라간다.
- **동시 수정**: 저장할 때 불러온 `updated_at`과 같은 행만 갱신한다(`UPDATE … WHERE updated_at = 불러온 값`). 0행이면 다른 관리자가 먼저 저장한 것이므로 거부하고 다시 불러오게 한다.
- **권한 거부와 충돌 구분**: 첫 저장(insert)에서 RLS가 막으면 `42501`이라 `denied`, 같은 키가 이미 있으면 `23505`라 `conflict`로 돌려준다. 갱신(update)이 0행이면 현재 `updated_at`을 다시 읽어 다르면 `conflict`, 같으면 `denied`다.
- **검증**: zod 스키마로 검사한다. 저장 전에 잘못된 값(빈 원본, 중복 원본, 빈 구분 목록 등)은 거부한다. DB에서 읽은 값이 스키마에 안 맞으면 기본값을 쓰고 경고한다.
- 마이그레이션은 `supabase/migrations/20261117000200_survey_settings.sql` 개별 파일로 만든다. **사용자가 Supabase SQL Editor에서 적용한다.** 이 프로젝트는 Supabase를 로컬에서 실행하지 않는다. 적용 전에는 기본 설정으로 동작하고 저장은 막힌다.

#### 4.8.5 설정 창

- 현장실사서 화면 오른쪽 위 **환경설정** 버튼 → 넓은 창(가로 스크롤 없음, 세로 스크롤만).
- 탭 5개: **칸·치환표** / **방식별 예외**(방식마다 `useMokukOnly` 스위치와 규칙, 알려진 방식 목록) / **국사(모국·집중국)** / **문제점 세부내역** / **주소·지역**. 가져오기·내보내기 탭은 2차다.
- 하단: 변경 N건 표시, **저장**, **변경 취소**, **기본값으로 되돌리기**(확인 창을 거친다).
- 치환표는 행 추가·삭제, 원본·넣을 값 두 칸이다. 같은 원본이 두 번 있으면 그 줄에 표시한다.
- **치환 추가 단축**: 결과 표에서 줄을 펼치면 칸별 `원본 → 변환 결과`가 보인다. 관리자에게는 각 칸에 **[치환 추가]** 버튼이 있어, 그 칸과 원본 값을 채운 채 설정 창의 해당 탭을 연다. 새로 나온 표기를 바로 처리할 수 있다.
- **내보내기/가져오기(2차, 1차에서는 만들지 않는다)**: 설정을 JSON 파일로 저장·불러온다(백업과 검토용). 가져오기는 관리자만 하고, 스키마 검증 뒤 "바뀌는 항목 N건"을 보여 준 다음 저장한다.

### 4.10 오류와 경고

| 상황 | 처리 |
|---|---|
| 실사서 양식이 아님 / 읽을 수 없음 | 그 파일만 오류, 나머지는 계속 |
| `~$` 임시 파일, 엑셀이 아닌 파일 | 읽지 않고 건너뜀(오류가 아님), 건너뛴 개수를 알림 |
| 라벨을 못 찾음 | 그 칸은 빈 값, 경고 `라벨을 찾지 못했습니다: …` |
| 변환 불가(지역 구분, 모국명 형식 등) | 원본 또는 빈 값 + 경고 |
| 방식 값이 알려진 방식 목록 밖(빈 값은 제외) | 값은 그대로 내보내고 경고 `알 수 없는 방식 값: …`. 치환표나 알려진 방식 목록에 추가하면 해소된다 |
| 모국명과 상위국명이 이름만 다름(통합국↔중심국) | 경고하지 않는다 |
| 파일명과 셀의 코드 불일치 | 경고, 셀 값 사용 |
| 같은 통합시설코드 중복 | 경고(결과에는 둘 다 넣는다) |
| 설정 테이블이 없음(마이그레이션 미적용) | 기본 설정으로 동작하고, 설정 창에 "마이그레이션이 필요합니다"를 표시한다. 저장은 막는다 |
| 저장된 설정이 스키마에 맞지 않음 | 기본 설정으로 동작하고 화면 위에 경고 배너. 잘못된 항목은 설정 창에서 고치도록 표시 |
| 다른 관리자가 먼저 저장함 | 저장을 거부하고 "다시 불러오세요"를 안내한다(§4.8.4) |

### 4.11 테스트

- **읽기**: 메모리에서 합성 xlsx를 만들어(`XLSX.utils` + 병합) 라벨 찾기를 단위 테스트한다: `below`, `right`, 병합 칸, 섹션 구분, 같은 라벨 여러 개, 라벨 없음.
- **기타N**: 본문의 `기타1·2·3`만 모으고 순서가 문서 순서와 같다 / `기타(OM)` 같은 괄호 라벨 제외 / `현장조사 사진` 아래의 `기타1…`은 제외 / 오른쪽이 다른 `기타N` 라벨이면 값 없음 / 값이 하나도 없으면 빈 문자열 / 상세출입방법·건물구분이 치국현황 기타 앞에 온다.
- **모국·집중국**(표 기반): 5G 통합국, LTE 중심국(`-26_`·`_1-` 두 모양), `(공동)`·`(도서)`·`(공동)(도서)` 접두, `.55.WCDMA…` 꼬리(`(도서)남면우학W.55.WCDMA.E3R-NODEB(외)`→`남면우학W`/`비SCAN`), 전송실이 SCAN으로 나오는 경우, 기지국 이름이 `비SCAN`이 되는 경우, 상위국명이 있을 때·없을 때, 상위국명이 모국명과 다른 경우, 방식이 인빌딩이면 상위국명을 무시하는지(`S목포옥암통합국`), `_`·`-NN_`·`.55.`가 없는 이름, 통합국↔중심국 차이에 경고가 없는지.
- **방식별 예외**: 방식 원본이 `인빌딩`이면 철탑 형태가 고정값이고 장비위치가 `장비설치 층`에서 읽히며 철탑 규격·공중선 형상은 원본값 그대로인지 / `useMokukOnly`가 켜진 방식에서 상위국명을 무시하는지 / 알려진 방식 목록 밖의 값(`인빌딩(광분산)`)에서 경고가 나오고 빈 값에서는 나오지 않는지 / 방식이 `인빌딩`이 아니면 영향이 없는지 / 조건이 **치환 전** 원본으로 판단되는지(방식 칸이 `광분산`으로 치환되어도 예외가 적용된다) / 방식 칸의 치환표 `인빌딩`→`광분산`.
- **주소**: 번지가 `327-6`이면 `번지`를 붙이고 `198-1번지`이면 붙이지 않는다(`번지번지` 금지), 번지가 비면 구주소만.
- **변환 함수**(표 기반, 실제 관찰한 값): `5차`→`26-05`, `1S`→`1`, `LGT`→`LGU+`, 모국명, 지역, Site명(접두 `(공동)`·`(도서)`·`(단독)` 제거, 꼬리 `GIR*`·`PRU*`·`LORA`·`AAUY`·`_이` 제거, 동·층 유지).
- **`build-rows`**: 선택한 칸만 채워지고 열 번호가 세부 시트와 같은지 테스트한다.
- **설정**(순수 함수, `.ts`): 저장된 설정(기본값과 다른 부분만)과 기본값 합치기 / 알 수 없는 키 무시 / 스키마 검증 실패 항목 / 적용 순서(내장 변환 → 방식별 예외 → 치환표) / 같은 원본 중복 / 앞뒤 공백 무시 / `#` 구분자 토큰이 숫자 한 자리와 맞는지 / 접두 태그·SCAN 단어 목록을 바꾸면 모국·집중국 결과가 바뀌는지 / 칸을 끄면 결과에서 빠지는지.
- 설정 창 화면(`.tsx`)은 vitest가 `.tsx`를 실행하지 않으므로 로직을 `.ts`로 빼서 테스트하고, 화면은 사람이 확인한다.
- **정답 대조(수동)**: 사용자 파일(정답 행이 있는 엑셀)을 정답으로 일치율을 계산하는 로컬 스크립트를 돌려 결과를 §8에 기록한다. 실사서 원본은 저장소에 올리지 않는다.
- **권한(수동, 구현 후)**: 마이그레이션 적용 뒤 ① 일반 계정으로 설정 저장이 거부되는지(UI 숨김이 아니라 DB가 막는지), ② 관리자 계정으로 저장되는지, ③ 비로그인은 읽지 못하는지를 SQL 또는 화면으로 확인해 §8에 기록한다.
- 검증: `npx tsc --noEmit`, `npx eslint . --max-warnings=0`, `npm test`.

## 5. 완료 기준

1. 실사서 엑셀 13건이 오류 없이 읽히고 파일마다 한 줄이 나온다.
2. 정답 행이 있는 엑셀에서 "확실" 16개 칸이 일치한다(수완포레·아트박스 9건). 모국(&기지국)·집중국·철탑 형태·장비위치·방식이 §2.4와 같은 일치율로 나온다. 철탑 규격(10/10)·공중선 형상(7/10)은 인빌딩 1건(무안오룡)을 뺀 값이다. 공중선 형상은 수완포레 3건이 `1S`·`3S`로 입력되어 있어 다르게 나오는 것이 정상이다.
3. 돌산무슬목 2건(세부 6747·6748행)에서 값이 만들어진다.

4. 무안오룡(인빌딩)에서 방식 `광분산`, 철탑 형태 `인빌딩`, 장비위치 `1층 EPS_A 실`, 모국·집중국 `S목포옥암통합국`이 나오고, 철탑 규격·공중선 형상은 실사서 원본값이 그대로 나온다.

6. `tsc`·`eslint`·`npm test` 통과, 홈 번들 불변.

10. 화정아이파크 101동 B3층 엑셀을 받으면 같은 방식으로 확인해 §8에 기록한다.

- 관리자가 아닌 사용자에게 설정 창을 **읽기 전용으로 보여 줄지**(기본: 보여 준다).
- **확정(2026-11-13)**: `NW구조혁신`→`NW슬림화`를 기본 치환표에 넣는다(§4.8.1).
- `문제점 세부내역`에 `상세출입방법`·`건물구분`을 계속 넣을지(기본: 넣는다).
- **인빌딩 철탑 규격 `1`, 공중선 형상 `1`**은 기본 규칙에서 **뺐다**(근거 47%·53%, 샘플 1건). 의미(장비 수량 등)와 실사서의 `0`·`OMNI`와의 관계를 확인하면 설정 창에서 켠다. 화정아이파크 엑셀로 한 건 더 확인한 뒤 재검토한다.

## 7. 알려진 한계

- 현재 값을 읽지 않으므로 사용자가 입력해 둔 값과의 차이를 알려 주지 못한다. 칸(열) 단위로 붙여넣어야 기존 값이 지워지지 않는다.
- 실사서 양식이 바뀌면 규칙표를 고쳐야 한다. 라벨을 못 찾으면 경고로 알리므로 조용히 틀리지는 않는다.
- **PDF만 있는 실사서는 처리하지 못한다.** 엑셀을 구해야 한다.
- 설정 저장에는 마이그레이션 SQL을 사용자가 직접 적용해야 한다. 적용 전에는 기본 설정으로 동작하고 저장하지 못한다.
- 치환표는 글자가 **정확히 같은** 값만 바꾼다. 비슷한 표기(띄어쓰기·오타)는 각각 따로 추가해야 한다.
- 방식별 예외 규칙의 조건은 첫 단계에서 **방식 칸 하나**뿐이다. 다른 칸을 조건으로 쓰는 규칙은 지원하지 않는다.
- 인빌딩 규칙은 샘플 1건과 세부 시트 통계에 근거한다. 철탑 규격·공중선 형상은 근거가 약해 기본 규칙에서 뺐고, 운영하며 설정 창에서 다듬는다.
- 방식 값이 변형 표기(예: `인빌딩(광분산)`)로 오면 방식별 예외가 적용되지 않는다. 경고가 나오므로 치환표나 알려진 방식 목록에 추가한다.
