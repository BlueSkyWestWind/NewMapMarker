# 비즈니스 규칙 (Business Rules)

- 제품: **MapMarker Pro** (`0004_NewMapMarker`)
- 문서 버전: **Ver_1.0**
- 최종 갱신: 2026-07-25
- 관련 문서: [PRD](./Ver_1.0_PRD.md) · [USECASE](./Ver_1.0_USECASE.md) · [DATABASE](./DATABASE.md) · [STATE](./STATE.md)

> 이 문서는 **판단 규칙의 단일 진실 원천**이다. 코드와 문서가 다르면 둘 중 하나가 버그다.
> 규칙 ID(`BR-*`)는 테스트 케이스([TEST_CASE](./TEST_CASE.md))와 1:1로 연결된다.

## 1. 그룹핑 (최우선 도메인)

### BR-G01 유효 키 (Effective Group Key)

```
effectiveKey(marker) = marker.group_key ?? lotAddressKey(marker.jibun_address)
```

- 두 마커는 **유효 키가 완전히 같을 때만** 같은 그룹이다.
- 같은 번지라도 `group_key`가 다르면 **별도 그룹**이다.
- `group_key`가 있는 마커와 없는 마커는 (값이 우연히 같지 않은 한) 다른 그룹이다.

**구현 위치**
| 위치 | 입력 형태 |
| --- | --- |
| `lib/address-group.ts::getEffectiveGroupKey` | snake_case row |
| `modals/marker-detail-modal.tsx::getMarkerEffectiveKey` | camelCase marker |

> ⚠️ **동일 규칙이 두 곳에 구현되어 있다(G2).** 한쪽만 고치면 그룹 판정이 화면마다 달라진다. 변경 시 반드시 양쪽을 함께 수정하고, 단일화는 [CR-002](./CHANGE_REQUEST/CR-002.md)에서 처리한다.

### BR-G02 역할 판정

| 그룹 멤버 수 | 역할 구성 |
| --- | --- |
| 1 | **단독** — `parent_marker_id = null` |
| 2 이상 | **대표 1** (`parent = null`) + **SUB N** (`parent = 대표 id`) |

- 그룹당 대표는 **항상 정확히 1개**다(단독 포함). — NFR-11
- SUB의 부모는 **같은 유효 키 안에** 있어야 한다.

### BR-G03 대표 승격 순서 (결정적)

대표가 필요할 때 다음 순서로 **결정적으로** 선정한다.

```
1순위: group_role == '대표' 인 멤버 중 created_at 이 가장 이른 행
2순위: (해당 없으면) 멤버 중 created_at 이 가장 이른 행
```

같은 입력이면 항상 같은 결과가 나와야 한다. 랜덤·현재 시각 의존 금지.

### BR-G04 지도 렌더 조건

```
렌더 대상 = (parent_marker_id == null) OR (detached_visible == true)
```

- 기본은 **번지당 대표 1핀**이다(P2 문제 해결).
- `detached_visible = true`인 SUB만 추가로 개별 핀이 된다.
- 좌표(`lat`/`lng`)가 null이면 조건과 무관하게 렌더하지 않고 "좌표 없음 N건"으로 집계한다. — BR-D03

### BR-G05 분리(Separate) 절차 — 순서가 규칙이다

```
separateLabelGroup(라벨, 선택된 대표)
 ① 남은 번지 그룹을 먼저 재승격한다      ← dangling parent 방지 (NFR-13)
 ② 분리 대상 멤버에 새 group_key 부여 + 사용자가 선택한 대표 지정
 ③ 이동 멤버의 detached_visible = false 로 리셋
```

| 규칙 | 내용 |
| --- | --- |
| BR-G05-a | 분리 그룹의 대표는 **사용자가 직접 선택**한다(자동 선정 아님) |
| BR-G05-b | ①을 ②보다 먼저 수행한다. 순서를 바꾸면 부분 실패 시 잔여 SUB가 이탈한 대표를 가리킨다 |
| BR-G05-c | ②가 실패해도 ①이 끝나 있으므로 **dangling parent는 발생하지 않는다.** 최악의 경우 중복 대표가 남고 다음 재정렬에서 자가 치유된다 |
| BR-G05-d | 분리 직후 새 대표 핀은 원 대표와 **같은 좌표에 겹친다.** 실위치로 드래그하라는 안내 토스트를 반드시 표시한다 |

> ⚠️ 이 절차에는 **트랜잭션이 없다**(G6). 원자화는 [CR-003](./CHANGE_REQUEST/CR-003.md).

### BR-G06 원복(번지로 합치기) 절차

```
mergeSplitGroupToLot()
 ① 분리 그룹 멤버의 group_key 제거 (null)
 ② assignGroupMembers 로 번지 기준 재판정 (BR-G03 적용)
```

| 규칙 | 내용 |
| --- | --- |
| BR-G06-a | 원복 후에도 **단일 대표는 보장**된다 |
| BR-G06-b | 되돌린 분리 대표와 원 번지 대표가 모두 `group_role='대표'`일 수 있다. 이때 **원 번지의 대표가 바뀔 수 있으나** 판정은 결정적이며 정합성에는 무해하다 |

### BR-G07 재업로드·복원 시 그룹 유지

| 함수 | 동작 |
| --- | --- |
| `assignMarkerParentsByLotAddress` | 유효 키 기준 부모 재지정 |
| `applyMarkerRolesFromStoredGroupRole` | 저장된 `group_role`을 반영 |

두 경로 모두 **유효 키 기준**이므로 엑셀 재업로드·백업 복원 후에도 분리 상태가 유지된다(FR-23).

### BR-G08 그룹 경계 재필터 (상세 모달)

상세 모달의 연관 목록은 부모 체인을 따라 멤버를 모은 뒤 **반드시 유효 키로 다시 필터**한다.

- 데이터 이상으로 부모가 그룹 경계를 넘어 있어도 **다른 그룹이 섞이지 않는다**. — NFR-12
- 이 재필터는 방어 로직이지 정상 경로가 아니다. 재필터에서 멤버가 제외되면 데이터 점검이 필요하다([DATABASE §7](./DATABASE.md) 쿼리 ②).

## 2. 마커 데이터

### BR-D01 좌표 유효성

| 규칙 | 내용 |
| --- | --- |
| BR-D01-a | `lat`/`lng` 둘 중 하나라도 null이면 좌표 없음으로 본다 |
| BR-D01-b | 좌표 없음 마커는 목록에는 남고 **지도에만 렌더되지 않는다** |
| BR-D01-c | GPSMAP 입력 좌표는 **한국 영역 범위**를 벗어나면 거부한다(FR-48) |

### BR-D02 태그 정규화

입력이 문자열 / JSON 배열 / 구분자 나열 중 무엇이든 **배열로 정규화**해 `tags` jsonb에 저장한다.

### BR-D03 좌표 없음 집계

사이드바 헤더에 `장비 N건 · 좌표 없음 M건` 형태로 표기한다. 숫자를 생략하지 않는다(DESIGN §5 원칙).

### BR-D04 삭제 파급

마커 삭제 시 `information` · `erp_details`가 **CASCADE로 함께 정리**된다. SUB의 부모가 삭제되면 `parent_marker_id`는 SET NULL 되고, 다음 재판정에서 BR-G03으로 대표가 다시 정해진다.

## 4. 필터

### BR-F01 필터 축

| 모드 | 축 |
| --- | --- |
| 장비 | 연도 · 사업유형 · 색상 · 태그 |
| 축전지 | 용량 · 수량 · 국소명 |

### BR-F02 결합 방식

- 축 **내부**는 OR(선택된 값 중 하나라도 일치)
- 축 **간**은 AND(모든 축을 만족)
- 아무것도 선택하지 않은 축은 필터를 적용하지 않는다

### BR-F03 제외 사유 집계

필터로 걸러진 건수를 **축별로 집계해 표시**한다. 결과 0건은 오류가 아니라 안내 문구로 처리한다.

### BR-F04 기본값 적용 행도 필터 대상

`capacity`/`quantity`가 DB에서 null이라 기본값(600/12)으로 표시된 행도 **필터 대상에 포함**한다(FR-15).

### BR-F05 모드 전환 시 초기화

모드를 바꾸면 필터가 초기화된다. 모드별 축이 달라 유지가 오히려 혼란을 준다.

## 5. 엑셀 입출력

### BR-E01 헤더 검증

필수 헤더가 누락되면 **업로드를 중단**하고 누락 헤더명을 안내한다. 부분 파싱으로 진행하지 않는다.

### BR-E02 지오코딩

| 규칙 | 내용 |
| --- | --- |
| BR-E02-a | 좌표가 없는 행만 주소 지오코딩 대상이다 |
| BR-E02-b | 배치 큐 + 결과 캐시로 동일 주소 재요청을 방지한다 |
| BR-E02-c | 실패한 행은 **좌표 없이 저장**되고 실패 주소 목록으로 보고된다 |

### BR-E03 결과 보고

성공 / 중복 / 실패를 **숫자로** 토스트에 표시한다. 실패 주소 목록을 함께 제시한다.

### BR-E04 위치등록(ERP) 스테이징

| 규칙 | 내용 |
| --- | --- |
| BR-E04-a | 파싱·지오코딩까지 마친 결과를 `stagedErpUpload`에 보관하고 **[적용] 시에만 DB 커밋**한다 |
| BR-E04-b | 미리보기에 **기존 좌표 보존 N건 · 신규 좌표 M건 · 지오코딩 실패 K건**을 표시한다 |
| BR-E04-c | [취소] 시 DB는 변경되지 않는다 |
| BR-E04-d | 스테이징은 persist 대상이 아니다. 새로고침 시 소멸하며 재업로드가 필요하다 |

### BR-E05 기존 좌표 보존

이미 좌표가 있는 마커는 재업로드해도 **좌표를 덮어쓰지 않는다**. 담당자가 드래그로 보정한 위치가 유실되면 안 된다.

### BR-E06 ERP 원본 보존

ERP 79열은 매핑 컬럼과 별개로 **`raw` jsonb에 전량 보존**한다. 포맷이 바뀌어도 재파싱할 수 있어야 한다.

### BR-E07 위치 모드 주소 입력

| 규칙 | 내용 |
| --- | --- |
| BR-E07-a | 줄당 1주소. `이름[Tab]주소` 형식을 지원한다 |
| BR-E07-b | 빈 줄·중복은 제거하고, 이미 표시된 주소는 건너뛴다 |
| BR-E07-c | 추가 후 지도를 추가된 마커에 맞춰 자동 fit 한다 |
| BR-E07-d | 처리 후 입력창에는 **실패한 주소만 남긴다**(즉시 재시도 가능) |
| BR-E07-e | 생성된 마커는 **DB에 저장하지 않는다.** 새로고침 시 소멸한다 |

## 6. 백업 · 복원

### BR-B01 백업 범위

`markers`(`group_key` 포함) · `information` · `erp_details` · `battery_markers` · `battery_specs` 전량.

### BR-B02 parent 재파생

`parent_marker_id`는 백업에 저장하지 않는다. 복원 시 **유효 키 + `group_role`로 재파생**한다.

### BR-B03 구 백업 폴백

`group_key` 열이 없는 구 백업은 null로 읽어 **번지 그룹으로 안전 폴백**한다.

### BR-B04 덮어쓰기 경고

복원은 기존 데이터를 덮어쓴다. 실행 전 백업 선행을 **경고 문구로 명시**한다.

### BR-B05 왕복 무손실

백업 → 복원 후 행 수와 그룹 구조가 동일해야 한다. 릴리스 게이트 항목이다.

## 7. 캡처

### BR-P01 소스 우선순위

```
1순위  /api/kakao-static-map   (KAKAO_REST_API_KEY → 없으면 JS 키 시도)
2순위  /api/map-tile-proxy      (호스트 allowlist)
```

REST 키가 없어도 **캡처는 성공해야 한다**(FR-41).

### BR-P02 정보창 배치

캡처 모드에서는 정보창을 마커에서 떨어뜨려 배치해 **라벨 가림을 방지**한다.

### BR-P03 해상도

격자 분할 캡처 후 스티칭하므로 결과 PNG는 **화면 해상도보다 높아야** 한다.

### BR-P04 부분 실패

격자 조각 일부가 실패하면 **불완전한 이미지를 내려주지 않고** 오류를 안내한 뒤 재시도를 유도한다.
