## 3. 상세 명세

표기: **주 흐름** = 정상 시나리오 · **대안** = 정상 범위 내 분기 · **예외** = 오류 처리

### UC-01 지도 열람 및 모드 전환

| 항목 | 내용 |
| --- | --- |
| 액터 | 열람자 |
| 사전조건 | 없음 |
| 사후조건 | 선택 모드가 `localStorage(map-marker-ui)`에 저장됨 |

**주 흐름**
1. 사용자가 `/`에 접속한다.
2. 시스템이 공개 env를 주입하고 카카오 SDK(`services,clusterer`)를 로드한다.
3. 지도가 기본 중심(35.159542, 126.8526012) · 레벨 6으로 렌더된다.
4. 시스템이 Supabase에서 장비·축전지 마커를 조회해 캐시한다.
5. 사이드바 헤더에 건수 요약("장비 N건 · 좌표 없음 M건")이 표시된다.
6. 사용자가 모드 탭에서 [축전지]를 선택한다.
7. 필터·선택 상태가 초기화되고 축전지 마커만 렌더된다.

**대안**
- 3a. 이전 방문에서 저장된 모드가 있으면 그 모드로 시작한다.
- 6a. 비로그인 상태에서 [위치] 탭은 비활성이며 "로그인 후 이용할 수 있습니다" 툴팁이 뜬다.

**예외**
- 2E. SDK 로드 실패(도메인 미등록/쿼터) → 지도 영역에 오류 안내. **대응: 카카오 JS 키에 배포 도메인 등록.**
- 4E. Supabase 조회 실패 → 오류 토스트, 지도는 빈 상태로 유지.

### UC-02 로그인 / 로그아웃

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사후조건 | 세션 캐시 갱신, 인증 전용 섹션 노출/은닉 |

**주 흐름**

**예외**
- 3E. 자격 증명 오류 → 모달 내 오류 메시지, 모달 유지.

### UC-03 마커 필터링

| 항목 | 내용 |
| --- | --- |
| 액터 | 열람자 |
| 사전조건 | 장비 또는 축전지 모드 |

**주 흐름**

4. 필터별 제외 건수가 집계되어 표시된다.

**대안**
- 2a. [전체 선택] / [전체 해제]로 한 번에 조작한다.
- 2b. 모드를 바꾸면 필터가 초기화된다.

**예외**
- 3E. 결과 0건 → 빈 목록 안내 문구 표시(오류 아님).

### UC-06 마커 상세 조회

| 항목 | 내용 |
| --- | --- |
| 액터 | 열람자 |
| 사전조건 | 마커가 지도 또는 목록에 표시됨 |

**주 흐름**
1. 지도에서 마커를 클릭하거나 목록 항목을 클릭한다.
2. 상세 모달이 열린다(지연 로드).
3. 시스템이 선택 마커의 **유효 키**를 계산하고, 부모 체인으로 연관 마커를 모은 뒤 **유효 키가 일치하는 멤버만** 남긴다.
4. 기본 정보 · 연관 장비 표 · ERP 상세 · GPS 카드가 표시된다.
5. 표의 셀은 줄바꿈 없이 한 줄로 표시된다(가로 스크롤 없음).

**대안**
- 4a. 대표 국소면 SUB 목록이 함께 보이고, 단독이면 자기 자신만 보인다.
- 4b. [로드뷰] 버튼으로 UC-20으로 진행한다.
- 4c. [편집] 버튼으로 UC-07로 진행한다.

**예외**
- 3E. 데이터 이상으로 부모가 그룹 경계를 넘어 있으면(dangling parent) 유효 키 필터가 해당 멤버를 제외해 **다른 그룹이 섞이지 않는다**.

### UC-10 동/구역 그룹 분리 ★핵심

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사전조건 | 로그인 · 같은 번지에 복수 국소가 존재 · `20260723000000_add_group_key.sql` 적용 |
| 사후조건 | 분리 그룹이 별도 `group_key`를 갖고 지도에 독립 대표 핀이 생김 |
| 트리거 | 아파트 동별·공장 구역별로 핀을 나눠 보고 싶을 때 |

**주 흐름**
1. 담당자가 대상 번지의 대표 마커 상세 모달을 연다.
2. 연관 장비 목록에서 동/지하/기타 라벨 단위 그룹을 확인한다.
3. 분리할 라벨을 선택하고 [분리]를 누른다.
4. 시스템이 **분리 그룹의 대표 국소를 직접 선택**하도록 요구한다.
5. 담당자가 대표를 선택하고 확인한다.
6. 시스템이 순서대로 처리한다.
   - ① **남은 번지 그룹을 먼저 재승격**한다(대표 이탈 대비).
   - ② 분리 대상에 새 `group_key`와 선택된 대표를 지정한다.
   - ③ 이동 멤버의 `detached_visible`을 false로 리셋한다.
7. 지도에 분리 그룹의 새 대표 핀이 추가된다.
8. 새 대표 핀은 원 대표와 **같은 좌표에 겹쳐** 표시되며, 실위치로 드래그하라는 토스트가 뜬다.

**대안**
- 8a. 담당자가 새 핀을 드래그해 실제 위치에 배치한다(UC-08).
- 3a. 이미 분리된 그룹은 [번지로 합치기]가 노출된다(UC-11).

**예외**
- 6E1. `group_key` 컬럼이 없으면(마이그레이션 미적용) update가 실패한다. → 현재는 일반 DB 오류 메시지로만 표시된다. **후속 개선(G3): 마이그레이션 파일명 안내 추가.**
- 6E2. ②단계 실패 시 ①이 이미 끝나 있으므로 **잔여 SUB가 이탈 대표를 가리키는 dangling parent는 발생하지 않는다.** 최악의 경우 중복 대표가 남고, 다음 재정렬에서 자가 치유된다.
- 6E3. 다단계 업데이트에 **트랜잭션이 없다**(알려진 제약, Ver_1.1 RPC 원자화 예정).

### UC-11 분리 그룹 원복 (번지로 합치기)

**주 흐름**
1. 분리 그룹의 마커 상세 모달을 연다.
2. [번지로 합치기]를 누른다.
3. 시스템이 해당 멤버들의 `group_key`를 제거한다.
4. `assignGroupMembers`가 번지 기준으로 그룹을 재판정한다.
5. `created_at`이 가장 이른 대표-역할 마커가 대표가 되고 나머지는 SUB가 된다.
6. 지도에서 대표 1핀만 남는다.

**대안**
- 5a. 되돌린 분리 대표와 원 번지 대표가 둘 다 `group_role=대표`일 수 있다. 판정은 결정적이지만 **원 번지 대표가 바뀔 수 있다**(단일 대표 보장은 유지되므로 정합성에는 무해).

### UC-13 장비 엑셀 업로드

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사전조건 | 로그인 · 장비 모드 |
| 사후조건 | `markers` + `information` 행 생성, 지도 반영 |

**주 흐름**
1. [장비 엑셀] 섹션에서 파일을 선택하거나 드롭한다.
2. 시스템이 헤더를 매핑해 행을 파싱한다.
3. 좌표가 없는 행의 주소를 지오코딩 큐로 배치 변환한다(캐시 적용).
4. `markers`·`information`에 저장한다.
5. 유효 키 기준으로 대표/SUB를 재판정한다(**기존 분리 상태 유지**).
6. 성공/중복/실패 건수를 토스트로 보고한다. 실패 주소 목록이 함께 표시된다.
7. 지도와 목록이 갱신된다.

**예외**
- 2E. 필수 헤더 누락 → 업로드 중단 + 누락 헤더 안내.
- 3E. 지오코딩 실패 → 해당 행은 좌표 없이 저장되고 "좌표 없음 N건"으로 집계된다.
- 4E. DB 오류 → 오류 토스트, 부분 저장 가능성 안내.

### UC-15 위치등록(ERP) 업로드 — 미리보기 후 적용

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사전조건 | 로그인 |
| 사후조건 | [적용] 시에만 DB 커밋 |
| 특징 | 파싱·지오코딩까지 끝난 결과를 `stagedErpUpload`에 보관(persist 안 함) |

**주 흐름**
1. 담당자가 ERP 엑셀(79열)을 업로드한다.
2. 시스템이 `markers` · `information` · `erp_details` 행을 만들고 원본 79열을 `raw` jsonb에 담는다.
3. 주소를 지오코딩한다.
4. 미리보기에 요약이 표시된다: **기존 좌표 보존 N건 · 신규 좌표 M건 · 지오코딩 실패 K건**(+실패 주소 목록).
5. 담당자가 내용을 확인하고 [적용]을 누른다.
6. 시스템이 스테이징 데이터를 DB에 커밋하고 지도를 갱신한다.

**대안**
- 5a. [취소] 시 스테이징이 폐기되고 DB는 변경되지 않는다.
- 5b. 새로고침 시 스테이징이 소멸한다(persist 대상 아님) — 재업로드 필요.

**예외**
- 4E. 실패 건수가 과다하면 담당자가 원본 주소를 수정 후 재업로드한다.

### UC-16 위치 모드 주소 다중 입력

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사전조건 | 로그인 · 위치 모드 |
| 사후조건 | 브라우저 전용 임시 마커 생성(**DB 미저장 · 새로고침 시 소멸**) |

**주 흐름**
1. [주소로 위치 찍기] 섹션의 텍스트 영역에 주소를 줄 단위로 붙여넣는다.
2. 시스템이 파싱한다 — 줄당 1주소, `이름[Tab]주소` 형식 지원, 빈 줄·중복 제거.
3. 이미 표시된 주소는 건너뛴다.
4. 지오코딩을 진행하며 진행률을 표시한다.
5. 임시 마커를 생성해 지도에 추가한다.
6. 추가된 마커들에 맞춰 지도 화면이 자동으로 맞춰진다(fit).
7. 성공/중복/실패 결과를 토스트로 보고한다.

**대안**
- 7a. 성공 시 입력창에는 **실패한 주소만 남아** 바로 재시도할 수 있다.

**예외**
- 4E. 전부 실패 → 마커 추가 없이 실패 목록만 표시.

### UC-17 / UC-18 백업 · 복원

**UC-17 백업 — 주 흐름**
1. [데이터 백업/복원] 섹션에서 [백업]을 누른다.
2. 시스템이 `markers`(`group_key` 포함) · `information` · `erp_details` · `battery_markers` · `battery_specs`를 조회한다.
3. 테이블별 시트로 구성된 엑셀 파일이 다운로드된다.

**UC-18 복원 — 주 흐름**
1. [복원]에서 백업 엑셀을 선택한다.
2. 시스템이 시트별로 행을 읽어 각 테이블에 반영한다.
3. `parent_marker_id`는 저장하지 않고 **유효 키 + `group_role`로 재파생**한다.
4. 분리 구조가 재구성되고 지도가 갱신된다.

**대안**
- 3a. `group_key` 컬럼이 없는 **구 백업 파일**은 null로 읽혀 **번지 그룹으로 안전 폴백**된다.

**예외**
- 2E. 시트/헤더 불일치 → 복원 중단 + 안내.
- ⚠️ 복원은 기존 데이터를 덮어쓴다. **실행 전 UC-17로 현재 상태를 백업**할 것.

### UC-19 영역 선택 → 격자 캡처 → PNG 저장 ★핵심

| 항목 | 내용 |
| --- | --- |
| 액터 | 열람자 |
| 사후조건 | 화면 해상도보다 높은 PNG 파일 다운로드 |
| 트리거 | 보고서용 지도 이미지가 필요할 때 |

**주 흐름**
1. 플로팅 컨트롤에서 [영역 격자 자동 캡처]를 누른다.
2. 지도 위에 선택 오버레이가 켜진다.
3. 드래그로 사각 영역을 지정한다(경계 가이드 표시).
4. 캡처 패널에서 옵션을 확인하고 실행한다.
5. 시스템이 영역을 격자로 분할하는 계획(`plan`)을 세운다.
6. 캡처 모드에서 정보창을 마커에서 떨어뜨려 배치한다(겹침 방지).
7. 격자 셀별로 지도를 이동·캡처한다.
   - 우선 **카카오 정적맵**(`/api/kakao-static-map`)으로 시도한다.
   - 실패하면 **타일 프록시**(`/api/map-tile-proxy`)로 폴백한다.
8. 캡처 조각을 한 장으로 스티칭한다.
9. PNG로 다운로드된다.

**대안**
- 7a. `KAKAO_REST_API_KEY`가 없으면 JS 키로 시도 후 실패 시 타일 프록시로 진행한다(**캡처는 여전히 성공**).
- 3a. 선택을 다시 드래그해 영역을 조정한다.

**예외**
- 7E. 프록시가 allowlist 밖 호스트를 요청받으면 거부한다(SSRF 방어).
- 7E2. 허용되지 않은 origin의 요청은 거부한다.
- 8E. 조각 일부 실패 → 오류 안내 후 재시도 유도.

### UC-20 로드뷰 및 촬영일자 확인

**주 흐름**

2. 로드뷰 모달이 해당 좌표로 열린다.

**예외**
- 2E. 해당 지점에 로드뷰가 없으면 안내 문구를 표시한다.
- 3E. 촬영일자 조회 실패 → 로드뷰는 정상 표시하고 일자만 생략한다.

### UC-21 / UC-22 GPSMAP 좌표 변환

| 항목 | 내용 |
| --- | --- |
| 액터 | 담당자 |
| 사전조건 | 로그인 (사이드바 링크는 로그인 시에만 노출) |

**UC-21 단건 — 주 흐름**
1. `/gpsmap`에 진입해 [단건] 모드를 선택한다.
2. 위도·경도를 도/분/초/1-100초 필드로 입력하거나 주소를 입력한다.
3. 시스템이 DMS→10진 변환 후 **한국 영역 유효성**을 검증한다.
4. VWorld 지도에 위치가 표시되고, 로드뷰 패널로 현장을 대조한다.
5. [엑셀 내려받기]로 결과를 저장한다.

**UC-22 일괄 — 주 흐름**
1. [일괄] 모드에서 여러 줄을 붙여넣는다.
2. 시스템이 행 단위로 파싱해 순차 조회한다.
3. 행별 성공/실패가 표에 표시된다.
4. [엑셀 내려받기]로 전체 결과를 저장한다.

**예외**
- 3E. 한국 영역 밖 좌표 → 해당 행을 실패로 표시하고 나머지는 계속 진행한다.

### UC-23 지도 표시 옵션 조정

**주 흐름**

   - 클러스터 on/off, 아이콘 스타일(파이 ↔ 도넛)
   - 지적편집도 on/off
   - 확대/축소(1단계) 또는 줌 슬라이더 드래그
   - [내 위치] / [광주 시청]

3. 클러스터·아이콘 스타일·지적편집도 설정은 다음 방문에도 유지된다.

**예외**
- 1E. 위치 권한 거부 → 안내 토스트, 지도는 유지.

## 5. 핵심 시나리오 (End-to-End)

### S-A 월간 데이터 갱신

```
로그인(UC-02)
  → 백업(UC-17)                        ← 되돌릴 지점 확보
  → ERP 엑셀 업로드 · 미리보기(UC-15)
  → 실패 주소 확인 후 [적용]
  → 필터로 신규 국소 확인(UC-03)
  → 좌표 없는 마커 위치 보정(UC-08)
```

### S-B 아파트 단지 동별 분리

```
대표 마커 상세(UC-06)
  → 동 라벨 그룹 확인
  → [분리] + 대표 선택(UC-10)
  → 겹친 새 대표 핀을 실제 동 위치로 드래그(UC-08)
  → 결과가 잘못됐으면 [번지로 합치기](UC-11)
```

### S-C 보고자료용 지도 이미지

```
필터로 대상만 남기기(UC-03)
  → 클러스터 off · 지적편집도 on(UC-23)
  → 영역 선택 → 격자 캡처(UC-19)
  → PNG 다운로드 → 보고서 삽입
```

### S-D 현장 위치 확인

```
위치 모드 전환(UC-01)
  → 주소 여러 줄 붙여넣기(UC-16)
  → 지도 자동 fit
  → 각 지점 로드뷰로 현장 확인(UC-20)
  → 정밀 좌표가 필요하면 /gpsmap(UC-21)
```
