## 1. 기능 정의

### 1.1 핵심 요구사항

> 작업 당일 국소명 또는 주소를 입력하면 **07시부터 17시까지 1시간 간격으로** 기온·체감온도·습도·바람·강수를 보여주고, 시간대별 작업 가능 여부를 판정한다. 태풍은 발생 시에만 표시한다.

### 1.2 대상 위험 (축전지 수거 작업 기준)

| 위험 | 축전지 수거 작업에서의 구체적 위험 |
| --- | --- |
| **폭염** | 온열질환. 축전지는 중량물이라 운반 시 대사열이 큼. 옥외 함체·옥상·지하 등 통풍 불량 장소 작업 다수 |
| **강수** | 감전(단자·전해액), 젖은 노면 중량물 운반 중 미끄러짐, 차량 적재 중 낙하, 함체 개방 시 내부 침수 |
| **한파** | 한랭질환. 장갑 착용에 따른 그립 저하 → 중량물 놓침, 노면 결빙, 손 감각 저하로 단자 취급 부주의 |
| **강풍** | 옥상·철탑 함체 작업 시 추락, 적재물·공구 낙하, 차량 도어 충격, 함체 도어 급개폐 협착 |
| **태풍** *(조건부)* | 발생 시 강풍·호우 동시 발생, 이동 경로상 국소는 사전 작업 연기 판단 필요 |

## 2. 안전 판정 기준

> **판정 임계값은 전부 `src/features/worksite-weather/constants/thresholds.ts` 한 곳에 상수로 모은다.**
> 한파 하위기준이 향후 확정되면 이 파일만 수정한다. 판정 함수에 숫자를 직접 쓰지 않는다.

### 2.1 폭염 — 법정 기준 (준수 필수)

2025년 6월 1일 시행 개정 산업안전보건법에 따라 폭염·한파 관련 건강장해 예방이 사업주 보건조치 의무에 포함되었으며, '폭염작업'은 **체감온도 31℃ 이상**이 되는 작업장소에서의 장시간 작업으로 규정되었다.

| 체감온도 | 판정 | 조치 내용 |
| --- | --- | --- |
| **31℃ 이상** | 🟡 주의 | 2시간 이상 연속 작업 시 ①온도·습도 조절장치 가동 ②작업시간대 조정 ③적절한 휴식 부여 중 하나 이상 시행 |
| **33℃ 이상** | 🟠 경고 | 2시간마다 20분 이상 휴식 부여가 원칙. 1시간마다 10분 이상 등 현장 여건에 따른 방식도 가능 |
| **35℃ 이상** | 🔴 위험 | 무더위 시간대(14~17시) 옥외작업 중지(불가피한 경우 제외), 담당자 지정 후 건강상태 확인 |
| **38℃ 이상** | ⛔ 중지 | 매시간 15분씩 휴식공간에서 휴식 제공, 무더위 시간대 작업 원칙적 중지 |

> ⚠️ 법령상 기준은 **작업장소에서 실제 측정한 체감온도**다. 본 시스템의 기상청 예보 기반 체감온도는 **작업 계획 수립용 사전 참고값**이며 현장 실측을 대체하지 않는다. 화면과 저장 자료 양쪽에 상시 표기한다.

### 2.2 강풍 — 법정 기준 준용

안전보건규칙 제37조 제1항은 기상상태 불안정 시 작업 중지를, 제383조는 철골작업에 대해 **풍속 10m/s 이상**, 강우량 시간당 1mm 이상, 강설량 시간당 1cm 이상인 경우 작업 중지를 규정한다. 옥상 함체·철탑 등 고소 옥외 작업이 포함되는 축전지 수거는 **제383조 기준을 준용**한다.

| 풍속 | 판정 | 권고 |
| --- | --- | --- |
| 4m/s 미만 | 🟢 양호 | 정상 진행 |
| 4 ~ 7m/s | 🟡 주의 | 적재물 결박 확인, 경량 자재 비산 주의 |
| 7 ~ 10m/s | 🟠 경고 | 고소 작업 지양, 함체 도어 고정, 2인 1조 필수 |
| **10m/s 이상** | ⛔ 중지 | **고소·철탑 작업 중지**(제383조 준용). 지상 작업만 제한적 수행 |
| 강풍주의보·경보 발효 | ⛔ 중지 | 작업 연기 |

> 기상청 강풍주의보 기준은 육상 풍속 14m/s 이상 또는 순간풍속 20m/s 이상이므로, **특보가 없어도 10m/s를 넘을 수 있다.** 특보에만 의존하지 않고 풍속 수치를 직접 판정한다.

### 2.3 강수

| 조건 | 판정 | 권고 |
| --- | --- | --- |
| 강수확률 30% 미만, 강수 없음 | 🟢 양호 | 정상 진행 |
| 강수확률 30~60% | 🟡 주의 | 방수 커버·미끄럼 방지화 준비, 중단 계획 수립 |
| 강수확률 60% 이상 | 🟠 경고 | 옥외 단자 작업 지양, 적재 시 2인 1조 |
| **1시간 강수량 1mm 이상** | ⛔ 중지 | **철골·고소 작업 중지**(제383조). 지상 작업 시 절연장갑 필수 |
| 호우주의보·경보 발효 | ⛔ 중지 | 작업 연기 |
| 강수형태 = 눈/진눈깨비 | 🟠 경고 | 노면 결빙 확인, 운반 동선 제설 후 진행 |
| **시간당 신적설 1cm 이상** | ⛔ 중지 | 제383조 준용 |

### 2.4 한파 — 기상청 기준 준용

한파 하위규칙은 정비 진행 중이므로 기상청 한파특보 및 겨울철 체감온도를 준용한다. **확정 시 상수 파일만 교체할 수 있게 분리해 둔다.**

| 체감온도 | 판정 | 권고 |
| --- | --- | --- |
| 0℃ 이상 | 🟢 양호 | 정상 진행 |
| -5 ~ 0℃ | 🟡 주의 | 방한장구 착용, 온열 휴식 공간 확보 |
| -10 ~ -5℃ | 🟠 경고 | 1시간마다 실내 휴식, 노면 결빙 점검, 그립 확인 후 중량물 취급 |
| -10℃ 미만 또는 한파특보 | ⛔ 중지 | 작업 연기 검토 |

### 2.5 태풍 — 조건부 표시

**평상시에는 화면에 표시하지 않는다.** 아래 조건 중 하나라도 충족될 때만 최상단에 태풍 패널이 노출된다.

| 노출 조건 | 표시 내용 |
| --- | --- |
| 태풍특보(주의보/경보) 발효 | 특보 종류, 발효 시각 |
| 활성 태풍 + 예상 경로가 국내 영향권 | 태풍명·번호, 현재 위치, 중심기압, 최대풍속, 예상 진로, 국소 최근접 예상 시점 |
| 그 외 | **표시 안 함** (DOM에서 완전 제거) |

응답의 `typhoon`이 `null`이면 프론트엔드는 해당 영역을 렌더링하지 않는다.

## 3. 계산 유틸 (TypeScript)

> `tsconfig.json`은 `strict: true`, `noImplicitAny: false`, `strictNullChecks: false`, `target: ES2017`.
> 프로젝트 규약상 **`any` 금지**, 반환 타입 명시, 주석은 **why**만 한글로.

`src/features/worksite-weather/lib/apparent-temp.ts`

```ts
/** 여름철 체감온도(기온 ≥ 25℃) — 기상청 공식. Tw는 Stull 습구온도(라디안 atan). */
export function heatIndexSummer(ta: number, rh: number): number {
  const tw =
    ta * Math.atan(0.151977 * Math.sqrt(rh + 8.313659)) +
    Math.atan(ta + rh) -
    Math.atan(rh - 1.676331) +
    0.00391838 * Math.pow(rh, 1.5) * Math.atan(0.023101 * rh) -
    4.686035;

  return (
    -0.2442 + 0.55399 * tw + 0.45535 * ta - 0.0022 * tw * tw + 0.00278 * tw * ta + 3.0
  );
}

/** 겨울철 체감온도(기온 ≤ 10℃, 풍속 ≥ 1.3m/s) — 기상청 공식 */
export function windChillWinter(ta: number, windMs: number): number {
  const kmh = windMs * 3.6;
  // 공식 적용 범위를 벗어나면 기온을 그대로 쓴다 (외삽 시 비현실적 값이 나옴)
  if (ta > 10 || kmh < 4.8) return ta;

  const p = Math.pow(kmh, 0.16);
  return 13.12 + 0.6215 * ta - 11.37 * p + 0.3965 * p * ta;
}

export type ApparentTempType = "heat" | "cold" | "normal";

export interface ApparentTemp {
  value: number;
  type: ApparentTempType;
}

export function apparentTemp(ta: number, rh: number, windMs: number): ApparentTemp {
  if (ta >= 25) return { value: heatIndexSummer(ta, rh), type: "heat" };
  if (ta <= 10) return { value: windChillWinter(ta, windMs), type: "cold" };
  return { value: ta, type: "normal" };
}
```

`src/features/worksite-weather/lib/wind.ts`

```ts
const DIR16 = [
  "북", "북북동", "북동", "동북동", "동", "동남동", "남동", "남남동",
  "남", "남남서", "남서", "서남서", "서", "서북서", "북서", "북북서",
] as const;

/** 풍향 각도(VEC, deg) → 16방위 — 기상청 변환식 */
export function windDirection(vec: number): string {
  return DIR16[Math.floor((vec + 11.25) / 22.5) % 16];
}

/** 풍속 → 체감 등급 (표시용. 판정은 thresholds.ts 기준으로 별도 수행) */
export function windLabel(ms: number): string {
  if (ms < 4) return "약함";
  if (ms < 9) return "약간 강함";
  if (ms < 14) return "강함";
  return "매우 강함";
}
```

> **습도의 역할**: 같은 기온 31℃라도 습도 50%면 체감 32℃ 수준이지만 습도 80%면 체감 37℃를 넘는다. 습도를 화면에 표시해야 작업자가 체감온도 급등의 원인을 납득한다.

#### C8 수정 — `parseAmount` 안전측 판정

원본은 `"1.0mm 미만"`을 **절반(0.5)** 으로 환산했다. 이는 강수량을 실제보다 낮게 보는 방향이라 **안전 판정 시스템에서 잘못된 보수화**다. 또한 `"30.0~50.0mm"`에서 정규식이 첫 숫자(30)만 잡아 상한을 놓친다.

**판정은 상한값으로, 표시는 기상청 원문 그대로** 분리한다.

`src/features/worksite-weather/lib/parse-amount.ts`

```ts
export interface AmountRange {
  /** 판정에 쓰는 상한값(안전측). "강수없음" = 0 */
  max: number;
  /** 화면에 그대로 노출할 기상청 원문 */
  label: string;
}

/**
 * PCP/SNO 문자열 → 판정용 상한값.
 * 기상청은 "강수없음" / "1.0mm 미만" / "1.0~29.9mm" / "50.0mm 이상" 형태로 반환한다.
 * 위험 판정이므로 범위값은 상한을 채택한다. 단 "미만"은 임계값에 걸리지 않도록 직전값을 쓴다.
 */
export function parseAmount(raw: string | null | undefined): AmountRange {
  const label = (raw ?? "").trim();
  if (!label || label.includes("없음")) return { max: 0, label: "없음" };

  const nums = (label.match(/\d+(?:\.\d+)?/g) ?? []).map(Number);
  if (nums.length === 0) return { max: 0, label };

  // "1.0mm 미만"은 1mm 기준에 걸리면 안 되므로 임계값 직전으로 낮춘다
  if (label.includes("미만")) return { max: Math.max(0, nums[0] - 0.01), label };

  return { max: Math.max(...nums), label };
}
```

### 4.4 단기예보 기준시각 — **C7 로직 버그 수정**

원본 `getVilageBase()`는 **가장 최근 발표시각**을 반환한다. 그런데 단기예보는 발표시각 이후 시간대만 제공하므로, 14시에 조회하면 base=1400 → 15시부터의 예보만 오고 **07~13시 슬롯이 전부 비어버린다.** §4.4 본문("07~17시를 덮으려면 02시 또는 05시 발표분")과 코드가 서로 모순이었다.

07~17시 골격을 보장하려면 **당일 07시 이전 발표분 중 가장 최신**을 고정 선택해야 한다.

`src/features/worksite-weather/lib/kma-base-time.ts`

```ts
export interface KmaBase {
  baseDate: string; // YYYYMMDD
  baseTime: string; // HHmm
}

const PAD = (n: number): string => String(n).padStart(2, "0");

/** Workers는 UTC로 동작하므로 KST(UTC+9) 기준 필드를 직접 만든다. */
function kstParts(now: Date): { y: number; m: number; d: number; h: number; min: number } {
  const kst = new Date(now.getTime() + 9 * 3600 * 1000);
  return {
    y: kst.getUTCFullYear(),
    m: kst.getUTCMonth() + 1,
    d: kst.getUTCDate(),
    h: kst.getUTCHours(),
    min: kst.getUTCMinutes(),
  };
}

function ymdKst(now: Date, dayOffset = 0): string {
  const kst = new Date(now.getTime() + 9 * 3600 * 1000 + dayOffset * 86_400_000);
  return `${kst.getUTCFullYear()}${PAD(kst.getUTCMonth() + 1)}${PAD(kst.getUTCDate())}`;
}

/**
 * 07~17시 골격용 단기예보 기준시각.
 * 최신 발표분을 쓰면 조회 시각 이전 슬롯이 결측되므로,
 * 07시 이전 발표(05 → 02 → 전일 23) 중 이미 제공 중인 것을 고른다.
 */
export function getVilageBaseForToday(now: Date = new Date()): KmaBase {
  const { h, min } = kstParts(now);
  const isPublished = (baseHour: number): boolean =>
    h > baseHour || (h === baseHour && min >= 15); // 발표 +10분 제공, 여유 5분

  if (isPublished(5)) return { baseDate: ymdKst(now), baseTime: "0500" };
  if (isPublished(2)) return { baseDate: ymdKst(now), baseTime: "0200" };
  return { baseDate: ymdKst(now, -1), baseTime: "2300" };
}

const ULTRA_NCST_DELAY_MIN = 40; // 매시 정시 관측 → 약 40분 후 제공

export function getUltraNcstBase(now: Date = new Date()): KmaBase {
  const { h, min } = kstParts(now);
  if (min >= ULTRA_NCST_DELAY_MIN) return { baseDate: ymdKst(now), baseTime: `${PAD(h)}00` };
  if (h === 0) return { baseDate: ymdKst(now, -1), baseTime: "2300" };
  return { baseDate: ymdKst(now), baseTime: `${PAD(h - 1)}00` };
}
```

> ⚠️ **Cloudflare Workers는 UTC로 동작한다.** KST 보정이 없으면 배포 후 `NO_DATA`가 반복된다. `new Date().getHours()`를 직접 쓰는 코드가 하나라도 남으면 안 된다.

### 5.3 격자 변환 (온디맨드)

> ✅ **검증 완료** — 아래 구현으로 순천(70,70)·광주(58,74)·목포(50,67)·여수(73,66)·서울시청(60,127)이 모두 §9 표 및 기상청 공표값과 일치함을 확인했다.

`src/features/worksite-weather/lib/grid.ts`

```ts
export interface KmaGrid {
  nx: number;
  ny: number;
}

/** 기상청 격자 좌표 변환 (Lambert Conformal Conic). 값이 결정적이므로 저장하지 않고 매번 계산한다. */
export function toGrid(lat: number, lng: number): KmaGrid {
  const RE = 6371.00877;
  const GRID = 5.0;
  const SLAT1 = 30.0;
  const SLAT2 = 60.0;
  const OLON = 126.0;
  const OLAT = 38.0;
  const XO = 43;
  const YO = 136;
  const DEGRAD = Math.PI / 180.0;

  const re = RE / GRID;
  const slat1 = SLAT1 * DEGRAD;
  const slat2 = SLAT2 * DEGRAD;
  const olon = OLON * DEGRAD;
  const olat = OLAT * DEGRAD;

  let sn =
    Math.tan(Math.PI * 0.25 + slat2 * 0.5) / Math.tan(Math.PI * 0.25 + slat1 * 0.5);
  sn = Math.log(Math.cos(slat1) / Math.cos(slat2)) / Math.log(sn);

  let sf = Math.tan(Math.PI * 0.25 + slat1 * 0.5);
  sf = (Math.pow(sf, sn) * Math.cos(slat1)) / sn;

  let ro = Math.tan(Math.PI * 0.25 + olat * 0.5);
  ro = (re * sf) / Math.pow(ro, sn);

  let ra = Math.tan(Math.PI * 0.25 + lat * DEGRAD * 0.5);
  ra = (re * sf) / Math.pow(ra, sn);

  let theta = lng * DEGRAD - olon;
  if (theta > Math.PI) theta -= 2.0 * Math.PI;
  if (theta < -Math.PI) theta += 2.0 * Math.PI;
  theta *= sn;

  return {
    nx: Math.floor(ra * Math.sin(theta) + XO + 0.5),
    ny: Math.floor(ro - ra * Math.cos(theta) + YO + 0.5),
  };
}
```

## 7. 화면 설계 — **C12 반영**

### 7.1 표 열 구성

프로젝트 UI 규칙(`.cursor/rules/table-no-wrap.mdc`): **셀 줄바꿈 금지 · 가로 스크롤 금지 · 세로 스크롤 허용.**
원본의 7열은 사이드바 폭에서 줄바꿈을 유발한다. 아래로 조정한다.

| 열 | 내용 | 비고 |
| --- | --- | --- |
| 시각 | `15시` | 경과 슬롯은 회색 |
| 기온/체감 | `32.0 / 36.1` | 한 셀 병합 |
| 습도 | `65%` | |
| 바람 | `서남서 11.2` | 방위+수치 한 셀 (방위만으로는 위험도 판단 불가) |
| 강수 | `60% 1.5mm` | 확률+강수량 한 셀 |
| 판정 | `⛔` | 아이콘만 |

6열 · 전 셀 `whitespace-nowrap` · 표를 담는 컨테이너는 `max-w` 확대로 대응하고 `overflow-x`를 쓰지 않는다.

### 7.3 설계 원칙

## 8. 아키텍처 및 캐싱 — **C5 / C13 수정**

```
[Client]  battery_markers 스토어 검색 → (미HIT 시) Kakao 지오코딩 → lat/lng 확정
   │  fetch('/api/worksite-weather?lat=..&lng=..&workType=..')
   ▼
[Next.js Route Handler on Cloudflare Workers (OpenNext)]
   ├─ guardProxyRequest (origin + rate limit)
   ├─ toGrid(lat, lng)
   ├─ 캐시 조회
   └─ fetch × 3~4 병렬: 단기예보 / 초단기실황 / 초단기예보 / 특보 (+태풍 조건부)
```

Supabase 접근이 서버 경로에 **없다**는 점이 원본과의 핵심 차이다.

### 8.1 캐시 전략 — Cache API 전제 폐기

> ⚠️ **Cloudflare Cache API(`caches.default`)와 `fetch(..., { cf: { cacheTtl } })`는 `*.workers.dev` 도메인에서 동작하지 않는다.** 존 단위 캐시가 없기 때문이다. 현재 배포는 `newmarker.celyoon.workers.dev`이므로, 원본 §8.1의 TTL 표는 **배포 환경에서 전부 무효**가 된다.
> 또한 `open-next.config.ts`가 `defineCloudflareConfig()` 기본값이라 **incremental cache가 구성되어 있지 않아** `unstable_cache`·ISR도 영속되지 않는다.

| 단계 | 방식 | 비고 |
| --- | --- | --- |
| **1단계 (필수)** | **isolate 메모리 캐시** — `proxy-guard.ts`의 `Map` 패턴과 동일 | best-effort. isolate 재활용 구간에서만 유효하지만 연속 조회에는 충분히 효과적 |
| **1단계 (필수)** | **응답 `Cache-Control`** — 브라우저/CDN 재조회 억제 | `roadview-dates` 라우트 선례와 동일 |
| **2단계 (권장)** | **커스텀 도메인 연결** → Cache API 활성화 | 원본 TTL 표를 그대로 적용 가능해짐 |
| 대안 | Workers KV 바인딩 추가 | 무료 쓰기 1,000회/일. 격자 단위 캐싱엔 충분하나 바인딩 추가는 별건 승인 필요 |

**논리 TTL (구현 방식과 무관하게 동일 적용)**

| 캐시 키 | 대상 | TTL | 근거 |
| --- | --- | --- | --- |
| `vilage:{nx}:{ny}:{baseDateTime}` | 단기예보 | **3시간** | 3시간마다 갱신 |
| `ncst:{nx}:{ny}:{baseDateTime}` | 초단기실황 | **50분** | 매시 갱신 |
| `ufcst:{nx}:{ny}:{baseDateTime}` | 초단기예보 | **50분** | 매시 갱신 |
| `warn:156:{10분단위}` | 특보 | **10분** | 실시간성 |
| `typhoon:active` | 태풍정보 | **1시간** | 3시간 간격 발표 |

### 8.2 Cloudflare 제약

| 제약 | 본 기능 소요 | 판단 |
| --- | --- | --- |
| 서브리퀘스트 (무료 50 / 유료 1000) | 3~4건 | 충분 |
| 동시 외부 연결 6개 | 3~4개 병렬 | 여유 적음 — `Promise.all` 묶음을 4개 이하로 유지 |
| **CPU 시간** | 파싱은 배열 1회 순회로 경미 | **⚠️ 착수 전 현재 요금제 확인 필요.** OpenNext Next.js Worker는 SSR 자체가 CPU를 쓰므로 "무료 10ms" 전제는 검증 없이 신뢰할 수 없다 |
| 하루 100,000 요청 | 일 수십 건 예상 | 충분 |

## 11. 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| **예보 체감온도 ≠ 실측 체감온도** | 법적 조치 이행 근거로 오인 | 화면·TBM 자료 양쪽에 상시 고지, 현장 실측 병행 안내 |
| **workers.dev에서 캐시 무효** | KMA 일일 호출 한도 조기 소진 | isolate 캐시로 완화 + 커스텀 도메인 연결 결정 (§8.1) |
| **`getVilageBaseForToday` 오적용** | 오전 슬롯 전량 결측 | 발표시각 경계(02:14/02:16, 05:14/05:16)를 **단위 테스트로 고정** |
| **PCP/SNO 문자열 파싱 누락** | 강수 판정 전면 오류 | `parseAmount()` 필수 적용 + 전 케이스 단위 테스트 |
| **TMP vs T1H 코드 혼동** | 기온 미표시 | 소스별 카테고리 매핑 테이블로 통일 (부록 B) |
| Workers UTC 기준 | `NO_DATA` 반복 | KST 보정 함수 일원화, `getHours()` 직접 사용 금지, **배포 환경에서** 실측 검증 |
| **특보 본문 텍스트 파싱 실패** | 특보 미반영 | 파싱 실패 시 특보를 "확인 불가"로 표기하고 **판정에서 제외하지 않고 보수적으로 경고** |
| 예보 풍속 ≠ 순간풍속 | 강풍 위험 과소평가 | 법정 기준이 순간풍속임을 명시, 예보 풍속 7m/s부터 경고 상향 |
| 국소명 검색 실패 | 사용 포기 | 별칭 다중 등록, 부분일치, 주소·지도 클릭 폴백 |
| **컬럼 추가로 백업 왕복 손실** | 데이터 유실 | `headers.ts`·`full-backup.ts` 동시 갱신 + 왕복 무손실 테스트 |
| 지하·옥상·함체 내부 온도 차이 | 위험 과소평가 | "옥외 기준값" 명시, 밀폐공간 별도 실측 필수 안내 |
| 기상청 API 장애 | 조회 불가 | `verdict: "unknown"` + "판정 불가" 명시 (**임의 추정값 표시 절대 금지**) |
| 한파 하위 기준 향후 확정 | 기준 변경 필요 | 임계값을 `constants/thresholds.ts`로 분리 |
