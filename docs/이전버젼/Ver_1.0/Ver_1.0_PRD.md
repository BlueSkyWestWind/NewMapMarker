- 제품: **MapMarker Pro** — 통신 장비·축전지 국소 지도 관리 웹

- 작성일: 2026-07-25
- 관련 문서: [PLAN](./Ver_1.0_PLAN.md) · [IA](./Ver_1.0_IA.md) · [USECASE](./Ver_1.0_USECASE.md) · [DESIGN](./Ver_1.0_DESIGN.md)

## 1. 제품 개요

카카오맵 위에 **통신 장비 국소**와 **축전지 설치 지점**을 마커로 표시하고,
엑셀 기반 대량 데이터와 함께 관리하는 사내 웹 애플리케이션.

담당자는 ERP에서 내려받은 엑셀을 업로드하는 것만으로 전체 국소를 지도에 올리고,
시설팀별 색상·연도·사업 유형으로 필터링하며, 특정 영역을 고해상도 PNG로 캡처해 보고서에 사용한다.

### 한 줄 정의

> "엑셀로 들어와서, 지도로 보이고, 이미지로 나가는" 국소 관리 도구.

## 2. 대상 사용자

| 페르소나 | 역할 | 주 사용 시나리오 | 권한 |
| --- | --- | --- | --- |
| **시설 담당자** (주 사용자) | 장비 국소 데이터 유지 | 월간 ERP 엑셀 업로드, 마커 위치 보정, 시설팀 지정 | 로그인 |
| **팀 관리자** | 팀 단위 현황 파악 | 팀 색상 필터, 영역 캡처 후 보고자료 작성 | 로그인 |
| **현장 조사자** | 위치 확인 | 위치 모드에 주소 붙여넣기, 로드뷰로 현장 확인 | 로그인 |
| **열람자** | 조회만 | 장비/축전지 마커 조회·필터 | 비로그인 |

## 3. 문제 정의

| # | 문제 | 현행 | Ver_1.0 해결 |
| --- | --- | --- | --- |
| P1 | 엑셀 수천 행을 지도에서 볼 수 없음 | 엑셀 필터로 주소를 눈으로 확인 | 업로드 → 지오코딩 → 즉시 마커 렌더 |
| P2 | 같은 번지에 장비 수십 개 → 핀 겹침 | 마커가 한 점에 뭉쳐 판독 불가 | 번지 그룹핑(대표 1핀) + 필요 시 동/구역 분리 |
| P3 | 보고서용 지도 이미지 확보 어려움 | 화면 캡처 → 해상도 부족 | 영역 선택 → 격자 캡처 → PNG 스티칭 |
| P4 | 현장 위치 확인에 별도 도구 필요 | 카카오맵 앱 별도 실행 | 앱 내 로드뷰 모달 + 촬영일자 |
| P5 | 좌표/주소 상호 변환 수작업 | 외부 사이트 개별 변환 | GPSMAP 단건·일괄 변환기 + 엑셀 내보내기 |
| P6 | 데이터 백업 수단 부재 | DB 접근 권한 필요 | 엑셀 전체 백업·복원 |

## 5. 비기능 요구사항 (NFR)

### 5.1 보안

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| NFR-01 | 외부 지도 리소스 요청은 서버 라우트를 경유하고, 대상 호스트를 **allowlist**로 제한한다 | `proxy-guard` 단위 테스트 |
| NFR-02 | 카카오 **REST 키**는 서버 전용이며 클라이언트 번들에 포함되지 않는다 | `NEXT_PUBLIC_` 접두사 미사용 |
| NFR-03 | 프록시 라우트는 자기 도메인(+`PROXY_ALLOWED_ORIGINS`) origin만 허용한다 | 라우트 가드 |
| NFR-04 | 시크릿은 `.env*`에 두고 커밋하지 않는다 | `.gitignore` |
| NFR-05 | Supabase RLS 정책을 적용한다 | `20260627000001_enable_rls_and_policies.sql` |
| NFR-06 | 사용자 입력을 DOM에 직접 삽입하는 XSS 경로를 만들지 않는다 | 패턴 그렙 검수 |

### 5.2 성능

| ID | 요구사항 | 목표 |
| --- | --- | --- |
| NFR-07 | 홈 First Load 번들 | 현행 482 kB, 회귀 금지 (증가 시 원인 명시) |
| NFR-08 | 무거운 모달은 지연 로드 | `next/dynamic` 적용 |
| NFR-09 | 마커 조회는 캐시하고 중복 요청을 억제 | React Query 키 `["map-marker","markers"]` |
| NFR-10 | 대량 마커(수천 건)에서 지도 조작이 멈추지 않음 | 클러스터러 사용 |

### 5.3 데이터 정합성

| ID | 요구사항 |
| --- | --- |
| NFR-11 | 그룹당 대표는 항상 1개(단독 포함)이며 SUB의 부모는 같은 유효 키 안에 있어야 한다 |
| NFR-12 | 상세 모달의 연관 목록은 부모 체인으로 모으더라도 **유효 키로 재필터**해 그룹 경계를 넘지 않는다 |
| NFR-13 | 그룹 조작 시 재승격을 분리보다 먼저 수행해 dangling parent를 남기지 않는다 |
| NFR-14 | 백업→복원 왕복 시 행 수·그룹 구조가 보존된다 |

> ⚠️ 현재 그룹 조작은 순차 `update` 다단계이며 **트랜잭션 원자성이 없다**. NFR-11~13은 앱 로직 방어에 의존하며, RPC 원자화는 Ver_1.1 과제다.
