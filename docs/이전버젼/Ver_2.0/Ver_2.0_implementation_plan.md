## 0. 목업 해석

제공된 목업의 한글 라벨 일부가 깨져 있었다(`테시보드`, `그룰 관리`, `CCTV 므나미칭`,
`킹스 대미터`, `강소 도가`, `접물 명모드`, `내밫내기`).

### 0.1 좌측 메뉴 라벨 (확정)

사용자 확인을 받은 값이다. **화면 표기는 이 문자열을 그대로 쓴다** — 띄어쓰기 포함.

| 순서 | 라벨 | `NavKey` |
|---|---|---|
| 1 | 대시보드 | `dashboard` |
| 2 | 지도 | `map` |
| 3 | 마커관리 | `markers` |
| 4 | 그룹관리 | `groups` |
| 5 | CCTV | `cctv` |
| 6 | 데이터백업/복원 | `backup` |
| 7 | 설정 | `settings` |

> 「마커관리」·「그룹관리」는 **붙여 쓴다.**
> 「CCTV」는 목업의 "CCTV 모니터링"이 아니라 **`CCTV` 단독**이다.
> 6번은 처음 「데이터분석」이었으나, **이미 있는 기능**인 백업/복원으로 교체했다 —
> 없는 기능을 자리만 잡아 두기보다 실재하는 기능을 올린다.

### 0.2 패널 내부 라벨 (미확정 — 추정값)

좌측 메뉴만 확정받았다. 패널 안쪽 문구는 아직 추정이며 3단계에서 확정한다.

| 목업 표기 | 추정 |
|---|---|
| 정소 설정 / CCTV 실정 | 장소 설정 / CCTV 설정 |
| 킹스 대미터 | 장소 데이터 |
| + 강소 도가 | + 장소 추가 |
| + 접물 명모드 / + 내밫내기 | + 엑셀 업로드 / + 내보내기 |
| 정소 징헤... `68` | 장소 검색... + 건수 배지 |

목업의 지도는 위성 영상이다. 현재 프로젝트는 카카오맵 기반이며 위성/일반 전환 기능이
이미 있으므로 **스킨 차이일 뿐 별도 작업이 아니다.**

## 0.3 개정 요청 (원문)

> 날씨는 대시보드쪽으로 이동을 해줘, 대시보드는 지도위에 그날 작업대상의 내역 및
> 기상정보를 보여 주는 걸로 구성할려고 해

이에 따라 **대시보드는 "준비 중"이 아니라 이번 버전의 실구현 대상**이 된다.
좌측 레일에 별도의 「날씨」 메뉴는 두지 않는다.

### 대시보드 정의

**당일 작업대상 국소별로 "지금 작업해도 되는가"를 한 화면에서 답한다.**

| 요소 | 내용 |
|---|---|
| 작업대상 내역 | 저장된 작업 국소 목록 (이름·주소·작업유형) |
| 기상정보 | 국소별 당일 판정(가능/주의/경고/중지) · 위험요약 · 권장 작업시간대 |
| 지도 연동 | 목록 항목 ↔ 지도 마커 상호 강조, 클릭 시 해당 국소로 이동 |

## 1. 목표

화면의 **껍데기(셸)** 를 목업 구조로 교체하고, 그 위에 **대시보드를 신설**한다.
셸 교체 대상 기능은 배치만 바꾸고 내부 로직은 건드리지 않는다.

- 좌측 상단 브랜드 + 아이콘 네비게이션 레일 신설
- 중앙 설정 패널(카드형) — 세그먼트 탭 + 액션 버튼 + 검색/필터
- 우측 지도 전면 배치
- 상단 전역 검색바 (`Ctrl+K`)

## 2. 현재 구조 (As-Is)

```
app/page.tsx
└ MapMarkerPage
  ├ MapSidebar            aside w-[340px]  ← 좌측 전부를 이것 하나가 담당
  │ ├ header  : AuthHeader · 주소/좌표 통합 변환기 링크
  │ ├ ModeTabs: 장비 | 축전지 | 위치 | 날씨&CCTV      ← 데이터 도메인 전환
  │ ├ body    : (날씨 모드) WorksiteWeatherPanel + CCTV 아코디언
  │ │           (그 외)     Accordion — 주소검색·엑셀·필터·장소검색·마커목록
  │ └ footer  : 백업/복원 아코디언
  ├ KakaoMapCanvas + MapFloatingControls
  └ 모달: Roadview · MarkerDetail · MarkerEdit · CctvVideo
```

| 사실 | 값 |
|---|---|
| 라우트 | `/` (지도), `/gpsmap` (별도 도구) — 사실상 단일 화면 |
| 사이드바 폭 | `340px` 고정 (`map-sidebar.tsx:130`) |
| 화면 전환 축 | `MapMode` = `equipment \| battery \| location \| weather` |
| UI 상태 | Zustand + `persist` (`mode`, `isSidebarOpen`, `isClusteringEnabled`, `markerListFilter` 등) |
| 사이드바 구성 파일 | `components/sidebar/` 12개 |

**핵심 제약**: 현재는 **모드(데이터 도메인)** 가 최상위 전환 축인데,
목업은 **메뉴(기능 영역)** 가 최상위다. 이 축의 재배치가 이번 작업의 본질이다.

## 3. 목표 구조 (To-Be)

```

├ NavRail          w-[200px]  브랜드 + 메뉴 7개
├ WorkPanel        w-[340px]  현재 메뉴에 해당하는 설정 카드
├ TopSearchBar     전역 검색 (Ctrl+K)
```

### 3.0 폭 결정

| 영역 | 값 | 근거 |
|---|---|---|
| `NavRail` | **200px** | 목업 비율. 아이콘 + 최장 라벨(「데이터백업/복원」 9자)이 줄바꿈 없이 들어가야 한다 — 2단계에서 실측 |
| `WorkPanel` | **340px** | 아래 참조 — 목업의 320이 아니라 **기존 값 유지** |

목업 비율만 보면 패널은 320px대다. 그런데 **패널에 들어갈 컴포넌트들이 이미 340px를
전제로 만들어져 있다** (`map-sidebar.tsx:130`의 `w-[340px]`).
`filter-panel.tsx`의 드롭다운은 `min-w-[8rem]`(128px)이라 2개만 나란히 놓아도
여백 포함 320px를 넘기고, `backup-restore-section.tsx`는 `grid-cols-2`다.

320px로 줄이면 **"배치만 바꾸고 내부는 건드리지 않는다"는 이번 작업의 전제가 깨진다** —
섹션 내부 그리드를 하나씩 다시 손봐야 한다. 20px를 아끼려고 회귀 위험을 살 이유가 없다.

폭은 `features/shell/constants.ts` 한 곳에서 상수로 관리하고,
`cctv-video-modal.tsx`·`map-region-capture-panel-view.tsx`가 이 값을 참조하게 한다.
지금은 세 파일에 `340`이 각각 하드코딩돼 있어 한 곳만 고치면 어긋난다.

전체 좌측 점유폭은 `200 + 340 = 540px`. 이 값이 지도 영역의 좌측 오프셋이 된다.

### 3.1 메뉴 ↔ 기존 기능 매핑

| 메뉴 | 이번 버전 처리 | 재사용하는 기존 자산 |
|---|---|---|
| 대시보드 | **신규 구현.** 당일 작업대상 내역 + 기상정보. **기본 진입 화면** | `worksite-weather` 자산 전부 (아래 3.3) |
| 지도 | **표시 설정** — 장비/축전지/**위치** 세그먼트 · 검색 · 필터. 위치 탭은 통합 변환기(§3.6) | `ModeTabs` 재구성, `filter-panel`, `place-search-section`, `gpsmap` |
| 마커관리 | **데이터 관리** — 장소 추가 · 엑셀 업로드 · 내보내기 · 등록 섹션 + 마커 목록 + **필터** | `markers-list-panel`, `filter-panel`, `equipment-excel-section`, `battery-excel-section` |
| 그룹관리 | **비활성**(준비 중 표시) | — |
| CCTV | CCTV 조회 패널 | `cctv-panel` (현재 날씨탭 안) |
| 데이터백업/복원 | **기존 기능 이관** — 전체 백업 · 전체 복원 · 등록 데이터 일괄 삭제 | `backup-restore-section` (현재 사이드바 footer) |
| 설정 | 지도 표시 설정(클러스터링·지적도·위성) | `map-floating-controls` 일부 |

> **지도와 마커관리의 경계**
> 지도는 **무엇을 어떻게 보여줄지**(도메인·검색·필터), 마커관리는 **데이터를 어떻게 바꿀지**
> (추가·업로드·내보내기)를 맡는다. 목업은 두 가지를 지도 패널에 함께 뒀지만,
> 읽기 전용 조작과 데이터 변경을 한 패널에 섞으면 실수로 업로드를 누르는 경로가 생긴다.

`MapMode`의 `weather` 값은 **유지**한다. 대시보드가 이 모드를 쓰는 화면이 된다 —
값을 없애면 `overlay-content.ts`·필터·스토어 초기화까지 손대야 한다.

### 3.2 세그먼트 탭 (목업의 `장소 설정 | CCTV 설정`)

메뉴가 최상위가 되면 모드는 패널 안쪽 세그먼트로 내려간다.
`MapMode`를 없애지 않고 **그대로 유지**한다 — 스토어·쿼리·오버레이가 전부 이 값에 묶여 있어
제거하면 변경 범위가 기능 전체로 번진다.

### 3.3 대시보드가 재사용하는 기존 자산

전부 이미 있고 검증된 것들이다. **새로 만들 것은 화면뿐이다.**

| 자산 | 위치 | 역할 |
|---|---|---|
| `savedWeatherSites: SiteMatch[]` | `store/use-map-marker-store.ts` | 작업대상 목록. `persist` 대상이라 새로고침에도 남는다 |
| `fetchWorksiteWeather(site)` | `worksite-weather/lib/worksite-weather-api.ts` | 10분 TTL 캐시 + 동시요청 중복 제거 |
| `overall` / `hazardSummary` / `recommendedWindows` | `types/weather.ts` | 판정·위험요약·권장 시간대 |
| `VERDICT_ICON` · `VERDICT_LABEL` · `VERDICT_TONE` | `types/weather.ts` | 지도 오버레이와 **표기 통일** (Ver 1.1에서 일원화함) |
| `hazard-summary-list` · `weather-timeline-table` · `typhoon-banner` | `worksite-weather/components/` | 상세 뷰 그대로 사용 |

### 3.4 지도 위 표시 (확정)

> 대시보드에는 마커가 없어야 되고, 내가 작업등록한 것만 마커가 보이고,
> 그에대한 날씨 정보를 보여주면 됨

**일반 마커는 대시보드에 나오지 않는다.** 지도에 뜨는 것은 **작업등록한 국소뿐**이다.

| 대상 | 대시보드에서 |
|---|---|
| 장비·축전지·위치 마커 (DB 전체) | **표시하지 않음** |
| 작업등록 국소 중 **장비** (`savedWeatherSites` ∩ 장비 마커) | **표시** — 이것만 |
| 작업등록 국소 중 **축전지** | **표시하지 않음** (확정) |
| 작업등록 0건 | 지도에 마커 없음 (정상 상태) |

`selectActiveMarkers`(`lib/select-active-markers.ts`)의 날씨 분기를 현재의 "전부 감춤"에서
**`savedWeatherSites`의 id로 장비 마커를 걸러 낸 목록**으로 바꾼다.
Ver 1.1에서 한 번 있다가 제거된 로직이라 되살리는 형태이며,
그 원본도 장비 마커만 걸렀다(`git show 2c6e542`).

#### 축전지 국소를 지도에 올리지 않는다 (2026-08-01 확정)

> 대시보드에서는 축전지 마커를 볼 필요 없음

국소 검색은 장비+축전지를 통합해 후보를 만들므로(`worksite-weather-panel.tsx:95-106`)
`savedWeatherSites`에 축전지 국소가 섞일 수 있다. 그래도 **지도에는 올리지 않는다.**

이 결정의 결과로 **지도 마커 수 ≤ 목록 건수**가 된다. 둘은 같지 않을 수 있다.

- 지도에 뜨는 마커는 **항상 목록에 있는 국소**다 (부분집합 관계는 지킨다).
- 목록은 저장된 국소를 **전부** 보여 준다 — 축전지 국소도 기상 판정은 필요하다.
- 목록 행에서 지도 이동을 눌렀을 때 해당 마커가 없으면 **좌표로만 이동**하고 강조는 생략한다.
  아무 반응 없이 끝나면 고장으로 보인다.

### 3.5 로그인 게이팅 (확정)

> 대시보드와 지도는 로그인 없이도 보여주면 되고 단 지도에 위치 탭은 로그인 해야지만
> 보이도록 해줘 그외 메뉴도 모두 접속을 해야지만 보이도록 설정해줘
> / 메뉴가 안보이도록 해주면됨, CCTV는 보이도록 해줘

**잠긴 메뉴는 비활성이 아니라 목록에서 뺀다.**

| 메뉴 | 비로그인 |
| --- | --- |
| 대시보드 · 지도 · CCTV | **보임** |
| 마커관리 · 그룹관리 · 데이터백업/복원 · 설정 | **숨김** |

- 지도는 열리되 **위치 세그먼트만** 잠근다(🔒). 장비·축전지 조회는 비로그인 가능.
- CCTV는 ITS 공공데이터 **읽기 전용 조회**라 인증을 걸지 않는다.
- 「준비 중」(그룹관리)은 로그인과 별개 상태다. 로그인하면 **보이되 눌리지 않는다.**

**폴백이 필요하다.** 로그아웃 시 보고 있던 화면이 숨김 대상이면 대시보드로,
위치 세그먼트를 보던 중이면 장비로 되돌린다. 이 처리가 없으면 빈 화면이 남는다.

> 메뉴를 숨기므로 **로그인 진입점**이 반드시 보여야 한다.
> 현재 사이드바 상단의 `AuthHeader`를 **레일 하단 계정 영역**으로 옮긴다.

### 3.6 위치 탭 = 주소/좌표 통합 변환기 (통합)

> 주소/좌표 변환기와 위치 탭의 기능을 하나로 합쳐주는 걸로 해줘

기능이 겹친다. `/gpsmap`(745줄)이 사실상 상위 집합이다.

| | `/gpsmap` | 기존 위치 탭 |
| --- | --- | --- |
| 입력 | 주소·상호명·GPS·좌표 | 주소(이름⇥주소) |
| 방식 | 단건 조회 · 일괄 변환 · 엑셀 | 주소 1건 · 엑셀 |
| 결과 | 변환 결과 표 + 엑셀 내려받기 | 지도에 임시 마커 |

합친 뒤 위치 탭 구성: **단건 조회 / 일괄 변환 / 엑셀** 세그먼트 ·
GPS 좌표(도분초) 강제 이동 · 변환 결과 표(완료·조회중·대기·실패) + 엑셀 내려받기.
결과는 **지금 보고 있는 지도에** 임시 마커로 찍힌다 — 화면을 떠났다 돌아올 필요가 없어진다.

**`/gpsmap` 라우트는 유지한다.** 북마크·공유 링크가 있을 수 있고, 변환만 크게 볼 때
전체 화면이 유리하다. 위치 탭과 **같은 컴포넌트를 공유**해 로직은 한 벌만 유지한다.
라우트를 없애면 745줄이 홈 번들에 합류한다(현재 `/gpsmap`은 351 kB로 분리).

> 변환 결과 표는 셀을 줄바꿈하지 않고 **표 상자만 가로 스크롤**한다 (`table-no-wrap`).

### 3.7 도메인별 화면 구성

세그먼트(장비/축전지/위치)를 바꾸면 패널 내용이 함께 바뀐다.
**라벨은 추정하지 않고 현재 사이드바에서 그대로 가져왔다.**

| 화면 | 장비 | 축전지 | 위치 |
| --- | --- | --- | --- |
| 지도 — 필터 | 연도 · 사업구분 · 색상 · 태그 | 색상 · 태그 | 없음 |
| 지도 — 그 외 | 장소 검색 | 장소 검색 | **통합 변환기**(§3.6) |
| 마커관리 — 등록 | 「위치 등록 및 관리」🔒 | 「엑셀로 위치 찍기 (축전지)」🔒 | — (세그먼트 없음) |
| 데이터백업/복원 | (세그먼트 없음 — §3.8) | (세그먼트 없음 — §3.8) | — |

- **연도·사업구분은 장비 전용**이다(`filter-panel.tsx:115`의 `mode === 'equipment'` 조건).
  축전지에도 필요하면 별도 작업이다 — 이번 범위 밖.
- 🔒는 로그인이 필요한 항목(`showAuthenticatedSections`).
- 기존 「주소로 위치 찍기」·「엑셀로 위치 찍기」는 §3.6 통합 변환기에 흡수된다.

### 3.8 데이터백업/복원 — 이동만 한다 (확정)

> 데이터 백업/복구에 **이동**을 하라고 했다

**현재 기능을 그대로 옮긴다. 기능을 더하지 않는다.**

| 옮기는 것 | 현재 위치 | 비고 |
| --- | --- | --- |
| 전체 백업 (`exportFullExcel`) | 사이드바 footer 아코디언 | 장비+축전지 통합 파일 |
| 전체 복원 (`importFullExcel`) | 〃 | 통합 파일 |
| 등록 데이터 일괄 삭제 | 〃 | **축전지 모드에서만 노출** — 현재 동작 유지 |

- **도메인(장비/축전지) 탭을 만들지 않는다.** 백업이 통합 파일 하나라 나눌 대상이 없다.
- **장비 일괄 삭제를 만들지 않는다.** `use-data-backup-actions.ts`에 해당 액션 자체가 없고,
  되돌릴 수 없는 신규 파괴 기능이라 이번 「이동」의 범위가 아니다.
- 삭제 버튼 문구에 **대상과 건수**는 적는다 — "축전지 41건이 모두 지워집니다".
  기능 추가가 아니라 이미 있는 버튼의 표시를 고치는 것이다.

> 초안(2026-08-01)에는 장비·축전지 탭으로 나눠 각 탭에서 백업·복원·삭제를 제공한다고 적혀 있었다.
> 코드 확인 결과 그중 **도메인별 백업·복원과 장비 일괄 삭제는 존재하지 않는 기능**이었다.
> 요청은 이동이었으므로 신설분을 계획에서 뺀다. 도메인별 백업이 필요해지면 별도 버전에서 다룬다.

### 3.9 메뉴 전환 시 상태 보존 (확정)

`setMode`는 모드가 바뀌면 `filters`·선택 마커·`cctvMarkers`·`selectedCctv`를 비운다
(`use-map-marker-store.ts:153`). 대시보드가 `mode: 'weather'`를 쓰므로
**지도 ↔ 대시보드 왕복만으로 필터가 두 번 초기화된다.**

Ver 1.1에서는 사용자가 탭을 직접 눌렀을 때만 일어나 납득됐지만, 메뉴 이동은 빈도가 다르다.
필터를 걸어 두고 날씨를 확인하고 돌아오는 것은 정상 동선이다.

| 경로 | 초기화 |
|---|---|
| 세그먼트를 직접 누름 (장비 ↔ 축전지 ↔ 위치) | **초기화한다** — 도메인이 바뀌면 필터 항목 자체가 다르다 |
| 메뉴 이동 (대시보드 ↔ 지도 ↔ 마커관리 …) | **보존한다** |

스토어에 메뉴 전환 전용 액션(`setActiveNav`)을 두고, 그 경로에서는 `mode`만 바꾸고
초기화는 건너뛴다. `setMode`의 현행 동작은 그대로 둔다 — 세그먼트가 계속 쓴다.

### 3.10 좁은 화면의 영역 캡처 패널

`map-region-capture-panel-view.tsx`는 지도 영역 안에서 `absolute left-4`로 뜨고 폭이 340px다.
좌측 점유가 340 → 540px로 늘면 1024px 화면의 지도 영역이 684 → **484px**가 되어
패널이 지도의 70%를 덮는다.

- 절대배치 기준은 지도 컨테이너(`kakao-map-canvas.tsx:957`의 `relative`)라 **겹침 문제는 없다.**
  오프셋을 더하면 오히려 지도 안쪽으로 밀려 없던 버그가 생긴다.
- 1024px 미만에서 패널 폭을 줄이거나 하단 배치로 전환한다. 6단계 반응형 작업에 포함.

| 작업대상 N개 × 기상 조회 | 국소가 많으면 호출 폭증·기상청 쿼터 소진 | 10분 캐시 활용 + 동시 요청 상한(예: 4) + 순차 채우기 |
| 작업대상이 0개 | 대시보드가 빈 화면 | 추가 방법을 안내하는 빈 상태 화면 필수 |
| 기상 조회 부분 실패 | 한 국소 실패로 전체가 안 뜸 | 행 단위로 실패 표시, 나머지는 정상 렌더 |
