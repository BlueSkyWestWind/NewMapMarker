# Ver_1.1 제품 요구사항 정의서 (PRD)

- 제품: **MapMarker Pro** — 통신 장비·축전지 국소 지도 관리 웹
- 문서 버전: **Ver_1.1**
- 작성일: 2026-07-26
- 이전 버전: [Ver_1.0 PRD](../Ver_1.0/Ver_1.0_PRD.md)
- 관련 문서: [PLAN](./Ver_1.1_PLAN.md) · [IA](./Ver_1.1_IA.md) · [USECASE](./Ver_1.1_USECASE.md) · [DESIGN](./Ver_1.1_DESIGN.md)

---

## 1. 제품 개요

Ver_1.0에서 확립한 "국소를 지도에 놓고 관리한다"에 **"오늘 그 국소에서 작업해도 되는가"** 를 더한다.

| 구분 | Ver_1.0 | **Ver_1.1** |
| --- | --- | --- |
| 핵심 질문 | 국소가 어디에 있고 어떤 장비가 있는가 | + **지금 작업 가능한가** |
| 모드 | 장비 · 축전지 · 위치 | + **날씨** |
| 외부 데이터 | 카카오맵 · VWorld | + **기상청 API 허브** |
| 산출물 | 엑셀 백업 · 지도 캡처 | + **TBM 안전 자료** |

## 2. 대상 사용자

| 액터 | Ver_1.1에서 추가된 관심사 |
| --- | --- |
| **현장 작업자** | 오늘 이 국소에서 몇 시에 작업할 수 있는지. 장갑 낀 손으로 태블릿 조작 |
| **작업 관리자** | 여러 국소를 한 번에 조회해 당일 작업 순서 결정. TBM 자료 배포 |
| **안전관리 담당자** | 법정 기준(폭염·강풍·강수) 충족 여부, 조치 근거 기록 |
| 열람자(비로그인) | 변화 없음 — 지도 조회만 |

## 3. 문제 정의

| # | 문제 | Ver_1.1 대응 |
| --- | --- | --- |
| P1 | 기상청 사이트에서 국소 위치를 매번 찾아 확인해야 함 | 국소명 검색 → 즉시 판정 |
| P2 | 예보는 "기온"만 보여주는데 법정 기준은 **체감온도** | 기상청 공식으로 체감온도 산출 |
| P3 | 폭염특보가 상시 발효 중이라 특보만으로는 판단 불가 | 시간대별 수치 판정 + 특보는 보조 |
| P4 | 오전에 조회하면 오후 시간대 예보가 없음 | 단기예보를 골격으로 07~17시 고정 |
| P5 | 옥상·철탑 작업의 강풍 위험이 지상과 같게 취급됨 | `work_type`으로 판정 강화 |
| P6 | TBM에서 근거 자료를 수기로 작성 | 판정 결과 엑셀 저장 |

## 6. 데이터 요구사항

### 6.1 스키마 변경

| 테이블 | 컬럼 | 타입 | 용도 |
| --- | --- | --- | --- |
| `markers` | `site_alias` | text | 국소 검색용 별칭 (쉼표 구분) |
| `markers` | `work_type` | text | `ground` \| `elevated` |
| `battery_markers` | `site_alias` | text | 동일 |
| `battery_markers` | `work_type` | text | 동일 |

- NULL 허용. NULL = 미분류 → `ground`로 취급.
- 백업 엑셀 열 목록에 포함되어 **왕복 무손실**을 유지한다.
- 마이그레이션 미적용 DB에서도 조회가 깨지지 않아야 한다(optional 읽기).

### 6.2 저장하지 않는 것

| 항목 | 사유 |
| --- | --- |
| 격자 좌표(nx, ny) | Lambert 변환이 수 µs. 저장하면 좌표 수정 시 stale 경로만 생김 |
| 특보 관서(stnId) | 주소 시·도 접두어로 코드에서 판정 |
| 판정 결과 | 시시각각 변함. 캐시는 메모리 TTL로 충분 |
