## 3. 상세 명세

### UC-W01 — 국소 검색해 작업 안전 날씨 조회

| 항목 | 내용 |
| --- | --- |
| **선행조건** | 마커 데이터 로드 완료. 기상청 인증키 설정됨 |
| **트리거** | 사이드바 `날씨` 탭(또는 장비·축전지 탭)의 "국소 작업 안전 날씨" 아코디언에서 검색 |

**주 흐름**

1. 사용자가 국소명(예: `조례국소`)을 입력한다.
2. 시스템이 로드된 마커에서 이름·별칭·주소·최종국소명을 부분일치 검색한다.
3. 후보 목록을 점수순으로 표시하고 **첫 항목을 자동 선택**한다.
4. 선택된 국소로 지도를 이동한다.
5. 좌표를 격자로 변환해 `/api/worksite-weather`를 호출한다.
6. 서버가 단기예보·초단기실황·초단기예보·기상특보를 병렬 조회해 병합한다.
7. 07~17시 11슬롯 타임라인, 종합 판정, 권장 시간대, 위험 요약을 표시한다.

**대체 흐름**

- **6a. 초단기 API 실패** — 단기예보만으로 타임라인을 구성한다. 실황/정밀 배지가 붙지 않을 뿐 기능은 정상.
- **6b. 특보 조회 실패·형식 불일치** — 특보를 비우고 `"기상특보를 확인하지 못했습니다"` 경고를 띄운다. **조용히 "특보 없음"으로 표시하지 않는다.**
- **6c. 일부 슬롯 결측** — 해당 슬롯을 `판정 불가(—)`로 두고 결측 건수 경고를 띄운다.
- **6d. 인증키 미설정·활용신청 누락** — 502와 함께 구분된 안내 문구를 표시한다.

**예외**

- 좌표가 국내 격자 범위 밖 → 400 `"기상청 격자 범위를 벗어난 좌표입니다"`
- 검색 결과 0건 → "등록 국소에 없음 — 주소로 검색" 버튼 노출 (UC-W04)

**사후조건** — 판정 결과가 10분간 캐시된다. 같은 국소 재조회 시 요청이 나가지 않는다.

### UC-W02 — 여러 국소를 한 번에 검색

| 항목 | 내용 |
| --- | --- |
| **트리거** | 검색창에 쉼표·줄바꿈으로 구분된 여러 키워드 입력 |

**주 흐름**

1. 관리자가 `조례, 여수, 광양` 또는 주소 목록을 붙여 넣는다.
2. 시스템이 키워드를 분리해 각각 검색하고 결과를 합친다(중복 제거).
3. `검색 1 / 12건 (3개 키워드)` 형태로 개수를 표시한다.
4. 날씨 모드에서는 **검색된 마커만 지도에 표시**한다.
5. `[이전]`/`[다음]`으로 국소를 순회하며 각각의 판정을 확인한다.

**규칙**

- 시·구 이름만 같고 동·지번이 다른 국소는 과도하게 매칭되지 않아야 한다.
- SUB 국소(`parentMarkerId` 존재 또는 `groupRole = SUB`)는 결과에서 제외한다.

### UC-W03 — 오늘의 작업 국소 저장·순회

**주 흐름**

1. 검색 결과 상태에서 `[오늘의 작업 국소로 저장 (N건)]`을 누른다.
2. 검색어가 비워지고 저장 목록 모드로 전환된다.
3. 헤더에 `🔖 오늘의 작업 국소 (N건)`이 표시된다.
4. 목록에서 국소를 고르거나 `[이전]`/`[다음]`으로 순회한다.
5. 개별 항목의 `✕`로 하나씩 제거하거나 `[전체 삭제]`로 비운다.

**사후조건** — 저장 목록은 `localStorage`에 영속된다(브라우저 재시작 후에도 유지).

**알려진 제약** — 원본 마커가 삭제돼도 저장 목록에 남는다. 동기화 로직은 Ver_1.2 과제.

---

### UC-W04 — 미등록 주소를 지오코딩으로 조회

**주 흐름**

1. 검색 결과가 0건이면 `[등록 국소에 없음 — 주소로 검색]` 버튼이 나타난다.
2. 버튼을 누르면 브라우저 카카오 지오코딩으로 좌표를 얻는다.
3. `matchedBy = geocode`인 임시 국소를 만들어 조회한다.
4. 지도는 마커 선택이 아니라 `placeSearch`로 해당 좌표로 이동한다.

**예외** — 지오코딩 실패 시 `"등록 국소·주소 어느 쪽에서도 찾지 못했습니다"`.

**제약** — 지오코딩 국소는 `workType`을 알 수 없어 항상 `ground`로 판정한다.

---

### UC-W05 — 시간대별 판정 근거 확인

**주 흐름**

1. 타임라인 표에서 각 시간대의 기온/체감·습도·바람·강수·판정을 본다.
2. 행에 마우스를 올리면 판정 사유(`체감온도 36.1℃`, `풍속 11.2m/s (고소작업 가중)`)가 뜬다.
3. 하단 위험 요약에서 4종별 피크값·시각·권고 조치를 확인한다.
4. 경과한 시간대는 회색으로 구분된다.

**규칙**

- 판정 등급 표기는 지도 정보창과 사이드바가 **동일**해야 한다.
- 결측 슬롯은 `—` + "판정 불가". 추정값을 채우지 않는다.

---

### UC-W06 — TBM 자료로 저장

**주 흐름**

1. `[TBM 자료로 저장]`을 누른다.
2. 시스템이 xlsx 모듈을 **그 시점에 내려받는다**(첫 클릭 시 짧은 지연).
3. 국소 정보·종합 판정·권장 시간대·11슬롯 표·위험 요약·특보·고지문을 담은 엑셀을 저장한다.
4. 파일명: `TBM_작업안전날씨_{국소명}_{YYYY-MM-DD}.xlsx`

**대체 흐름** — 모듈 로드 실패 시 토스트로 `"TBM 자료 저장에 실패했습니다"`.

**규칙** — 저장 자료에도 **실측 대체 불가 고지**를 반드시 포함한다.

---

### UC-W07 — 지도 정보창에서 현재 시각 날씨 확인

**주 흐름**

1. 날씨 모드에서 지도의 마커를 클릭한다.
2. 정보창 상단에 날씨 카드가 `조회 중...` 상태로 먼저 뜬다.
3. 조회가 끝나면 현재 시각 슬롯(시각·기온/체감·습도·바람·강수·판정)과 종합 판정이 표시된다.

**규칙**

- 사이드바가 이미 조회한 국소면 **캐시를 재사용**해 요청이 나가지 않는다.
- 정보창을 닫은 뒤 응답이 와도 제거된 DOM을 갱신하지 않는다.

---

### UC-W08 — 태풍 발효 시 작업 연기 판단

**주 흐름**

1. 국소 지역에 태풍특보가 발효 중이면 판정 카드 **위에** 태풍 배너가 나타난다.
2. 종합 판정이 `중지`로 고정되고 권장 시간대가 비워진다.
3. `[태풍 지도/통보문 보기]`로 기상청 진로도·통보문을 확인한다.

**규칙** — 태풍이 없으면 배너 DOM 자체를 만들지 않는다.

**제약** — 진로·중심기압 상세는 미구현(태풍정보 API 미신청). 특보 기반 표시만 제공.

---

### UC-W09 — 위성·레이더 지도 확인

**주 흐름** — 패널 상단 `[위성/레이더 지도]`로 기상청 위성·레이더 화면을 모달에서 확인한다.

**제약** — 외부 사이트 임베드. 실렌더 미검증(Ver_1.2 확인 과제).

## 5. 핵심 시나리오 (End-to-End)

### S1 — 여름철 아침, 당일 작업 계획 수립

```
07:30  관리자가 날씨 탭 진입
       → 저장된 "오늘의 작업 국소" 5건이 지도에 표시됨
07:31  1번 국소(순천 조례) 자동 선택 → 판정 조회
       → 종합 "위험", 권장 07:00~11:00
       → 폭염경보 발효, 13시 이후 체감 33℃ 초과
07:33  [다음]으로 2~5번 국소 순회하며 각각 확인
07:35  [TBM 자료로 저장] → 엑셀 배포
07:40  오전에 고소 국소 2건, 오후에 지상 국소 3건으로 순서 확정
```

### S2 — 현장 도착 후 재확인

```
13:50  작업자가 태블릿에서 해당 국소 검색
       → 14시 슬롯이 "실황" 배지로 갱신됨 (예보보다 체감 1.5℃ 높음)
       → 판정이 경고 → 위험으로 상향
13:52  위험 요약에서 "14~17시 옥외작업 중지" 확인
13:55  관리자에게 보고 후 작업 연기
```

### S3 — 특보 확인 불가 상황

```
09:00  국소 조회
       → 타임라인은 정상, 상단에 ⚠️ "기상특보를 확인하지 못했습니다" 경고
09:01  작업자가 기상청 사이트에서 특보를 직접 확인
```

> 이 경로가 중요하다. 특보 조회가 실패했을 때 **"특보 없음"으로 보이면 안 된다.**
