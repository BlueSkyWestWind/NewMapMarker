## 1. 안전 판정 (BR-W1x) — 최우선 도메인

### BR-W10 · 법정 기준은 임의로 바꾸지 않는다

폭염 임계값(체감 31/33/35/38℃)은 산업안전보건법, 강풍 10m/s·강수 1mm/h·적설 1cm/h는
안전보건규칙 제383조에 근거한다. **코드 상수를 바꾸는 것은 법령 해석 변경이다.**

### BR-W11 · 폭염 (체감온도 기준)

| 체감온도 | 판정 | 조치 |
| --- | --- | --- |
| 31℃ 이상 | 🟡 주의 | 2시간 이상 연속 작업 시 휴식·작업시간대 조정 |
| 33℃ 이상 | 🟠 경고 | 2시간마다 20분 이상 휴식 |
| 35℃ 이상 | 🔴 위험 | 무더위 시간대(14~17시) 옥외작업 중지 |
| 38℃ 이상 | ⛔ 중지 | 매시간 15분 휴식, 원칙적 작업 중지 |

### BR-W12 · 강풍 (제383조 준용)

| 풍속 | 판정 |
| --- | --- |
| 4m/s 미만 | 🟢 양호 |
| 4 ~ 7 | 🟡 주의 |
| 7 ~ 10 | 🟠 경고 |
| **10 이상** | ⛔ 중지 (고소·철탑) |

### BR-W13 · 강수·적설

| 조건 | 판정 |
| --- | --- |
| 강수확률 30% 미만 | 🟢 양호 |
| 30 ~ 60% | 🟡 주의 |
| 60% 이상 | 🟠 경고 |
| **1시간 강수량 1mm 이상** | ⛔ 중지 |
| **1시간 신적설 1cm 이상** | ⛔ 중지 |
| 강수형태 = 눈·진눈깨비 | 🟠 경고 (노면 결빙) |

### BR-W14 · 한파 (기상청 준용)

| 체감온도 | 판정 |
| --- | --- |
| 0℃ 이상 | 🟢 양호 |
| -5 ~ 0 | 🟡 주의 |
| -10 ~ -5 | 🟠 경고 |
| -10 미만 | ⛔ 중지 |

경계값은 **더 엄격한 쪽**에 붙인다 (-5℃는 경고).

### BR-W15 · 고소 작업 가중

`work_type = 'elevated'`이고 풍속이 **주의 기준(4m/s) 이상**이면 강풍 판정을 한 단계 올린다.
무풍 구간까지 올리지는 않는다 — 경보 피로를 만든다.

### BR-W16 · 시간대 판정 = 4종 중 최댓값

폭염·한파·강풍·강수 중 **가장 위험한 것**이 그 시간대의 판정이 된다.
사유는 해당하는 항목을 모두 나열한다.

### BR-W17 · 종합 판정 = 전 시간대 최댓값 + 특보

```
overall = worst(전 슬롯 verdict) ⊕ alertsVerdict(발효 특보)
if (태풍 발효) overall = 'stop'
```

### BR-W18 · 특보 반영 강도는 종류별로 다르다

| 특보 | 반영 | 근거 |
| --- | --- | --- |
| 호우·강풍·대설·태풍·한파 | **stop** | 특보 자체가 작업 중지 사유 |
| 폭염 경보·중대경보 | **danger** | 중지 판단은 체감온도가 주도 |
| 폭염 주의보 | **warning** | 동일 |
| 열대야 | **caution** | 야간 현상. 주간 작업에 직접 적용 곤란 |
| 건조·황사·풍랑 | 등급 미상승 | 작업 위험과 직결되지 않음 |

> **왜 폭염만 낮추는가**: 여름철 전남권은 폭염경보가 상시 발효된다.
> 일괄 "중지"로 처리하면 모든 국소가 ⛔로 표시되어 **경보 자체가 무의미해진다.**
> 폭염은 시간대별 체감온도로 이미 판정하고 있으므로 특보는 보조 신호로 쓴다.

### BR-W19 · 권장 시간대는 배열이다

**아직 지나지 않았고** 판정이 `주의` 이하인 슬롯의 **연속 구간**을 모두 뽑는다.
오전·오후로 갈라지는 경우가 흔하다. 태풍 발효 시에는 빈 배열이다.

## 2. 결측·불확실 처리 (BR-W2x)

### BR-W20 · 추정값을 만들지 않는다 — **최우선 불변식**

| 상황 | 금지 | 대신 |
| --- | --- | --- |
| 예보 슬롯 결측 | 보간·이전값 복사·0 채우기 | `verdict: 'unknown'` + `—` 표시 |
| 특보 형식 불일치 | 빈 목록으로 정상 처리 | `parsed: false` + "확인 불가" 경고 |
| 지역 미상 | 전국 특보 일괄 적용 | 특보 비우고 경고 |
| 기온·습도·풍속 중 하나 결측 | 기본값으로 체감온도 계산 | `apparent: null` |

> 안전 판정에서 **조용히 틀리는 것**이 최악이다. 모르면 모른다고 표시한다.

### BR-W21 · PCP/SNO 문자열은 상한을 채택한다

기상청은 `"강수없음"` / `"1.0mm 미만"` / `"1.0~29.9mm"` / `"50.0mm 이상"` 문자열을 준다.

| 원문 | 판정값 | 이유 |
| --- | --- | --- |
| `강수없음` | 0 | — |
| `1.0mm 미만` | 0.99 | 1mm 기준에 걸리면 안 됨 |
| `1.0~29.9mm` | **29.9** | 범위는 **상한** — 낮은 쪽을 고르면 위험 과소평가 |
| `50.0mm 이상` | 50 | 하한이 최소 보장치 |

표시는 **기상청 원문 그대로**, 판정만 상한값으로 한다.

### BR-W22 · 부분 실패를 전체 실패로 만들지 않는다

초단기실황·초단기예보·특보 조회가 실패해도 단기예보만으로 응답한다.
단, 특보 실패는 반드시 `warnings`에 남긴다.

## 3. 기준시각 (BR-W3x)

### BR-W30 · 단기예보는 07시 이전 발표분을 쓴다

```
05시 발표 (05:15 이후)  →  02시 발표 (02:15 이후)  →  전일 23시 발표
```

**최신 발표분을 쓰면 안 된다.** 14시에 조회할 때 14시 발표를 쓰면 15시부터의 예보만 와서
**07~13시 슬롯이 통째로 빈다.**

### BR-W31 · 시간 계산은 반드시 KST로

Cloudflare Workers는 **UTC**로 동작한다. `getHours()` 같은 로컬시간 API를 쓰면
로컬에서는 통과하고 배포 후에만 `NO_DATA`가 난다.
`toKstParts()`를 통해 `getUTC*`로만 읽는다.

### BR-W32 · 소스 우선순위

| 구간 | 소스 | 배지 |
| --- | --- | --- |
| 현재 시각 이전 | 단기예보 | 경과 (회색) |
| 실황 관측 시각 | 초단기실황 | 실황 |
| 현재 ~ +6시간 | 초단기예보 | 정밀 |
| +6시간 이후 | 단기예보 | 예보 |

**전체 교체가 아니라 항목별 오버레이**다. 초단기에는 `POP`·`SNO`가 없으므로
단기예보 값을 지우면 안 된다.

### BR-W41 · 정규화

공백·하이픈을 제거하고 소문자로 비교한다 (`SC-조례` ↔ `sc 조례` ↔ `sc조례`).

### BR-W42 · 좌표 없는 국소는 제외

기상 조회를 걸 수 없다. 지오코딩 폴백(UC-W04)으로 넘긴다.

### BR-W43 · SUB 국소는 검색 결과에서 제외

`parentMarkerId`가 있거나 `groupRole = SUB`인 마커는 대표가 이미 결과에 있으므로 제외한다.

## 5. 특보 지역 매칭 (BR-W5x)

### BR-W50 · 시·도 체계에 따라 매칭 방식이 다르다

| 시·도 종류 | REG_KO 예 | 규칙 |
| --- | --- | --- |
| 도(道) | `순천시`·`장성군` | REG_KO가 주소에 포함돼야 함 |
| 광역시·특별시 | `광주서부`·`광주동부` | **시·도 일치만으로 해당** |

광역시 특보구역은 시 내부 권역으로 쪼개져 있어 주소(`광주광역시 북구`)와 문자열이 절대 겹치지 않는다.
시·군 규칙만 적용하면 **발효 중인 특보를 놓친다.**

### BR-W51 · 시·도가 다르면 즉시 제외

`경기도 광주시`와 `광주광역시`처럼 이름이 겹치는 지역이 있다. 시·도를 먼저 판정한다.

### BR-W52 · 시·도 축약 표기 매핑

`전라남도 ↔ 전남`은 접미사 제거로 유도되지 않는다(첫 글자 + 셋째 글자).
17개 시·도 명시 매핑을 쓴다.

### BR-W53 · 해제·취소 특보는 제외

`CMD`에 `해제`·`취소`가 포함되면 발효 목록에서 뺀다. 그 외(발표·변경·갱신)는 유효로 본다.

### BR-W54 · 응답은 코드가 아니라 한글이다

`wrn_now_data.php`의 `WRN`/`LVL`/`CMD`는 `폭염`/`경보`/`변경` 같은 **한글 문자열**이다.
기상청 DB 스키마 문서의 코드값(`W`/`1`/`1`)과 다르다. **실응답을 기준으로 한다.**
`LVL`은 `주의`로 오므로 통용 표기 `주의보`로 변환한다.

## 6. 표시 규칙 (BR-W6x)

### BR-W60 · 판정 표기는 단일 소스

아이콘·라벨·색은 `types/weather.ts`에서만 정의한다.
컴포넌트에 다시 정의하면 같은 등급이 화면마다 다른 이름으로 보인다.

### BR-W61 · 실측 대체 불가 고지는 상시 표시

법령상 기준은 **작업장소 실측 체감온도**다. 예보 기반 값은 사전 참고용이다.
화면과 TBM 저장 자료 **양쪽에** 반드시 표기한다.

### BR-W62 · 경과 시간대는 회색으로 표시하되 숨기지 않는다

오전 실적 대조에 쓰인다.

### BR-W63 · 태풍은 조건부 노출

태풍특보 미발효 시 **DOM 자체를 만들지 않는다**.

### BR-W64 · 표는 줄바꿈·가로 스크롤 금지

프로젝트 UI 필수 규칙. 열이 넘치면 열을 합친다(바람 = 방위+수치, 강수 = 확률+강수량).
