| **CR 번호** | CR-001 |

## 1. 배경

`20260723000000_add_group_key.sql`(및 `20260722000000_add_detached_visible.sql`)이 적용되지 않은 DB에서 그룹 분리·동 개별 표시를 시도하면 update가 실패한다.

현재 사용자에게 노출되는 것은 **Supabase의 일반 DB 오류 메시지**뿐이다. 담당자는 원인이 마이그레이션 누락임을 알 수 없고, 개발자 문의로 이어진다.

> UC-10 예외 6E1: "현재는 일반 DB 오류 메시지로만 표시된다. **후속 개선(G3): 마이그레이션 파일명 안내 추가.**"

NFR-18은 이미 "필수 컬럼 부재 시 사용자에게 마이그레이션 파일명을 안내한다"를 요구하고 있으나, Ver_1.0에서 미구현 상태다.

## 2. 문제 재현

```
전제: 20260723000000_add_group_key.sql 미적용 DB
1. 로그인 → 같은 번지에 복수 국소가 있는 대표 마커 상세 열기
2. 동 라벨 선택 → [분리] → 대표 선택 → 확인
3. 결과: "column markers.group_key does not exist" 류의 원문 오류 토스트
   → 담당자가 대응 방법을 알 수 없음
```

## 3. 요구사항

| ID | 요구 |
| --- | --- |
| CR1-R1 | 컬럼 부재로 인한 실패를 **일반 DB 오류와 구분해 감지**한다 |
| CR1-R2 | 사용자에게 **누락된 마이그레이션 파일명**을 포함한 한국어 안내를 표시한다 |
| CR1-R3 | 안내는 조치 방법(관리자에게 마이그레이션 적용 요청)까지 포함한다 |
| CR1-R4 | `group_key`뿐 아니라 `detached_visible` 부재도 동일하게 처리한다 |
| CR1-R5 | 컬럼 부재 상황에서 **부분 갱신을 남기지 않는다** (선행 단계가 이미 커밋된 경우 그 사실을 안내) |
| CR1-R6 | 정상 경로의 오류 메시지 형식은 변경하지 않는다 |

## 4. 제안 동작

**대상 컬럼 맵**

| 컬럼 | 마이그레이션 파일 |
| --- | --- |
| `group_key` | `20260723000000_add_group_key.sql` |
| `detached_visible` | `20260722000000_add_detached_visible.sql` |

**메시지 예시**

```
그룹 분리에 필요한 컬럼(group_key)이 데이터베이스에 없습니다.
마이그레이션 20260723000000_add_group_key.sql 적용이 필요합니다.
관리자에게 적용을 요청한 뒤 다시 시도해 주세요.
```

**감지 방식(권장)**

- Supabase 오류의 코드/메시지에서 **컬럼 부재 유형**을 판별한다.
- 컬럼명 → 마이그레이션 파일명 매핑 테이블을 상수로 둔다.
- 매핑에 없으면 기존 일반 오류 메시지로 폴백한다.

## 5. 변경 범위

| 영역 | 변경 |
| --- | --- |
| 신규 | 컬럼↔마이그레이션 매핑 상수 + 오류 해석 유틸 |
| 수정 | 그룹 조작 경로의 오류 처리 (`marker-detail-modal` 및 데이터 접근 계층) |
| 수정 | 동 개별 표시 토글 오류 처리 |
| 문서 | [DATABASE §3.3](../DATABASE.md) · [API §6.3](../API.md) · CHANGELOG |
| 테스트 | TC-X05 기대값 갱신 + 유틸 단위 테스트 추가 |

**변경하지 않는 것**: 그룹 판정 로직, DB 스키마, 마이그레이션 파일 자체.
