## 1. 전환 축의 이동

Ver_1.1까지는 **모드(데이터 도메인)** 가 최상위였다. Ver_2.0은 **메뉴(기능 영역)** 를 최상위로 올린다.

```
Ver_1.1   [장비][축전지][위치][날씨&CCTV]  ← 사이드바 상단 4탭이 화면 전부를 결정
Ver_2.0   메뉴 7종(레일)  →  패널 안에서 [장비][축전지][위치] 세그먼트
```

**`MapMode`는 제거하지 않는다.** 스토어·쿼리·오버레이·필터가 전부 이 값에 묶여 있어,
없애면 변경 범위가 기능 전체로 번진다. `weather` 값도 유지하며 **대시보드가 쓰는 모드**가 된다.

## 3. 네비게이션 구조

### 3.1 메뉴 정의

라벨은 **사용자 확인을 받은 문자열 그대로** 쓴다 (계획서 §0.1). 띄어쓰기 포함.

| 순서 | 라벨 | `NavKey` | 상태 | 비로그인 |
| --- | --- | --- | --- | --- |
| 1 | 대시보드 | `dashboard` | 신규 구현 · **기본값** | 보임 |
| 2 | 지도 | `map` | 재배치 | 보임 |
| 3 | 마커관리 | `markers` | 재배치 | **숨김** |
| 4 | 그룹관리 | `groups` | **준비 중**(비활성) | **숨김** |
| 5 | CCTV | `cctv` | 재배치 | 보임 |
| 6 | 데이터백업/복원 | `backup` | 재배치 (**이동만** — §4.4) | **숨김** |
| 7 | 설정 | `settings` | 재배치 | **숨김** |

- 「마커관리」·「그룹관리」는 **붙여 쓴다**. 「CCTV」는 단독 표기다.
- 「준비 중」(그룹관리)은 로그인과 별개 상태다 — 로그인하면 **보이되 눌리지 않는다**.

### 3.2 `activeNav` ↔ `mode` 관계

메뉴 전환이 모드를 강제하는 경우와 그렇지 않은 경우를 구분한다.

| `activeNav` | `mode` |
| --- | --- |
| `dashboard` | `weather` 고정 — 지도 마커 규칙이 이 값에 묶여 있다 (§8) |
| `map` | 세그먼트로 사용자가 선택 (`equipment` / `battery` / `location`) |
| `markers` | 세그먼트 없음. 직전 도메인 유지 (`location` 제외) |
| `cctv` · `settings` | 관여 안 함 |
| `backup` | 세그먼트 없음. 직전 도메인 유지 — 삭제 버튼 노출 조건이 `mode`에 걸려 있다 (§4.4) |

**메뉴 전환은 필터를 보존한다** (계획서 §3.9 확정).

`setMode`는 모드가 바뀌면 `filters`·선택 마커·`cctvMarkers`를 비운다(`use-map-marker-store.ts:153`).
대시보드가 `mode: 'weather'`를 쓰므로 메뉴가 이 함수를 그대로 호출하면
지도↔대시보드 왕복만으로 필터가 두 번 날아간다.

| 경로 | 초기화 |
| --- | --- |
| 세그먼트를 직접 누름 | **한다** — 도메인이 바뀌면 필터 항목 자체가 다르다 |
| 메뉴 이동 | **안 한다** — `setActiveNav`가 `mode`만 바꾼다 |

`setMode`의 현행 동작은 그대로 둔다. 세그먼트가 계속 쓴다.

## 4. 화면별 패널 구성

### 4.1 지도 (`map`) — 표시 설정

**무엇을 어떻게 보여줄지**만 담당한다. 데이터를 바꾸는 조작은 마커관리로 분리했다.

| 세그먼트 | 필터 | 그 외 |
| --- | --- | --- |
| 장비 | 연도 · 사업구분 · 색상 · 태그 | 장소 검색 · 위치 찾기 |
| 축전지 | 색상 · 태그 | 장소 검색 · 위치 찾기 |
| 위치 🔒 | 없음 | **주소/좌표 통합 변환기** (§9) · 임시 위치 목록 |

> **연도·사업구분은 장비 전용**이다 — `filter-panel.tsx:115`가 `mode === 'equipment'`로 분기한다.
> 축전지에 필요하면 별도 작업이며 이번 범위 밖이다.

### 4.2 마커관리 (`markers`) — 데이터 관리

세그먼트를 두되 **위치는 제외**한다(위치는 지도 전용).

| 구역 | 내용 |
| --- | --- |
| 등록 (장비 🔒) | 「위치 등록 및 관리」 — `EquipmentExcelSection` + `EquipmentInfoSection` |
| 등록 (축전지 🔒) | 「엑셀로 위치 찍기 (축전지)」 — `BatteryExcelSection` |
| 목록 | `MarkersListPanel` |
| 필터 | `FilterPanel` — 지도와 **같은 컴포넌트·같은 스토어 필터**를 공유 |

> 필터를 양쪽에 두는 것은 중복이 아니라 **같은 상태의 두 진입점**이다.
> 목록을 보며 거르는 흐름과 지도를 보며 거르는 흐름이 다르다.

### 4.3 CCTV (`cctv`)

`CctvPanel` 그대로. **인증을 걸지 않는다** — ITS 공공데이터 읽기 전용 조회다.
CCTV 영상 모달은 지금처럼 `MapMarkerPage`가 소유한다(패널이 언마운트돼도 지도 마커는 남는다).

### 4.4 데이터백업/복원 (`backup`) — 이동만

계획서 §3.8 확정. **`BackupRestoreSection`을 사이드바 footer에서 메뉴로 옮기기만 한다.**

| 구역 | 내용 |
| --- | --- |
| 공통 | **전체 백업 · 전체 복원** — 장비+축전지 통합 파일 (`exportFullExcel` / `importFullExcel`) |
| 일괄 삭제 | **축전지에서만 노출** (`deleteAllBatteryMarkers`) — 현재 동작 그대로 |

- **도메인 탭을 만들지 않는다.** 백업이 통합 파일 하나라 나눌 대상이 없다.
- **장비 일괄 삭제를 만들지 않는다.** 액션 자체가 없고, 되돌릴 수 없는 신규 파괴 기능이다.
- 삭제 버튼 문구에 대상과 건수는 적는다 — "축전지 41건이 모두 지워집니다". 표시 수정이지 기능 추가가 아니다.

> 현재 이 섹션은 `mode` prop을 받아 축전지일 때만 삭제 버튼을 낸다.
> 백업 메뉴에는 세그먼트가 없으므로 **어떤 `mode` 값을 넘길지**가 이동 시 유일한 판단 지점이다.
> 직전 도메인을 그대로 넘긴다(§3.2 `markers`와 같은 규칙).

### 4.5 설정 (`settings`)

클러스터링 · 클러스터 아이콘 스타일 · 지적도 · 위성 — 현재 `MapFloatingControls`가 가진 표시 설정.
플로팅 컨트롤을 없앨지 병존시킬지는 3단계에서 결정한다(지도를 보며 즉시 토글하는 흐름이 있다).

### 4.6 그룹관리 (`groups`)

`ComingSoon` 안내만. 기능 신설은 이번 범위 밖이다.

## 5. 대시보드 (신규)

### 5.1 정의

**당일 작업대상 국소별로 "지금 작업해도 되는가"를 한 화면에서 답한다.**

| 요소 | 내용 | 출처 |
| --- | --- | --- |
| 작업대상 내역 | 국소 이름 · 주소 · 작업유형 | `savedWeatherSites` (persist) |
| 기상정보 | 판정(가능/주의/경고/중지) · 위험요약 · 권장 작업시간대 | `fetchWorksiteWeather(site)` |
| 지도 연동 | 목록 ↔ 마커 상호 강조, 클릭 시 해당 국소로 이동 | `setSelectedMarkerId` · 지도 `panTo` |

### 5.2 화면 구조

```
┌─────────────────────────────────────────┐
│ 오늘의 작업 국소 (N건)      [전체 삭제]  │
├─────────────────────────────────────────┤
│ 🔴 조례국소                  중지        │  ← 행 = WorksiteRow
│    전남 순천시 조례동 123-4 · 옥상·철탑  │
│    폭염 36.1℃(15시) · 강풍 11.2m/s      │
│    권장 07:00~11:00                     │
├─────────────────────────────────────────┤
│ 🟢 매곡국소                  양호        │
│    …                                    │
├─────────────────────────────────────────┤
│ ⚠️ 덕진국소 — 조회 실패 [다시 시도]      │  ← 행 단위 실패
├─────────────────────────────────────────┤
│ [선택 국소 상세]                         │

```

작업대상 0건이면 **빈 상태 화면**으로 대체한다 — 목록·상세 대신 등록 방법 안내.

### 5.3 조회 정책

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 캐시 | 기존 10분 TTL 모듈 캐시 그대로 | `worksite-weather-api.ts` — 지도 오버레이와 **공유** |
| 동시 요청 상한 | **4** | 국소가 많을 때 기상청 쿼터 소진 방지 |
| 채우기 방식 | 순차 채우기 — 도착한 행부터 렌더 | 전체 대기 시 빈 화면이 길어진다 |
| 부분 실패 | **행 단위로 표시**, 나머지는 정상 렌더 | 한 국소 실패로 전체가 죽지 않게 |

## 6. 상태 구조

### 6.1 Zustand 신규 필드

| 필드 | 타입 | persist | 용도 |
| --- | --- | --- | --- |
| `activeNav` | `NavKey` | **✓** | 현재 메뉴. 기본값 `'dashboard'` |
| `setActiveNav` | 액션 | — | 메뉴 전환. `mode`만 바꾸고 필터는 보존 (§3.2) |

> `weatherSearchMarkerIds`는 2026-08-01에 **제거됐다.** 소비처가 없는 쓰기 전용 상태였다
> (구조 점검 M-1). Ver_1.1 IA §7.1의 설명은 더 이상 유효하지 않다.

**현재 persist 대상** (`partialize`): `mode` · `isClusteringEnabled` · `clusterIconStyle` · `isCadastralMode` · `savedWeatherSites`.
여기에 `activeNav`를 더한다.

> persist된 값이 **숨김 대상 메뉴**로 복원될 수 있다. 복원 직후 로그인 상태로 검증해
> 접근 불가면 `dashboard`로 보정한다(§7.2).

### 6.2 대시보드 로컬 상태 (파생 우선)

```
상태:  selectedSiteId · weatherById(Map<siteId, 조회상태>)
파생:  sites          = savedWeatherSites
       selectedSite   = sites.find(id === selectedSiteId) ?? sites[0] ?? null
       counts         = sites.length
```

> Ver_1.1에서 선택 국소를 `useState` + `useEffect`로 관리하다 사용자의 선택이
> 첫 항목으로 되돌아가는 문제가 있었다(Ver_1.1 IA §7.2). 같은 실수를 반복하지 않는다.

### 6.3 캐시 계층 (Ver_1.1 승계, 변경 없음)

| 계층 | 위치 | TTL |
| --- | --- | --- |
| 클라이언트 모듈 캐시 + 중복제거 | `worksite-weather/lib/worksite-weather-api.ts` | 10분 |
| TanStack Query | `use-worksite-weather` | staleTime 10분 |
| 서버 isolate 메모리 캐시 | `worksite-weather/lib/kma-client.ts` | 소스별 10분~3시간 |

대시보드는 새 캐시를 만들지 않고 **이 계층을 그대로 탄다**. 지도 오버레이와 같은 캐시를 공유해야
같은 국소가 지도와 목록에서 다른 값으로 보이지 않는다.

## 7. 권한 매트릭스

### 7.1 노출 규칙

**잠긴 메뉴는 비활성이 아니라 목록에서 뺀다.**

| 대상 | 비로그인 | 로그인 |
| --- | --- | --- |
| 대시보드 · 지도 · CCTV | ✅ 보임 | ✅ |
| 마커관리 · 그룹관리 · 데이터백업/복원 · 설정 | **숨김** | ✅ (그룹관리는 준비 중) |
| 지도 — 장비 · 축전지 세그먼트 | ✅ | ✅ |
| 지도 — 위치 세그먼트 | 🔒 잠김 | ✅ |
| 대시보드 기상 조회 · TBM 저장 | ✅ | ✅ |
| CCTV 조회 | ✅ | ✅ |

> 메뉴를 숨기므로 **로그인 진입점이 반드시 보여야 한다.**
> `AuthHeader`를 사이드바 헤더에서 **레일 하단 계정 영역**으로 옮긴다.

### 7.2 폴백 규칙

로그아웃 시 처리가 없으면 빈 화면이 남는다.

| 상황 | 처리 |
| --- | --- |
| 보고 있던 메뉴가 숨김 대상이 됨 | `activeNav = 'dashboard'` |
| 위치 세그먼트를 보던 중 로그아웃 | `mode = 'equipment'` (현재 `map-sidebar.tsx:90`의 로직을 레일/패널로 이관) |
| persist 복원값이 접근 불가 메뉴 | 마운트 후 검증하여 `dashboard`로 보정 |

> 판정은 **마운트 이후**에 한다. `useHasMounted` 없이 하면 SSR 결과와 어긋나 하이드레이션이 깨진다.

## 8. 지도 마커 표시 규칙

| `activeNav` / `mode` | 지도에 뜨는 것 |
| --- | --- |
| 대시보드 (`weather`) | **작업등록 국소 중 장비 마커만** (축전지 국소 제외 — 계획서 §3.4 확정) |
| 지도 — 장비 | 장비 마커 (DB + pending) |
| 지도 — 축전지 | 축전지 마커 (DB + pending) |
| 지도 — 위치 | 임시 위치 마커 (`pendingLocationMarkers`) |
| 마커관리 | 직전 도메인의 마커 유지 |

**현재** `lib/select-active-markers.ts`의 `weather` 분기는 `return []` — 전부 감춘다.
이것을 **`savedWeatherSites`의 id로 장비 마커를 걸러 낸 목록**으로 바꾼다.
(이 함수는 2026-08-01에 `use-active-markers`에서 순수함수로 추출됐고 테스트 10건이 붙어 있다.)

- 작업등록 0건이면 마커 없음이 **정상 상태**다.
- **지도 마커 수 ≤ 목록 건수**다. 축전지 국소는 목록에만 나온다.
  마커가 없는 국소를 클릭하면 좌표로 이동만 하고 강조는 생략한다.

## 9. 위치 세그먼트 = 주소/좌표 통합 변환기

`/gpsmap`(745줄)이 기존 위치 탭의 상위 집합이라 하나로 합친다.

| | `/gpsmap` (현재) | 기존 위치 탭 (현재) |
| --- | --- | --- |
| 입력 | 주소 · 상호명 · GPS · 좌표 | 주소 (이름⇥주소) |
| 방식 | 단건 조회 · 일괄 변환 · 엑셀 | 주소 1건 · 엑셀 |
| 결과 | 변환 결과 표 + 엑셀 내려받기 | 지도에 임시 마커 |

**통합 후 위치 세그먼트**: 단건 조회 / 일괄 변환 / 엑셀 세그먼트 · GPS 좌표(도분초) 강제 이동 ·
변환 결과 표(완료·조회중·대기·실패) + 엑셀 내려받기. 결과는 **보고 있는 지도에** 임시 마커로 찍힌다.

**`/gpsmap` 라우트는 유지한다.**

- 북마크·공유 링크가 있을 수 있다.
- 변환만 크게 볼 때는 전체 화면이 유리하다.
- 라우트를 없애면 745줄이 홈 번들에 합류한다 (**현재** `/gpsmap` 351 kB로 분리, 홈 295 kB).

위치 세그먼트와 `/gpsmap`은 **같은 컴포넌트를 공유**해 로직을 한 벌만 유지한다.

> 변환 결과 표는 셀을 줄바꿈하지 않고 **표 상자만 가로 스크롤**한다 (`table-no-wrap`).

## 11. 레이아웃 상수

| 영역 | 값 | 근거 |
| --- | --- | --- |
| `NAV_RAIL_WIDTH_PX` | **200** | 아이콘 + 최장 라벨(「데이터백업/복원」)이 줄바꿈 없이 들어간다 |

목업 비율은 320px대지만 **패널에 들어갈 컴포넌트들이 이미 340px를 전제로 만들어져 있다.**
`filter-panel.tsx`의 드롭다운은 `min-w-[8rem]`(128px)이라 2개만 나란히 놓아도 여백 포함 320px를 넘고,
`backup-restore-section.tsx`는 `grid-cols-2`다. 320px로 줄이면 "배치만 바꾼다"는 전제가 깨진다.

**현재 `340`은 세 곳에 하드코딩돼 있다.**

| --- | --- | --- |
| `sidebar/map-sidebar.tsx:130` | `w-[340px]` | 파일 자체 삭제 |
