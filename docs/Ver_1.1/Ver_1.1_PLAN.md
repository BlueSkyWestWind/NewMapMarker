## 1. 배경

Ver_1.0은 장비·축전지·위치 3개 모드로 국소를 **지도에 표시하고 관리**하는 데까지 도달했다.
현장에서 다음 요구가 올라왔다.

> "축전지 수거 작업 당일, 그 국소에서 **몇 시에 일하면 되는지**를 알고 싶다."

2025년 6월 1일 시행 개정 산업안전보건법이 폭염·한파 건강장해 예방을 사업주 보건조치 의무에 포함하면서,
**체감온도 31℃ 이상 폭염작업**에 대한 조치가 법적 의무가 되었다. 옥상·철탑 함체 작업은 강풍·강수 규정(안전보건규칙 제383조)도 함께 걸린다.

Ver_1.1은 지도 위의 국소에 **기상 기반 작업 안전 판정**을 붙여, "어디에 있는가"에서 **"지금 작업해도 되는가"** 로 제품의 질문을 한 단계 옮긴다.

동시에 Ver_1.0 검수에서 미해결로 남아 있던 **홈 번들 회귀(R1)** 를 해소한다.

## 2. 목적 (Goals)

| G2 | 법정 기준(폭염 31/33/35/38℃, 풍속 10m/s, 강수 1mm/h) 반영 | 임계값 단일 상수 파일 |

## 10. 릴리스·운영 계획

### 10.1 배포 순서 (반드시 이 순서)

1. **Supabase SQL Editor에서 마이그레이션 실행**
   `20260727000000_add_worksite_weather_columns.sql`
2. 기상청 인증키 설정
   - 로컬 `.env.local`: `KMA_API_HUB_KEY=...`
   - 배포: `wrangler secret put KMA_API_HUB_KEY`
   - ⚠️ `wrangler.jsonc`의 `vars`에 넣지 말 것 (커밋된다)
3. `main` 배포 → Cloudflare 자동 반영
4. 배포 환경에서 KST 보정 실동작 확인 (Workers는 UTC로 동작)

### 10.2 롤백

| 대상 | 방법 |
| --- | --- |
| 앱 | Cloudflare 직전 Deployment로 복귀 |
| DB | 컬럼 추가만이라 롤백 불필요 (기존 기능 무영향) |
| 데이터 | 사전 엑셀 전체 백업 |

### 10.3 마이그레이션 미적용 시 동작

조회는 깨지지 않는다(`site_alias`·`work_type`을 optional로 읽음).
다만 **별칭 검색이 동작하지 않고 모든 국소가 `ground`로 취급**되어 옥상·철탑 강풍 가중이 걸리지 않는다.
